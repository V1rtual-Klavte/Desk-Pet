# V1rtual-Desk-Pet 产品设计

本文面向项目负责人，说明陪伴定位、玩法与交互。实现协议见 [current/](current/)，未完成工作见[未完成工作与已知缺口](plans/active/未完成工作与已知缺口.md)。重构前的详细说明保存在[历史基线](history/design/DES-2026-09-17基线.md)，默认无需通读。

## 1. 定位与体验原则

V1rtual-Desk-Pet 是可自定义 Card 与 Profile 的桌面陪伴应用。角色常驻桌面，用户可以聊天、切换外观，或让她在合适时机主动搭话；需要工具和任务编排的场景也由同一套运行时承担。

产品优先级：

1. **人格稳定**：Card 决定角色与表达，技术错误和工具状态也尽量保持一致语气。
2. **对话连续**：切换、关闭或重启后能够找回会话；长对话压缩后保留当前意图、纠正和未完成话题。
3. **低打扰**：主动搭话可关闭（档位「关」），频率分「低 / 中 / 高」三档，受随机唤醒区间、静默时间段与运行状态限制。
4. **轻量常驻**：MCP 只在运行期借用、结束即释放；技能正文只在显式调用或模型读取时进入对话；后台记忆整理受空闲与预算边界约束。
5. **能力可控**：用户能理解工具在做什么，需要确认时看到具体请求；角色语气不改变权限结果。

低内存和低延迟是设计目标，具体数值需要实测，不根据动态 import 或采用某个框架直接作保证。

## 2. Card、Profile 与用户记忆

| 对象 | 用户可定制内容 | 与其他对象的关系 |
|---|---|---|
| Card | 角色设定、语言风格、行为指引、角色变量 | 定义表达与互动状态，不拥有工具授权或用户长期事实 |
| Profile | 主题、立绘、字体与图层素材 | 定义视觉，不决定人格与权限 |
| 会话 | 当前话题、对话历史、工具记录、压缩摘要 | 支持多标签切换与历史恢复 |
| 用户画像与长期记忆 | 可追溯的事实、偏好、经历与短期事项；聊天里右键你自己的消息选「记住这条」，或直接说一句「记住……」（由模型判断是否写入），面板可查看来源原话、切换核心画像、纠正与忘记，并继续整理作业或预览备份恢复；后台整理在事务复核后自动提交；观察积累到可靠程度（至少 3 个有效观察日且覆盖率达 60%）后，她还能把稳定结论（作息时段、常用应用、专注习惯、使用节奏）沉淀成标注「系统观察」的**可撤销了解**——它在对话里必须注明是观察而非你的原话，不进核心画像，清空行为画像时一并消失 | 与 Card 的角色状态分开；整理候选在提交前不进召回，面板提供事后治理；系统观察与用户事实分区存放、分区召回 |

随包提供的 Card/Profile 是首次初始化种子。复制到运行时目录后，与用户导入资源一样可以编辑、重命名或删除；恢复默认资源会覆盖同名种子资源，需要用户明确操作。

### Card 玩法

同一桌宠可切换不同角色，随包种子提供默认卡 `default`（本体卡）、`yuki`、`angelkawaii` 与 `shu` 四张；默认卡出厂没有名字，名字由用户在对话里给她起，起名后进 Card 身份（随卡持久化，不进用户长期记忆），聊天气泡的说话人标签随之显示。实际列表以设置页和运行时资源为准。

设置页的「人格」节可直接管理 Card：新建（输入角色名，以随包模版为骨架）、编辑（角色设定、语言风格、输出规则、行为进阶、变量定义六段全文）、重命名（只改显示名）、导入、导出、删除，以及一个「模版」按钮——点开是完整的作者模版与一句可以直接照抄给 AI 的说明，复制即可拿去生成新卡。重命名不动文件名与角色状态，删除会连带清掉该卡的阶段文案与变量，正在生效的卡要先切走才能删。

Card 的自然语言行为指引结合当前互动状态影响回复，例如“长时间未回复时表达关心，但不要攻击用户”。这些文字交给模型理解，不作为可执行的条件脚本。

模型回复中的内部变量信息由回复模块解析，正文中不显示 `RUNTIME_DATA`。只有 Card 注册并允许更新的角色变量能被模型改写；角色台词、工具结果和摘要不会自动成为用户长期事实。

切换 Card 会准备阶段文案与变量状态，失败时回到原角色。缺少阶段文案时可能请求模型生成，因此不能把“不启动记忆整理”等同于所有初始化都不请求模型。精确状态边界见[人格与回复](current/personality.md)。

## 3. 聊天与会话

普通聊天可由模型分成最多四个气泡，提交后按节奏逐泡出现；生成时显示当前 Card 的正在输入文案。工具与计划回合保持即时流式展示，主动消息首泡与提示音同时出现。停止、插话或切会话时已提交内容立即全显，重开历史不会重新等待。关闭拟人表达保留已保存的气泡结构。

聊天支持选择或拖入最多四张图片。会话只记原文件路径，模型请求临时读取；不复制图片，原路径失效时显示不可用。

为控制内存占用，聊天历史默认只显示图片占位（文件名、大小、是否可用），不读取图片文件；点击占位可打开独立查看器。想要直接在聊天里看到图片，可在设置「外观 → 聊天图片自动预览」开启：开启后只为当前可见的消息按需加载预览，离开视口即释放。这个开关只影响历史图片的内联呈现，模型看图、选图发送与截图都不受它影响。

也可以让她看一眼你现在的画面：她截图后把画面展示在聊天里（与用户图片同一套展示）。前提是「静默访问」档位不是「关」（设置页里叫「静默了解频率」），关掉她就不能截图；只有展示给你看的截图才落盘、存于应用数据目录，你可以直接查看或删除，删除会话时一并清理。

聊天面板支持新建、切换、关闭标签和查看历史。角色与聊天之间的分割线可以拖动调整。

普通消息先保存再交给模型处理，运行中仍可继续发送。发送按钮旁可选择这条消息的投递方式：「插话」在当前响应及其工具批次结束后处理，「稍后继续」等当前任务自然结束前继续；不选则用设置里的默认发送方式。仍不能把“已排队”视为“已处理”：排队中的消息在输入框上方按类型列出（插话 / 稍后继续 / 已暂停），可逐条撤回，撤回结果会区分已撤回、已经开始处理与已不在队列。切换标签后，原会话的后台结果仍归原会话；失败会保留失败状态，不因展示了角色化兜底文案而算作成功。

插话在当前响应及工具批次结束后参与后续回答，不表示撤销已经发生的操作。运行中随时可以「停止」：停止是打断而不是失败，不会往会话里写失败文案；还没处理的输入转为已暂停，由你在排队面板选择「继续处理」或「全部丢弃」（发新消息时也会先处理它们）。这条消息到底有没有真正进入请求、请求有没有拿到回执，按输入逐条可核对，界面只在有证据时才那样说。进程中断留下的未完成运行在重开后会提示继续或丢弃。新增的停止按钮、暂停操作条与中断决策条尚未人工查看实机界面，见[未完成工作与已知缺口](plans/active/未完成工作与已知缺口.md#5-验证缺口)。

模型可能进行多次请求和工具调用。Provider 使用流式链路，最终回复统一经过变量与显示文本处理；产品不承诺“每条聊天固定一次 LLM”。工具执行过程的提示语来自当前 Card 的阶段文案（按工具类别匹配），界面不写死；同源的还有状态行的「思考中/规划中/重试中」、斜杠命令的输出与异常兜底台词，系统消息与错误诊断则保持中性，让用户分得清角色在说话还是系统出了问题。

### 长对话如何继续

上下文容量取自模型与用户设置。接近预算时由轻到重处理旧内容：先只改发送给模型的那一份视图（缩短过长的工具结果，必要时清掉大段工具结果的正文），仍然装不下才对较早的完整话题轮生成摘要；最近几轮的原文与工具配对受到保护，不会被清空或摘要取代。会话文件本身不会被删（回收只清理已作废的重复写入）。

`/compact` 可手动触发这一过程。只有摘要与边界成功提交才显示完成；摘要失败且无法构造可发送上下文时，会提示上下文不足。压缩用于当前会话连续性，跨会话长期记忆是独立的后续能力。

会话持久化、取消、恢复与工具记录的协议见[运行时契约](current/runtime-contract.md)及[当前记忆](current/memory.md)。

## 4. 主动陪伴

主动陪伴的档位（关 / 低 / 中 / 高）是唯一开关：设置页「AI → 主动陪伴」可选档位与静默时间段（默认 23:00–09:00，只约束主动消息）；聊天里 `/proactive on` 恢复默认「中」档、`/proactive off` 置「关」，状态可随时 `/proactive status` 查询（显示当前档位与今日送达）。AI 设置里的拟人表达决定聊天节奏，静默访问档位决定是否观察，两者独立于主动档位。静默访问优先截图，必要时回退窗口信息；读取哪些本地文件或目录由 AI 根据当前窗口判断，宿主逐项校验、只读不写，读取内容不落盘。观察整理为带来源的了解，与用户亲口确认的事实分开。

当前依据是窗口信息，不能写成已具备屏幕图像理解或能读懂所有网页内容。用户可配置三处档位与静默时间段；停留、防抖、冷却等节奏数值随档位派生，不再逐个开放。

主动搭话使用明确的主动来源与统一预算：真正开口那一步不携带工具；说话前她可以用几个只读小工具（截图、窗口信息、系统信息）先看看、查一下，再决定说不说话——辅助模型不支持图像时就不看截图。每日条数、开口间隔与 token 预算随档位：低档约 1–2 条/天、中档约 2–4 条/天、高档约 4–8 条/天（成功上限 2 / 6 / 10 条）；未回复达到两次后次日最多一条，但不完全停掉。自足、无需回应的分享不计未回复；忙碌或游戏时不追问进度。静默时间段默认 23–09 点（可改），静默开始前一小时只保留一次晚安机会。监控提示和角色自己的回复都不能冒充用户陈述写入长期记忆。

## 5. 桌面交互

| 操作 | 行为 |
|---|---|
| 拖动标题栏 | 移动窗口 |
| 聊天按钮 | 展开或收起聊天面板 |
| 会话标签与 `+` | 切换或新建会话 |
| 标签关闭按钮 | 关闭标签并保留归档，保持可用会话 |
| 关闭窗口（标题栏按钮 / Alt+F4 / ⌘W） | 隐藏到托盘，进程常驻 |
| 托盘或平台应用激活 | 恢复应用窗口 |
| 全局快捷键 | 召唤或收回桌宠，可在设置中修改 |
| 设置按钮 | 打开独立设置窗口 |
| 图层编辑入口 | 编辑当前 Profile 的展示效果并预览 |

召唤/收回使用光标附近的缩放动效，动画期间避免重复触发。透明、置顶和全屏桌面的表现依赖平台窗口能力，macOS 与 Windows 的具体实现分别维护。

快捷键、监控和窗口权限受系统设置影响。默认组合与可用选项以当前设置面板为准；实现参数不在产品文档中重复枚举。

### 聊天命令

输入 `/` 可以浏览和筛选命令；`/help` 是可用命令的入口。

| 命令 | 用户目的 |
|---|---|
| `/clear` | 归档当前对话并创建新会话 |
| `/compact` | 压缩当前会话的模型上下文，可能调用摘要模型 |
| `/skill <技能名> [额外指示]` | 显式调用一个技能，把技能正文加入本次对话；技能不存在、被关闭或正文为空时如实报出原因 |
| `/memory clean` | 清空当前长期记忆注册表条目；不是会话压缩或普通去重 |

旧文档列出的 `/smile`、`/sleep` 等表情命令已随表情系统移除，`/win open`、`/win close` 随 Windows 模拟器彩蛋一并移除，都不再存在。未识别的 `/` 开头文本会按普通消息处理。精确命令集合由[命令注册模块](../src/services/engine/slash/commands/index.ts)维护。

## 6. 外观、图层与声音

Profile 是可导入导出的资源集合，包含立绘和素材。随包默认 Profile 为糖糖粉与 yuki；用户可复制后编辑自己的版本。Profile 是自包含闭包：各类素材只从自身目录读取，导入即用，不借用其他 Profile 的资源。界面主题是产品级三套预设，不随 Profile。字体不随 Profile，在设置/外观里按全局配置选择系统已安装的字体。顶栏文案（缺省「就绪」——无 owner = 空闲的中性文案）是窗口运行时状态，不随 Profile、不持久化，暂未开放界面编辑。图层舞台与聊天区的兜底底色固定为白底，不随 Profile 变化。

### 角色展示效果

同一时刻选择关闭或灵动图层一种效果。每个 Profile 保存自己的素材和效果参数，全局设置只控制效果模式与全局强度。

- **灵动图层**：不同深度的背景、角色和前景随光标产生不同位移，形成层次感。编辑器可逐层选择素材、调整位移（取景）与缩放、设置逐层灵敏度，也可显隐或锁定单层，并调整全局强度。没有素材时，右栏底部的「没有素材？」面板给出一份分层出图提示词（可一键复制给有生图能力的 AI 逐层出图或改图）；素材文件仍由用户准备后经「上传本地图」导入。
- **关闭**：按静态立绘渲染，不启用分层位移。

编辑器与角色展示共用效果计算，保存到当前 Profile。切换 Profile 不应把上一份素材或参数带到下一份。字段、坐标和资源回退边界见[运行时数据](current/runtime-data.md)。

### 音效

音效用于启动、发送、回复、弹窗、窗口收回和未回复提示。音效库由 Web Audio 实时合成，不含音频文件；事件到音效的分配保存在 CONFIG，设置页可试听与更换。声音应辅助陪伴，不抢占用户注意力。

音效 ID、波形和具体参数由[音效模块](../src/services/audio/index.ts)维护；设置页提供可用选项，不在本文复制完整注册表。

## 7. 工具能力与安全呈现

聊天之外，应用提供文件读写、Bash、运行环境、窗口信息与截图等基础工具，以及 MCP、计划、子代理、剪贴板和应用打开等能力。截图需要「静默访问」档位非「关」，关闭时她不能截；她可以只自己看，也可以把画面展示在聊天里给你看。具体可用范围取决于设置、权限裁决与服务连接状态；MCP 按服务器开关在运行开始时借用、结束即释放。

复杂任务可通过 Plan 拆解步骤（可在设置里关闭「启用任务计划」，它是计划功能的唯一开关；是否触发默认只看关键词，不为此额外请求模型；设置里可改成「关键词 + 模型自判」，输入 `--plan` 也可强制触发）。步骤按顺序串行执行，不再有依赖/并行标注。计划确认时可以选择「全部执行」，也可以选择「逐步确认」：逐步确认在每一步开跑前停下来等你决定继续还是中止，中止后剩余步骤保持未执行；某一步失败时也停下来问，不会自动往下跑。步骤与工具状态保留检查点，恢复时不会自动重试结果未知的外部副作用。计划被取消、超时或按你的选择中止时会停在当前步骤、剩余步骤不执行，聊天区给出说明；这类计划与恢复产出的暂停计划都不会自动重放或自动续跑，须由你处置后才继续：面板上给出「继续」和「丢弃」两条出口，继续只跑剩下的步骤，不重新生成、也不再问一次确认。未知副作用步骤不会被自动重跑 —— 你要先选「标记为已完成」或「重跑此步」，否则这个计划只能丢弃。计划若因记录写入失败而无法留痕，会如实提示「计划执行记录写入失败」，不假装计划没跑过。当前验证范围和未完成体验项见[未完成工作与已知缺口](plans/active/未完成工作与已知缺口.md)，不把具备 Plan 接口等同于所有任务均可无人值守完成。

风险等级与权限结果分开：SAFE/NORMAL/DANGER/NOWAY 表达风险；allow/ask/deny 表达裁决。MCP 的 passthrough 表示继续交给统一策略，Skill 的说明不产生额外授权。

确认界面提供拒绝、仅本次允许和有限范围授权。运行结束、参数或策略改变等情况会使旧授权失效，不能把角色说“上次同意过”作为执行凭据。实现和网络边界见[工具系统](current/tool-system.md)。

## 8. 设置与数据

设置窗口按「通用 / AI / 记忆 / 工具 / 外观」分页，覆盖快捷键与更新检查、模型与会话策略、人格与陪伴（含拟人表达、记忆整理档位、主动消息档位与静默时间段、静默访问档位）、记忆库治理、工具与 MCP／Skill 管理面、字体与角色展示（含音效分配）。技术参数（上下文窗口、重试与工具上限、记忆预算等）不设界面控件，值只存在 CONFIG，改 YAML 生效。运行中的请求持有自己的快照；改变设置不代表在飞请求会立即改用新模型或 Card。

CONFIG 保存应用功能设置，Card/Profile 保存各自内容与素材，会话文件保存对话。设置修改直接写回 CONFIG 文件，不使用任何浏览器存储。开发/生产位置和恢复默认资源的覆盖范围见[运行时数据](current/runtime-data.md)。

导出配置或 MCP 配置可能包含用户填入的凭据，分享前应检查内容。设置面写入的 MCP 令牌只进应用自有存储（记忆库 mcp_credentials 表）、不进 CONFIG，因此不会被配置导出带出；它随记忆库备份/恢复一并走，分享备份时同样要检查。默认资源恢复会覆盖同名资源的修改，自建资源的保留规则以实际恢复入口为准。

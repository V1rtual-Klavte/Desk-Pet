## 路径模块

### Rust 端 (`paths.rs`)

```
AppPaths {
  data_root           ← debug: {project}/data/desk-pet/
  │                      release: {AppData}/desk-pet/
  ├── memory/ sessions/ personality/ profiles/   (运行时读写)
  │
  builtin_personality ← {resource}/personality/   (内置只读, Vite public/)
  builtin_profiles    ← {resource}/profiles/
}
```

- **init()** — `cfg!(debug_assertions)` 判断开发/生产，自动 `create_dir_all` 四个子目录
- **validate_path(path, base)** — canonicalize 后检查 starts_with，防路径穿越
- **validate_file_path(path)** — 只允许 home 或 temp 下（tool_exec 用）
- **resolve_resource_dir()** — 开发走 `{project}/public`，生产走 `resource_dir()`

### TS 端 (`paths.ts`)

```typescript
initPaths() → invoke Rust get_*_dir → 存内存
BaseDirs = { data, memory, sessions, personality, profiles }
// 业务模块自己拼文件名: `${BaseDirs.personality()}/stages/angelkawaii.json`
```

- 不在 `paths.ts` 硬编码业务文件名
- `BUILTIN_PROFILES_URL = "/profiles"` 前端直接 fetch

### 读写策略

| 操作 | 优先级 |
|------|--------|
| 读文件 | builtin 先查 → runtime 回退 |
| 写文件 | 仅 runtime，必须 `validate_path()` |
| 删除 | 仅 runtime |
| 列目录 | builtin + runtime 合并去重 |

**数据流（以 stages 为例）：**
```
读: loadStagesFromDisk → invoke("personality_file_read", "personality/stages/angelkawaii.json")
    → Rust: builtin_personality/stages/angelkawaii.json 先查
    → 不存在 → personality/stages/angelkawaii.json (runtime)
写: invoke("personality_file_write", path, content)
    → Rust: 仅 runtime，自动 mkdir parent + validate_path
```

# 活人感（拟人化）运行时契约

> **归档说明（2026-10-04）**：实现与自动验收完成，按用户指示归档。契约正文与当时的参数值原样保留作历史对照，**不再作为待实施目标**；剩余验收（真实桌面与设置往返、原生截图与 Windows 观察、真实模型节奏调优）不是契约内容，已转入[未完成工作与已知缺口](../../plans/active/未完成工作与已知缺口.md) §7 继续维护。当前行为以源码与 [人格与回复](../../current/personality.md)、[运行时数据](../../current/runtime-data.md)、[主动陪伴](../../current/proactive.md) 等 current 文档为准；以下正文提到的 active 路径、行号与授权状态均为当时记录，不作为当前指引。

> 用途：拟人化回复（分条气泡 / 打字节奏 / 正在输入 / 风格与策略 / 受限沉默）与三个开关（主动消息 / 拟人 / 静默访问）及同批能力（§8）的目标契约。
> 行为来源：两份理想 trace——[本体卡-小雪](../../../test/ideal-traces/本体卡-小雪.ideal.md) 与 [本体卡-小雪-休息日](../../../test/ideal-traces/本体卡-小雪-休息日.ideal.md)。它们是理想情况（期望来自用户、非实际运行结果）；本契约承接其中与拟人化相关的行为需求，不收录聊天记录。
> 状态（当时）：2026-10-04 代码实现与自动验收完成；真实桌面截图、设置往返及 Windows 原生观察尚待环境证据（剩余项见未完成总表 §7）。
> 参数来源：2026-10-03 开源调研（结论已内联于 §6.3 与 §11，不依赖外部文档；调研文档未入库）；源码事实基于工作树核查（[runtime.ts](../../../src/services/engine/harness/runtime.ts)、[harness-slot.ts](../../../src/services/engine/harness/harness-slot.ts)、[builder.ts](../../../src/services/context/builder.ts) 等，行号为当时值）。

## 1. 目标与范围

让桌宠回复具备微信式活人感（行为期望对齐两份理想 trace），并让 LLM 主动发起的消息共用同一套表达层。一批做全，不分轮次（用户决策：分批会增加测试与 token 负担）。同批一并收拢两份理想 trace 的其余能力需求：静默访问开关（§2.3）与同批能力口径（§8）。

**与 Card 的边界（不耦合）**：两份理想 trace 将编写为默认 Card `default`（其后另配 Profile）；活人感提示词与机制（指令块、标记、节奏、调度）都是引擎级、全局能力——不和 Card 耦合：不写进 Card、不随 Card 变化。Card 只携带自己的语言风格资产（人设 / 称呼 / 语气）。

| 做 | 说明 |
|---|---|
| 分条气泡 | 模型用整行标记分段；段落在提交前持久化，重载后逐泡还原一致 |
| 打字节奏 | 泡间延迟（字数 × 每字时长 + 抖动）；首条 lead-in「不秒回」 |
| 正在输入指示器 | 生成期间显示；文案走当前 Card（StageMap 新 key） |
| 回合分流 | 用工具的干活回合不拟人（不延迟、不拆节奏、流式照旧） |
| 主动消息同路径 | 主动投递走同一表达层；首泡即时（与提示音对齐） |
| 风格与策略指令块 | 请求静态层加 config 门控的口语化与回复策略指令（标点、条数、称呼、emoji、回话纪律、极短同档与沉默——需求出自两份理想 trace，见 §3） |
| 低概率不完美 | 提示词驱动（偶发错字、改口补一条更正）；引擎不做文本篡改 |
| 受限沉默 | `<<SILENT>>` 哨兵 + 引擎护栏；表示方式见 §7 实施必验项 |

| 不做 | 理由 |
|---|---|
| 表情包 / 语音条 | 需素材资源体系与图片消息渲染，是独立特性 |
| 撤回重发 | 与「气泡是投影、正文是真相源」的取消语义冲突；改口用「补一条更正」表达 |
| regex 强制拆分 | 会误伤代码/数字/链接；纯模型驱动，不拆只是效果少一点，不会出错 |
| `/humanize` 命令 | 配置写盘必须走设置页通道；另开命令写盘口会成第二入口（YAGNI） |
| 每 Card 拟人参数 | 节奏参数全局；Card 只负责语言风格资产 |

## 2. 控制面：三个开关

### 2.1 主动消息开关（不新建真值点）

- 真值点：Rust SQLite `proactive_control` 全局单行（[schema.rs:112-118](../../../src-tauri/src/proactive/schema.rs#L112-L118)，建表 `enabled=1`），字段 `enabled` / `mute_until` / `revision`。
- 现有入口：`/proactive on|off|status`（[commands/proactive.ts:15](../../../src/services/engine/slash/commands/proactive.ts#L15)）→ `setEnabled`（[index.ts:127](../../../src/services/proactive/index.ts#L127)）→ `ipc.control` 事务，scanner 即时生效。
- 本次改动：AITab 新增开关，**读写同一真值点**——读经既有 proactive IPC 端口（[store.rs:551](../../../src-tauri/src/proactive/store.rs#L551) 的 control 查询；若 TS 侧缺只读包装，在既有 ipc 模块补包装，不新开通道）；写复用 `setEnabled`（owner 取当前会话 + 激活 Card，与命令一致）。命令与 UI 双向一致。
- 语义保持现状：关 = 取消进行中尝试与表现、保留约定暂停；开 = 只检查仍有效窗口，不补发。
- 与「静默访问」开关（§2.3，由窗口监控升级）语义不同：总开关控制**所有** LLM 主动发起消息，静默访问只管观察来源。UI 文案实施时须区分，避免歧义。

### 2.2 拟人开关（新配置字段）

- 新增 `ai.humanizer.enabled`，**默认 true**。全链路同步清单：
  `CONFIG.yaml`（`ai.humanizer.enabled: true`）→ `CONFIG-DEV.yaml.example` → [config.ts](../../../src/services/config.ts) getter（`humanizerConfig`，`overrideOr("ai.humanizer.enabled", cfg.ai?.humanizer?.enabled ?? true)` 模式，参照 [CF:545-546](../../../src/services/config.ts#L545-L546)）→ [AITab.vue](../../../src/components/settings/AITab.vue) ref/checkbox/`defineExpose`（参照 [AT:669](../../../src/components/settings/AITab.vue#L669)）→ [SettingsPanel.vue](../../../src/components/settings/SettingsPanel.vue) `setOverrides({ "ai.humanizer.enabled": ... })`（参照 [SP:129](../../../src/components/settings/SettingsPanel.vue#L129)）→ 文档（`current/runtime-data.md` 配置清单）。
- 其余节奏参数（§6.3）为 `src/services/humanizer/` 模块常量，不进 CONFIG；实测调优后再定是否外露。
- **关 = 零行为**：不加指令块、不执行变换、不启动调度、流式与推送完全走现状（呈现即理想 trace 所说的「更规整的说话方式」，完整口径待立）；已落盘的多段条目仍按段渲染（历史一致）。

### 2.3 静默访问开关（由「窗口监控」升级）

- 原「窗口监控」按钮升级为「静默访问」开关（入口不变，语义升级）：开 = 窗口信息 ＋ 读文件 ＋ 截图三路观察；**截图优先**（能看见项目、结构这类更丰富的信息），不能截图才回退窗口信息与其他手段
- 读文件限于手边能读的（如项目 README、笔记）；观察沉淀进「了解层」（链路见 §8.1），带来源、不写用户事实
- 全程用户无感（无消息、无指示器）；关 = 这批观察不发生

### 2.4 正交关系

主动开关管「发不发」，拟人开关管「怎么发」，静默访问开关管「看多少」。三者可任意组合；拟人开时，主动消息与普通回复走同一表达层；拟人关时两者都维持现状。

## 3. 请求侧：风格与策略指令块

- **落点**：`buildPrompt`（[builder.ts:138](../../../src/services/context/builder.ts#L138)）static 层新增块 `static:humanizer`（priority 98，紧随 `static:v1rtual` 之后），随回合冻结（[R:1352-1353](../../../src/services/engine/harness/runtime.ts#L1352-L1353)），进 systemPrompt 静态前缀。
- **缓存论证**：恒定块（仅开关/措辞变化时变），不逐轮抖动，不破坏前缀缓存；与未完成总表 §4「plan/proactive 污染 system 前缀」问题不同源（那两条是逐轮变化块）。开关切换产生一次性缓存失效，可接受。
- **预算**：static 属核心块（[kernel.ts:45-47](../../../src/services/context/kernel.ts#L45-L47)），放不下按现有规则整回合报错、不截字；块目标 ≤300 tokens。若实测预算吃紧，备选：移入非核心可淘汰层（整块淘汰，[KB:81-90](../../../src/services/context/kernel.ts#L81-L90)），需内核小改，按证据决策。
- **内容要点**（引擎协议文本，非用户可见台词；措辞实施时按模型实测调优；行为需求出自两份理想 trace）：
  - **像真人发消息**：短句为主；用空格或短逗号断句；不用书面标点——冒号、破折号、引号、书名号不出现，句号基本不打。
  - **分条**：用整行 `<<SPLIT>>` 分隔多条气泡；一般 1–3 条，条数不固定——一条、两条、三条都可能，不搞每次齐刷刷的三连排比；总条数 ≤4；长内容 / 代码 / 列表 / 链接整段不拆。
  - **称呼**：不高频——不是每条都点名，按情境随机；只有认真、郑重的时刻才点一次（具体称呼口味属各 Card 的风格资产）。
  - **emoji**：随机低频、不固定位置；允许整条回复就是一个表情。
  - **回话纪律**：以「我」为主——亮自己的观点、喜好、小道理；不点评对方、不分析对方的状态；不复述用户；不解释自己的话；接得住没头没尾——同频翻回去。
  - **极短同档**：纯确认（一个表情、一个词、点头）用同档极短回复（嗯嗯 / 表情一类）；不是每条都要长篇回应，接不上话也走极短；好奇提问要「一个词就能答」，答不答都不追问。
  - **沉默**：只有输入确实无可回应（纯符号、误触、重复）时才整条输出 `<<SILENT>>`；纯确认表情不算噪音。
  - **技术 / 工具类问题**直接给结果，不卖萌、不拆条。

## 4. 输出侧：标记协议

- `<<SPLIT>>`：整行精确匹配（允许行首尾空白）才算分隔标记；>4 段合并进末段；无标记 = 单泡。
- `<<SILENT>>`：仅当整条可见回复只有该标记时有效。引擎护栏：拟人关时不识别；同一会话连续两次沉默被拒（第二次起按普通回复处理，仅剥离字面标记）；全程经既有 RuntimeTrace 留痕（脱敏，不含正文）。
- 两个标记仅在拟人开关开启时识别；关闭时原文直出，不做任何替换。
- 标记命名、整行匹配与合并策略的目的：与正常文本碰撞概率可忽略，且失败（模型不产标记）只损失效果、不损伤内容。

## 5. 提交与持久化

- **变换时机**：`after_response` 提交前钩子链（[harness-slot.ts:1747-1750](../../../src/services/engine/harness/harness-slot.ts#L1747-L1750)）。现有链：[createRuntimeDataStripHook:1019](../../../src/services/engine/harness/runtime.ts#L1019) → [stripRuntimeData:2702](../../../src/services/engine/harness/runtime.ts#L2702) 剥离 RUNTIME_DATA。拟人变换**追加在同一链上**，顺序：
  `剥离 RUNTIME_DATA` → `拟人变换（哨兵识别 / 标记转段）` → `留底配对 recordSettledReply(原始含标签正文 ↔ 最终落盘正文)`。
- **留底契约（关键）**：变量写入继续从原始正文解析（[R:2289](../../../src/services/engine/harness/runtime.ts#L2289) 结算路径 `rawTextForSettledReply` → `generateReply`），**拟人变换不得阻断**；`recordSettledReply` 记录的 stripped 侧必须是最终落盘文本，否则精确匹配失配会退化为无留底、变量写入丢失。实施必须覆盖「拟人开 + 回合含 RUNTIME_DATA」的变量写入回归（§10）。
- **结算取数**：结算返回的 `reply: processed.text`（[R:2294-2295](../../../src/services/engine/harness/runtime.ts#L2294-L2295)）是从**原始正文**解析出来的、仍含标记，不能直接作为推送文本；推送必须取变换后正文（与多段落盘同源）。
- **多段落盘**：变换把可见文本 part 转为多个 text part（每泡一段），落在**同一条**助手条目；`after_response` 返回值即提交内容，后续请求、压缩、摘要只见最终正文，标记与哨兵不进任何视图（与 RUNTIME_DATA 同原则）。
- **展示模型**：`Message`（[agent/types.ts:6-23](../../../src/services/agent/types.ts#L6-L23)）增加可选 `parts?: string[]`。装载路径 `messageFromEntry`（[read-model.ts:99](../../../src/services/session/read-model.ts#L99)）从条目多段生成；运行期推送与重载投影两条路都必须携带 parts，且以同一变换结果为来源；单段 / 旧数据缺省 undefined，走原渲染。
- **失败回退**：变换异常 → 整链回退为不拟人直出（宁可不拆，不可丢正文）；变换前的原始正文沿用 settledReply 留底机制，审计可回溯。

## 6. 展示调度（新模块 `src/services/humanizer/`）

### 6.1 职责与所有权

消费「已提交并已推送的助手条目」→ 维护逐泡揭示状态（瞬态，不持久化、不落盘），可注入时钟以便 Live 宿主测试；UI 只读状态渲染，不持逻辑。**不做**第二份消息 Store：chatHistory 仍是唯一展示列表。

### 6.2 回合分流

- 本轮 `toolCallHistory` 非空（或计划步运行）→ **task**：不延迟、不指示器、流式与即时推送维持现状。
- 否则 **casual**：指示器 + 逐泡揭示。
- 主动消息恒为 casual，但首泡即时（见 6.5）。分流判定以运行期事实为准，不依赖模型自述。

### 6.3 节奏参数（模块常量，标注「待实测调优」）

| 参数 | 起点值 |
|---|---|
| 每字时长 | 200–330ms 区间，默认 220ms |
| 抖动 | ×U(0.70, 1.30) |
| 泡间隔 | `clamp(字数 × 每字时长 × 抖动, 0.4s, 6s)` |
| 短泡封顶 | ≤4 字的气泡 ≤1.2s |
| 首泡 lead-in | 回复回合 U(0.3s, 1.5s)；生成已 ≥3s 时取 U(0.2s, 0.6s) |
| 指示器最短显示 | 400ms（防闪烁） |

### 6.4 正在输入指示器

- 新增 StageMap `stages` 组 key（建议 `typing`），文案经 `getStagePrompt` / `getSimpleStage`（[stages-cache.ts:113-131](../../../src/services/personality/stages-cache.ts#L113-L131)）取得；**不硬编码文案**。
- 通道复用 `deskpet-stage-hint`（[R:1212-1221](../../../src/services/engine/harness/runtime.ts#L1212-L1221) `emitStageHint`，含 titlebar 联动），显示位 `#ch-tool-status`（[ChatPanel.vue:724-726](../../../src/components/ChatPanel.vue#L724-L726)），工具状态优先。
- 须同步 `stages-prompt.md` 与 `validateStages`，**旧缓存判过期重生成**（否则新 key 永远取不到 Card 文案）；`FALLBACK_*` 保持中性兜底。
- 时序：生成开始 → 指示器显示；首泡揭示 → 指示器结束。

### 6.5 主动消息

走同一路径（[runner.ts:719-720](../../../src/services/agent/runner.ts#L719-L720) `pushCommittedProactiveMessage` → `playNotificationByBoundary`）。首泡即时揭示（提示音与首泡对齐），泡间延迟生效；不许延迟首泡，否则提示音与画面错位。主动消息的表达层同样遵循 §3 的风格与策略。

### 6.6 取消与代际

揭示状态绑定 session + run generation。新输入 / 停止 / 会话切换 → 未揭示部分**立即全显**（内容不丢）；非活跃会话不调度，重开会话直接全显。渲染条件形如 `index < (revealed ?? parts.length)`，保证无状态时全显。

### 6.7 流式门控

拟人开且本轮未出现工具调用时，抑制 `deskpet-assistant-stream` / `-stream-end` 增量（[R:1227-1250](../../../src/services/engine/harness/runtime.ts#L1227-L1250)），改由指示器 + 逐泡揭示表达；一旦本轮出现工具调用，立即回退现行流式直出。ChatPanel 的流式气泡（[C:691-694](../../../src/components/ChatPanel.vue#L691-L694)）不改结构。

## 7. 失败与回退

| 故障 | 行为 |
|---|---|
| 拟人变换异常 | 原文单选一段直出（等同关开关），留底与变量写入不受影响 |
| 调度 / 指示器异常 | 消息已推送，最坏情况一次性全显（等于现状） |
| 模型不产标记 | 单泡直出（效果降级，无错误） |
| 沉默表示 | 见下 |

**沉默的实施必验项**：`<<SILENT>>` 回合如何表示（空正文条目 / 不落条目 / 受控 stopReason）必须先验证 Pi 对空 / 极短助手条目的处理（后续请求视图、压缩、读模型、`isAssistantEntryVisible`），选择不影响上述任一路径的表示。若 Pi 无法安全表示，回退方案 = 用极短回复代替沉默（产品等价降级），并回报用户再定。验收要求：沉默回合在任何视图不出现空泡、不出现哨兵字面、不触发兜底台词覆盖模型的沉默决定（沉默是合法结果）。

## 8. 同批能力（来自两份理想 trace）

> 表达层之外、同批一应收拢的能力需求（理想期望口径）；各系统的实现与边界以各自契约为准。

### 8.1 静默了解（观察链与了解层）

- 触发：开关开启时她主动发起——判定「了解还很薄」就开一批静默了解
- 行动链：截图（看见项目、结构）→ 读手边能读的（README、笔记）→ 开一个子代理（辅助模型、`tools=[]`）静默整理观察
- 沉淀：进「了解层」，带来源（观察类，不写用户事实）；观察不自动变成用户偏好
- 边界：全程无感；开关关了这批不发生

### 8.2 主动链要点（扫描器 · 锚 · 选材 · 纪律）

- 扫描器不是 agent：确定性单一调度链（心跳 / 窗口事件 → 机会 → 指纹去重、打扰档位 → 规划 → 表达 → 回执）——「确定性外壳 ＋ 两处 LLM 缝」
- 两个 LLM 缝都无工具：规划子运行（辅助模型）与表达（聊天模型）均 `tools=[]`；记忆由宿主在外围解引用（喂精确目标）、落库也由宿主执行——无人值守副作用面为零；台词归聊天模型，子代理只做「台词之前」
- 锚 → 跟进：对话立锚（如「周六放纵日」）→ 机会预筛 → 规划子运行评估 → 落任务队列 → 到期成为候选
- 时机：画像驱动（如收工点）；没有画像就随机——每小时到几小时一条
- 选材：按画像话题占比加权（§8.3）＋ 一小份纯随机（防收敛）；内容自足、不绑回应；去重记账
- 纪律：降档不停（未回 ≥2 → 次日 ≤1 条，但不停）；「看到就行」类不计未回复；被无视不追问、不翻旧账；他在玩 / 忙的时段只放自足内容——不碰他正在做的事、不问进度
- 对账（以理想 trace 为准）：一天可以多条（现状「每日成功发话最多 1 条」待放宽）；晚安节奏与全局静默时段（现状 22–09）口径统一

### 8.3 画像 · 话题偏好（新增维度）

- 记录他爱聊哪些主题与大致占比（从对话参与度派生）；主动选材按占比加权、并留随机
- 边界：现有画像（`rhythm/apps/focus/activity`）不存标题与正文；话题维度同样只留主题标签与占比，不存对话正文

### 8.4 变量池与消费

- 三层：Card `好感度`（初始 0；只在有分量的时刻加分——幅度可大可小、按分量定；不按消息数涨、不因沉默掉）；interaction `unansweredCount`（她主动一次、到他下一次开口前无回应 +1；他一开口归零；「看到就行」类不计；≥2 → 次日降档但不停）；system `hour / dayOfWeek / isNightTime`（时间管静默与晚安节奏，dayOfWeek 管锚）
- 消费：提示词分档为主（值进请求视图 ＋ 行为进阶按档写规则）；代码级只做跨档迁移机会（她表示一下）；**不接采样 temperature**（它管随机性、不管亲密感，还会动摇输出协议）
- 刻度与分档：前篇 0–10、休息日稿已到 30——本批由用户授权代理决定采用 0–100；默认 Card 分档阈值 0/10/30/60/85，变量声明 proactiveBands，通用引擎不依赖具体变量名

### 8.5 记忆写入触发

- 用户亲口信息 → 写；她自己的话与主动消息 → 不写
- 观察类了解带来源，不冒充用户事实（与 §8.1 一致）

### 8.6 图片消息

- 对话支持用户发图——她看得见并自然回应；最多四张，每张15MiB。只存原路径，不另存副本或 base64；请求时临时读取，原路径失效明确显示不可用

### 8.7 本批已定口径（2026-10-03 用户授权代理决定）

- 正常主动成功额度6条／日，表达12次、规划8次，共享总token额度保持现有协议；发送后持久下一次1–3小时的槽，重启不连发。

## 11. 关键实现注意（易错点）

1. 留底配对必须记录**最终落盘文本**，否则 RUNTIME_DATA 变量写入静默丢失（§5）。
2. `after_response` 抛异常时 RUNTIME_DATA 不剥离（上游行为）：拟人变换必须挂在同一链内，不另建旁路，失败整体回退。
3. 运行期推送与重载投影两条 parts 来源必须同源同构，否则重载后气泡数与实时不一致。
4. 指示器复用 stage-hint 通道会进入现有阶段事件序列，Live 既有断言需核对。
5. 主动消息首泡即时，否则提示音先到、画面后到。
6. 节奏参数参考了 AGPL/GPL 许可的开源实现（chatluna-character、AstrBot 等）：**只借鉴参数与算法，不复制任何代码**。
7. **不把变换放进 reply 模块的 `generateReply`**：它运行在结算阶段（提交已发生），且重载投影（read-model 从 JSONL 重建）不经过它——标记会留在落盘正文并进入后续请求、压缩与重载展示。generator / 结算侧只做 §5 的两处配合：留底配对与展示取数。

## 目标

把记忆管线从“词面覆盖率 + top-50 + 单次阅读”升级为“可枚举的结构化词面检索”：

1. 入库不丢长消息尾部、失败不假装完成、合并不丢事件时间。
2. 索引带上下文、绝对事件日期、词表/IDF，检索能纠拼写、按意图扫描。
3. 召回不再让阅读器漏引直接变成主答漏证据；计数走批量枚举。
4. 评测能分开看“候选找全 / 最终包没丢 / 给定证据答对”，六题不再做决策。

非目标：本轮不引入向量检索、不默认打开 LLM rerank、不改 CONFIG 出厂默认、不推送远端。

## P5-B 方案（2026-10-18 调研，待批准）

### 评测口径切换：LoCoMo 改用异构 LLM judge（用户裁决 2026-10-18）

- **不再使用官方 F1，也不再保留 F1 回填链。** LoCoMo 的质量主口径改为异构 LLM judge 的语义正确率，以产品侧“答得对不对、全不全”为准。
- 理由：公开 harness（Mem0 / Zep / Cognee / A-MEM）没有一个直接调用 Snap `evaluation.py`；官方 F1 是词面重叠，惩罚正确但较长的回答，cat3 只取分号前、cat1 逗号拆句、cat5 是子串二值；独立审计还报告约 6.4% gold 错答。继续用 F1 会把格式和口径 artifact 当成产品语义质量。
- 现在怎么测：`--bench-judge` 默认 on；judge 模型默认 `deepseek-v4-pro`，必须不同于被测模型（`--bench-judge-model` 可覆盖）；prompt 只提供 question / gold answer / model response，按“语义正确且完整、允许同义改写与等价日期、缺项/错实体/无依据编造为错”判 yes/no；报告输出 `judge.enabled/model`、`scores.accuracy`、`byCategory[].accuracy`、`judgeFailures`，并保留 candidate/evidence recall 与成本。
- 删除 F1 相关：`datasets/locomo/run_official.py`、`requirements-official-locomo.txt`、`upstream-lock.json` 的 `locomo_evaluation`、`run-official.mjs`/`import-verdicts.mjs`/`export-hypotheses.mjs` 的 LoCoMo 分支、`scorer.mjs` 的 officialScores/官方分、`report.mjs` 的 LoCoMo pending_official 分支，以及对应测试、契约和文档。LongMemEval 的官方 judge 链保留不动。
- B1 不再以“官方 F1 格式”为目标；答案简洁/原词只在 judge 语义分下衡量，不单独做格式裁剪。

- [x] 已实现（2026-10-18）：`judge.mjs` 新增 LoCoMo 非对抗/对抗模板；`index.mjs` / `bench-adapter.ts` / `scorer.mjs` / `report.mjs` / `native-main.ts` 接入；LoCoMo F1 脚本、回填分支、requirements 与 lock 条目删除，LongMemEval 官方链保留。1 题烟测 `judge=deepseek-v4-pro`，语义正确率 1/1，F1 链未参与。

### B2C 根因补全（2026-10-18）

2 题烟测暴露的不是排序问题，而是候选池缺口：q0075 缺的甜点在命中话题的相邻回合（不含 dessert/favorite 词面），q0035 缺的 surfing 与 “outdoor activities” 无语料重叠。B2C 按两条通用通道补齐：

- **同线程邻接补全**：`expandConversationNeighbors` 把已选中会话命中按会话分组，取命中序号并集 ±2 回合，一次 `conversation_context` 扩读；单会话最多 10 轮、最多 3 个会话、2k token，JSONL 逐字校验、完整回合准入、revision/before/recordTime 边界、事件时间题跳过；只补一层，不递归、不作为新 seed。
- **方面候选词假设**：rewrite 提示允许模型提出最多 4 个方面候选词（活动/食物/书/地点/物品名）作为检索假设；只接受 `conversation_term_check` 确认语料存在的词，语料外词拒绝，候选词不得当事实。活动/食物/书类问题另补独立的类别种子词（hiking/surfing、cake/icecream 等），不要求种子与实体同句，无命中自然落空。
- **读者口径与列项渲染**：相邻原文直接、明确写出的同类项目可作为自身依据；列项问题必须跨会话与相邻回合汇总所有直接写出的不同项目，不能第一个命中就收尾，且只列所问人物/条件；仍禁止仅凭相邻关系补造未写出的项目。`enumeration` evidenceNeed 只用于直接历史 lookup；reader 未穷举时，宿主按问题词/类别种子词筛出 item-bearing 回合，按会话首次命中顺序把完整回合（最多 32 条）并入最终证据与 `answerSourceIds`。

### 小批次验收（不做灌库/trial 复用）

- 迭代：先 `--bench-case` 选 cat1 的 6 题（当前 manifest 中可用题），每次只灌 1–2 段对话；看 candidateRecall / finalEvidenceRecall，不先看官方 F1（已切换语义 judge）。
- 稳定后再跑固定 30 题 manifest 一次；记录 judge accuracy / candidate / final / cost。
- 目标：cat1 candidateRecall 64.3% → ≥75%，final ≥70%；cat2/4/5 证据召回不回归；语义 judge accuracy 不下降。
- 再做不同 seed 的 held-out 30 复验。

### 不做/暂缓

- 灌库快照与 trial 复用：管线变动频繁，暂不做。
- 全量 1986 题：约 48M tokens / 50h，不做日常跑批。
- cat3 大范围优化：gold 歧义/开放域为主，只处理明确检索漏（q0037）。
- rerank 默认保持 off。

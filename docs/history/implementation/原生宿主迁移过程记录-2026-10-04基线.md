### 9.2 W0/W1 已发现的问题（实现前必须处理）

1. **跨 crate 的两颗地雷（已在 W1a 处理）**：`paths/mod.rs` 的 `project_root()` 用 `env!("CARGO_MANIFEST_DIR")` 取**父目录**；文件搬进 `crates/native-host/` 后父目录变成 `crates/`，`data/desk-pet`、`CONFIG-DEV.yaml`、`test/.tmp` 会静默指错。同文件的 `include_str!("../../../CONFIG.yaml")` 也按本文件目录解析，同一串写法搬 crate 后指向 `crates/CONFIG.yaml`。两者都不编译报错。
2. **全局快捷键与呼出/收回状态机目前都在前端**：Rust 只注册了 `tauri-plugin-global-shortcut` 插件但**没有任何 register 调用**；`register`/`unregister` 在 `src/App.vue:463-478`，收回/呼出状态机（`isRetracted`）也在 `App.vue`。契约 §6.2 要求 Rust 直接处理，这两块是**必须重写**而非搬迁。
3. **设置窗与图层编辑器窗由前端 JS 创建**（`App.vue:182`/`:233`，依赖 capability `core:webview:allow-create-webview-window`），并靠 2s 轮询调 Rust 提层。原生宿主里必须改由 Rust 创建。
4. **窗口 label 被当成业务身份**：`tool_permit_{acquire,attach,release,cancel}` 用 `window.label` 作借用者、`memory_apply_change` 用 `window.label` 做 actor 门禁、`capture_screenshot` 用 `window.label` 做调用方白名单。原生宿主没有 WebView 窗口，这些必须换成显式 principal 参数，否则授权与回收语义丢失。
5. **工具额度的页面重载语义要重设计**：`tool/execution-permit.ts` 的 borrowerId 挂在 `globalThis`，靠 `tool_permit_attach` 在模块加载时回收旧"页面"的额度。单 Node 进程没有页面重载概念，孤儿回收路径需要新定义。
6. **二进制仍在走 JSON `number[]`**：`file_read_binary`、`profile_file_read`、`profile_file_write`、`personality_file_read/write` 五条命令以 `Vec<u8>`/`number[]` 往返；`profile/io.ts:54-56` 已注明 28MB/229 文件不可走 IPC。契约 §4.2 要求改二进制通道 + `HostBlobRef`。
7. **11 组跨窗口事件带 ack 与 5s 超时**（观察治理、记忆 revision、主动控制桥），且只在 `label ∈ {main, e2e}` 安装与路由。单 Node 进程后"窗口寻址/回执"需要重新定义；FS 侧的非 Tauri 分支目前是**直接降级跳过**（`revision.ts:46-48`）或**直接跳过**（`ownership.ts:36`）。
8. **asset 协议授权散落 3 处**（`lib.rs:333` 的 `allow_directory(profiles)`、`chat_images.rs:39`、`screenshot_cmd.rs:188` 的 `allow_file`）。Preview 依赖它，原生宿主需自带的静态资源通道或查看器。**不能保留为一个只服务于已删除 WebView 的空壳授权**。
9. **`initApp()` 只被 `App.vue` 的 `onMounted` 调用**（`init.ts:32` 注释），不在 `bootWindow` 链上。W3 写 Node bootstrap 时这条链路要整体接管，不能只搬 `boot.ts`。
10. **整数 `offsetX/offsetY` 的兼容分支待裁定**：`useParallax.ts:117-120` 把非零整数当作旧像素值、按窗口尺寸当场换算成百分比。契约要求"旧运行时格式不建兼容读取/双写"，但删掉它会**静默改变含整数 offset 的既有 Profile 的渲染**。已按"最终格式仅百分比"实现几何核（`crates/native-host/src/render/geometry.rs` 顶部登记），**需要用户裁定**：按百分比重读 vs 保留换算。

### 9.4 W0 冻结决定（协调者裁定，实现按此执行）

1. **`deskpet-cursor-move` 不进 Node 侧 `HostEventMap`**：它的生产者是 Rust 光标线程、消费者是原生渲染器，60fps 经 Node + IPC 转发没有意义。它保留在 Rust 的 `HostEvent::CursorMoved`，由 `EventSink` 直投原生 UI。
2. **`window-observed` 双投**：Node（behavior/observation 域）与原生 UI 都要消费。路由由 `EventSink` 实现负责，业务代码不关心，也不得为此建第二条广播路径。
3. **窗口 chrome 类命令不进 Node 侧 `HostCommandMap`**：`enhance_settings_window`、`enhance_layer_editor_window`、`set_picker_window_level`、`open_devtools`、`get_cursor_position`、`compute_popup_position`、`app_restart`、`list_system_fonts` 的消费者都是原生 UI；改由原生 UI 直接调宿主，**Node 不得驱动窗口显隐与层级**（契约 §6.2）。
   反之 `capture_screenshot`、`save_screenshot`、`get_runtime_activity`、`set_monitor_enabled` **保持 Node 可调**（工具链与观察域在用）。`HostCommandMap` 已按权威注册全量登记，本条是 W5 拆分时的依据，不是当前要改写的内容。
4. **不静默改线格式字段名**：`mcp_*` 的 `server_id` 与 cursor/popup 的 snake_case 字段按「今天消费者读什么」冻结。W5/W8 若要统一 camelCase，必须同步消费点，不能在桥内改名。
5. **20 处 `TODO(W0)` 是待办而非缺陷**：`src/services/host/types.ts` 里标 TODO 的都是「权威 TS 类型存在但是模块私有，W0 不许改那些文件」或「payload 今天只有内联字面量」。W3/W4a/W4b/W8 各自把它们改成 `import type` 或命名导出后清掉 TODO，**不得就此新造第二份结构定义**。

6. **`appearance.chatImagePreview` 不提前单独落地**：契约要求默认 `false`（历史只显示占位），而占位的可用性依赖「点击独立查看器」；当前 Vue 产品没有查看器，若现在只加开关与占位，等于把默认体验变成「聊天里看不到图」的降级。因此该字段与查看器一起在 W7/W8 落地，配置全链同步也在同一改动内完成。**在那之前不新增该字段、不做「无查看器的占位」**。

7. **UI 路线只读筛选结果（W0 第一步）**：三条路线对 10 个功能 gate 的取证结论 ——
   - **平台原生薄层：10/10 无结构性缺口**（macOS `NSWindow` 透明/置顶/整窗穿透/`alphaValue`/`collectionBehavior`、`NSTextInputClient`、TextKit2、CoreText 系统字体含 TTC、ImageIO GIF 全链路、`occlusionState`+`CADisplayLink` 停表；Windows `WS_EX_LAYERED`/`UpdateLayeredWindow`/DirectComposition 三条 alpha 路径、layered 窗按 alpha 逐像素命中是官方逐字行为、IMM32 按窗定位、DirectWrite 枚举与回退、WIC 动画 GIF）。
     **已知需自建**：macOS 逐像素穿透、引用块的排版构造、代码块独立横滚；**Windows 动画 WebP 需自带解码器**（WIC 内置只有 GIF）。
   - **egui/eframe 0.36.2：10/10 可通过但需 DIY** —— 它反而是候选中唯一内建动画 GIF+动画 WebP 逐帧播放的；代价是系统字体发现要引入第三方（官方 issue #5233 仍开放）、`strong()` 是变色不是真粗体、列表/引用无 widget、仅整窗穿透。
   - **Slint 1.18.1：不通过** —— 富文本表格/引用在官方"Currently Unsupported"清单、动画图官方称不在近期路线图（#2081）、点击穿透无 API（#5754 仍开），另有 Windows 多显示器 scale factor（#5701）与 Skia-DX12 透明（#8496）两个 open bug。**不进入原型，也不再作为备选维持**。
   - 冻结结论：原型只做 **① 平台原生薄层（基准）** 与 **② egui/eframe（最有希望的框架）**，两平台真实证据出来后冻结唯一生产路线。Slint 若要复活必须先看到上述三个 open 项收敛。
8. **原型证据等级要求**：文档/源码级结论**不等于**实机通过。中文 IME 候选窗跟随、透明窗实机观感、动画 WebP 是否真解多帧、隐藏即停的帧计数、跨屏 DPI —— 这五项必须由运行中的原型给出截图/计数，不接受"文档说支持"。原型源码放 `crates/native-host/examples/` 与探针 crate，**冻结路线后删除落选路线**，不长期保留两套半成品前端（契约 §2.1）。

9. **契约 `sourceFiles` 的刷新时机**：迁移期间 Rust 源码会持续搬家，`memory`/`proactive`/`observation`/`evaluation` 四份契约的 `sourceFiles` 已指向不存在的旧路径，`sourceHash` 必然 STALE。**不在每个迁移包后单独刷**（会反复返工），改为 **W1 全部包完成、Rust 侧不再搬动后一次性处理**：先按 SKILL `/analyze` 复核覆盖点是否仍成立（本次只有文件位置变化、无行为变化，但不拿这个当免审理由），再 `/generate` 刷新 `sourceFiles` 与 `sourceHash`，并同步跨层 caseId 记账。在这之前 **L4 与 `test:release` 都处于已知失效状态**，不得据此判通过或失败。
10. **W1 期间同步过、以后仍需检查的「第二定义点」**：`scripts/generate-memory-protocol.mjs` 的输出路径已随 W1b 改到 `crates/native-host/src/memory/protocol.rs`；`scripts/memory-performance.mjs` 的 `SOURCE_FILES` 与 `--manifest-path` 同样已改。后续每迁一个协议/生成物目录，都要查一遍生成脚本与性能脚本的路径常量，否则会静默在旧壳里重建第二份定义。
11. **`src-tauri` 侧已无消费者的依赖**：`rusqlite` 在 `src-tauri` 已无引用（`sha2` 仍被 `e2e_trace` 使用）。**保留到 W10 删壳时一并处理**，不在迁移中途单独清理 —— 中途删会掩盖「还有谁在用」的信号。

23. **W2 补充约定的裁定**：
    - **Node → 宿主的事件发布不进 `HostBridge` 形状**：`publishEvent` 保留在 `HostBridgeRuntime` 扩展面。理由：`HostBridge` 是**领域代码**用的接口，而发布事件是**运行时**的能力；把发布放进同一个接口等于允许任意领域代码广播任意事件。这不是"两套定义"——同一个桥对象、更宽的运行时视图。
    - **`HostBridgeUnavailableError` 定义在 `wire.ts`、由桶再导出**：接受（避免 `connection.ts` 形成模块环；公开形状不变）。
    - **blob 作用域校验失败即归还句柄、不可复活**：接受（被拒的句柄若还活着就是授权泄漏）。
    - **受控启动信息走环境变量 `DESKPET_HOST_LAUNCH`（一行 JSON）**：接受。不写 CONFIG、不写日志、不走 argv（argv 会进 `ps`）。
    - **`packaging/node-runtime.json` 锁 Node `22.22.3`**：接受为 provisional（满足 Pi 的 `>=22.19.0`）；**W10 首次打包前必须以实网分发包实证版本与 ABI**，不得把 provisional 当已验。
    - **二进制传输按方向串行（无 stream id）**：接受为 W2 粒度。若 W7 出现多路并发大流量需求，那是**协议扩展（要加 stream id）**，属契约变更而非实现细节。
    - **`AppError` 新增 `Remote` 变体、`code()` 返回 `Cow`**：接受（经 IPC 的远端错误码不再被折叠成 `OTHER`，这正是"错误码不降级"的要求）。
24. **HostBridge 取用口收敛（协调者裁定，已派实现）**：桶 `src/services/host/index.ts` **不得 import 任何 transport 实现**——它只持接口、类型与一个由 bootstrap 注入的实例；未注入时 `getHostBridge()` 抛 `HostBridgeUnavailableError`，**不做任何降级链**。四个窗口入口在 `bootWindow()` 里注入 Tauri 实现（在 `installGlobalHandlers` 之后、`initPaths()` 之前，因为 `initPaths` 自己就要过桥）；Node 侧在 `src/harness/main.ts` 注入 `connectHostBridge`。**理由是它是个真地雷**：桶一旦静态引入 `@tauri-apps`，Node 进程里任何 import 该桶的领域模块都会崩，逼迫每个领域文件绕过桶去直连实现。

25. **UI 生产路线冻结（W0 选型门结论）：平台原生薄层（AppKit + Win32）。**
    两个原型都以**真实窗口程序**跑完三条同构场景并留下实机证据（截图/日志在 `test/.tmp/ui-probe/` 与 `test/.tmp/ui-probe-egui/`，共 97 份）。判据顺序按契约 §2.1：先看功能 gate，再看同机资源。
    - **功能 gate**：原生薄层 10/10 无结构性缺口；egui 10/10 但列表、引用块、行内代码、代码块**全部 DIY**，真粗体要自注册 face，且**缺失 `FontFamily` 直接 `panic!`**（不是 fallback）——契约要求「缺失字体使用系统 fallback」，框架不兜底。
    - **决定性资源数字（release 实测）**：原生薄层隐藏态 RSS **≈50 MB**、**隐藏期帧回调 = 0**。egui 同场景 RSS **674 MiB**，其中**系统字体装载一项就 +472 MiB**（`PROBE_NO_SYSTEM_FONTS=1` 对照：202 MiB）——`epaint::FontData` 按 face **复制整个字体文件**（PingFang.ttc 78.2 MB × 2 face、Songti.ttc 66.9 MB…）。**这一项就是 9 倍于原生路线整进程占用**，且是结构性的：产品要求「系统字体枚举 + 按族名选择」，用户换任何字体会等比放大；要压下去得自建字体抽取/子集化管线，那是另一个项目。
    - 其余差异方向一致：隐藏停帧原生是字面 0（egui 稳态 0 但隐藏瞬间有 5 次节流余波，且 `ViewportInfo::visible()` 有延迟不能作为停帧依据）；富文本原生开箱（`NSTextTable`/`NSTextList`）而 egui 全 DIY；egui 的立即模式 + 共享状态**实测死锁冻结过一次 UI 线程且无报错**（对本产品的共享舞台状态是真实架构风险）；egui 无内建托盘、deferred 子视口的 `with_position` 实测未生效。
    - **egui 唯一胜项**：内建动画 GIF/WebP 逐帧播放（实测 3 帧 500ms/帧逐帧不同）。原生路线在 macOS 可用 ImageIO；**Windows 需自带解码器**，这条已登记为 W7 的实现项。
    - **落选路线处置**：`crates/ui-probe-egui/`（2364 行）为未跟踪的临时探针，按契约「冻结后删除落选路线」应删除；**保留到本次结论向用户交代后再删**（证据已固化在 `test/.tmp/` 与本节，删除不可逆，留一步回看）。`crates/ui-probe/`（4936 行，原生）**暂时保留供 W5/W6 参考与 W0/W2 打包最小试验复用**，产品 UI 落地后一并清理——两套探针都不进产品。

26. **取用口收敛引入的两处回归（协调者自己造成，已派修复）**：收敛裁定「桶不再持有默认实现」时，协调者的指令里写着「四个窗口入口在 `bootWindow()` 注入」——**这个前提是错的**：`bootWindow()` 只覆盖 main / settings / layer-editor **三个产品入口**，`test-e2e.html` → `test/e2e/e2e-main.ts` 有**自己的启动序列**。后果与处置：
    - **L4 宿主**会在 `initPaths()` 抛 `HostBridgeUnavailableError`（整层系统性变红）→ 在 `e2e-main.ts` 的领域初始化之前补注入，并在注释里写明「e2e 宿主不经过 bootWindow，注入点有意分开」。
    - **L2/L3（vitest）**此前依赖被删掉的懒默认（测试靠 alias 把 `@tauri-apps/api/*` 换成 `test/host/node-*` 的 Node 假实现）→ 新增测试侧桥安装设施并在 `vitest.config.ts` 的两个 project 配 `setupFiles`。**注意注释要诚实**：那里注入的实质是「Node 假宿主的桥」，不是真在连 Tauri。
    - 连带：`src/services/logger/index.ts` 的日志 flush 是 fire-and-forget + `.catch()`，接不住 `getHostBridge()` 的**同步抛**，会成为未捕获异常（旧行为不会）→ 一并加固并在注释里指名留痕点。

27. **W3a 引入的错误身份销毁（会打断 11 个 L3 文件，已派修复）**：`tauri-bridge.ts` 的错误归一函数对**不是 Rust `AppError` 载荷**的错误一律替换成新 Error，**丢掉了原始错误的 `name`**。后果链：11 个含 `await standardSetup()` 的 L3 文件 → `MemoryService.clear()` → `memoryStatus()` → `test/host/node-ipc.ts` 抛 `UnsupportedInNodeError`（Rust 专属命令的既定判据）→ 被归一成 `name === "Error"` → `standard-setup.ts` 的豁免分支失效 → 用例失败。

    - **测试侧三处同步完成**：`node-host-bridge.ts` 补 `platform`；**L4 场景顶层常量改执行期惰性求值**（`bashCommand()`）；引导测试补 `afterAll` 停两个调度器（**并判断"不污染断言"**：warn 断言按内容过滤特定子串，无关告警既不造成假绿也不造成假红；收紧成"恰好一条"反而会假红，故显式注释容忍）。
    - **🔴 它指出的最后一段（已派修）：Rust 侧没有事件路由** —— `host/dispatch.rs` **没有任何 `subscribe_events`/`ChatEvent::from_wire` 消费者**；死代码清扫也报过「`events` broadcast 通道**全仓无订阅者**（只有发送侧）」。**在这条接线落地前，断链 D 的修复在生产里看不到效果。**
    - **🔴 它顺手登记的「相邻断点」是最大的一个（已派修）：正文投影的生产者不存在** —— 线上 `apply_chat_projection` **只有会话侧**（A2 的 tabs/history），**没有带 `messages` 的正文帧** → **聊天窗没有任何可显示的消息**；reveal 事件按 messageId 存储却无处可裁。修法必须**并入 A2 的同一 builder**（A2 明确警告过：`messages` 整帧覆盖、面板缺省即清空，**两条生产者轮流发帧会互相清空**）。

另有两条**被明确否决的合并请求**（避免制造假耦合）：

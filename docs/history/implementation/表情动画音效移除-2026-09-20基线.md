# 表情 / 动画 / 音效移除（2026-09-20 基线）

**已完成并通过整轮 Live 门禁。** 当前能力以源码与 `docs/current/` 为准；本页保留当时的边界、影响面、实施中发现的回归与处理方式，不作为当前待办入口。仍待办的部分（资源审计与清理）见 [2026-09-20 收尾清单](../../plans/active/未完成工作与已知缺口.md)。验证数字只在[执行手册](../../plans/active/未完成工作与已知缺口.md#6-当前验证证据)记录一次，本页不复制。

## 目标

完全移除表情系统、角色帧动画系统，以及角色级与 Profile 级的音效映射；只保留系统级音效。人格阶段文案（`personality/stages/{cardId}.json`）与 `RUNTIME_DATA` 变量写入机制均为保留项。

## 前提事实（实施前按源码核实）

- 表情链从未接通：`EXPR_MAP` 恒为空对象（`buildExprMap()` 零调用者），`expressionCommands` 在模块求值时展开为空数组，`/smile`、`/sleep` 等按普通文本透传给模型。
- `deskpet-expression` 与 `deskpet-sound` 各只有 emit、零监听；`StreamView.vue` 无表情渲染层，也没有 `setExpression` 出口。
- `command-handler.ts` 与 `animation.ts` 全仓零引用。
- 角色帧动画素材（两张 Profile 各 109 个 PNG）没有任何显示消费者；立绘走 `materials/L2/body.png`。
- 音效全部为 Web Audio 实时合成，仓库无音频文件；系统级 8 个事件定义在 `audio/registry.ts`。
- `ProfileSound`（`profile.yaml` 的 `sound:`）读入后零消费者，真正生效的是 CONFIG `appearance.soundAssignments`。

**角色级与 Profile 级音效映射**：`ChatPanel.vue` 的 `playEventSound(personalityEffect.soundEvent)`；人格中间件的 `DEFAULT_EXPRESSIONS` / `DEFAULT_SOUNDS` / `wrap()` 输出；`runner.ts` 的 `PersonalityEffect` 传递；`harness-tool-adapter.ts` 的 `wrap("done")`；四张 `profile.yaml` 的 `sound:` 段与 `ProfileSound` 类型；`AITab.vue` 的情绪映射只读列表。

## 实施中发现并修复的回归

首轮整轮门禁 **3/3 trial 全挂**在 `variable-affection-praise`（variable-pool / vp-04）的 `expectAnyWriteHappened`。

**根因**：被删的 `formatEmotionForPrompt()` 名字是"情绪"，实际内容是**整个 `<RUNTIME_DATA>` 的格式规范**——模型写 Card 变量的唯一说明书。它在 `context/builder.ts` 的注入条件是 `sections.emotionMappings.length > 0`，即"有情绪映射"意外兼任了"允许模型写变量"的开关。删掉情绪链后模型拿不到格式说明，变量再也写不进去。

**改法**：

1. 说明书从情绪模块搬出，只保留变量部分，落在 `context/builder.ts` 的 `RUNTIME_DATA_INSTRUCTION`；注释标明解析侧是 `reply/generator.ts` 的 `RUNTIME_RE`，两处必须对齐。
2. 触发条件换成语义正确的开关：Card 声明了 `scope === "card"` 且 `updateBy === "llm"` 的变量才注入，顺带省掉无变量 Card 的静态前缀开销。
3. 措辞保留强约束"每轮都必须附带该区块；没有变化则留空区块"——中间一轮门禁正是在这里回退：去掉 emotion 强制行后措辞变成"只在有变化时写入"，读起来像可以整块省略，模型偶尔真的省略。改回强制后三轮全过。

教训：命名与实际职责不符时，按名字做影响面分析会漏掉整条下游链路，且类型检查抓不到——注入点本身语法合法。

## 随附：无效素材清理（同日）

表情与帧动画移除后，两处 Profile 目录仍存有大量未被任何代码引用的素材。按以下规则审计后删除：

| 类别 | 规则 | 依据 |
|---|---|---|
| `materials/**` | 一律保留 | 图层编辑器的素材选择器列出整个 `materials/` 目录（含子目录），每个文件都是用户可选资源 |
| `ui/**` | 只保留代码点名的 | `getUiUrl()` / `u()` 共点名 35 个路径 |
| `fonts/` | 只保留 YAML 点名的家族 | 注入器只按 `theme.fonts.ui` / `theme.fonts.chat` 注入，未点名的不加载 |
| `profile.yaml` / `character.yaml` | 保留 | 配置本体 |

删除合计 **538 个文件 / 约 40.9 MB**：随包种子 160 个（−19.1 MB）、运行时数据根 378 个（−21.8 MB）。分布为未引用的 `ui/photo`（28）、`ui/jine`（14）、`ui/Fromtemd`（15）、`ui/windows`（19）、未点名字体 `PixelMplus10-*`（2）、Profile 根目录 `body.png`（1），运行时另含 `frames/`（109）。

安全性依据：`yuki` 与 `glass` 使用 `theme.useDefaultUi` 且不自带 `ui/`，回退到 `DEFAULT_PROFILE = "sugar-pink"` 的 `ui/`；被引用的 35 个文件在 sugar-pink 中保留，删除后四个 Profile 在种子与运行时两处复核均为 8/8 引用齐备。运行时数据根被 `.gitignore` 排除，其删除不可由 git 恢复；种子部分可由 git 还原。

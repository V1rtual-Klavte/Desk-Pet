核对时新发现的问题（计划里没有）：

1. **`BufReader` 丢数据**：`mcp_send` 每次调用都新建 `BufReader` 包住 `ChildStdout`，一次 `read_line` 会预读多行，析构时缓冲里没用上的字节直接丢失 —— 后续请求会永远等一条已被丢弃的响应。常驻读线程顺带修掉了它。
2. **写失败会把进程丢在池外**：原实现在 `?` 上直接返回，进程既不在池里也没被 kill，下次调用一律「未连接」且 `mcp_kill` 找不到它。现在无论成败都放回池中。

⚠️ **已知残留（不在本轮范围）**：请求进行中进程仍会临时移出池（`mcp_kill` 与 `kill_all` 在这段时间里找不到它）。窗口已由 60s 上限封顶，且 Agent Loop 是顺序工具调用、同一 server 不会并发请求，实际影响很小；彻底解决需要把进程常驻池内并用并发安全的响应分发，属于独立改动。

## 3. 剩余待办

### 3.1 安全

> ✅ **S1–S6 已全部实施**，见 §2.4。下表保留当时的证据与方案，行号是审查时的位置。

| # | 问题 | 证据 | 方案要点 |
|---|---|---|---|
| S1 | `bash_exec` 阻塞 + 内存放大 | 非 async 命令体在 async worker 上同步跑 `try_wait + sleep(25ms)` 轮询，且 `timeout_ms` 可为 `null`（无终止条件）；先把全量 stdout/stderr 落盘再 `read_to_string` 整读入内存，截断发生在之后 | 改 `#[command(async)]` + `spawn_blocking`；设 Rust 侧默认超时；用 `SeekFrom::End` 只读尾部窗口 + 流式统计行数；删掉 `BashResult` 的 `stdout`/`stderr` 字段（TS 侧根本不用） |
| S2 | 工具输出无 spill | `tool/router.ts` 只做 50000 字符内联截断，`contentParts`/`details` 不截；Pi 的 bash 会把 `capture.spillPath` 拼进给模型的文本而 `tool/pi/tauri-execution-env.ts` 从不返回它 | Rust 截断时保留 temp 全量文件并返回 `spill_path`；`exec` 把 `spillPath` 放进截断对象；`router` 对 `contentParts` 的 text part 统一施加预算（image part 不动） |

## 5. 已知的坑

1. **`engine/pi/runtime.ts` 被 6 份 Contract 收录**（agent-runtime / memory / planner / safety / tool-execution / variable-pool）→ 任何改动都会让 6 份 hash STALE。多个改动要**集中一次改完再一次刷新**，否则反复重跑 analyze。
2. **Contract hash 过期会阻断所有 `pnpm test`**（包括带 `--module` 的）。改完源码先刷 hash，算法：`sourceFiles` 按路径排序 → 逐个 `readFileSync(utf8)` 拼接 → SHA-256。
3. ~~**`[Fact-Forcing Gate]` 钩子会拦 `git commit`**~~ —— **2026-09-15 复核更正：不拦 `git commit`**。
   该钩子（GateGuard 的 `pre:bash:gateguard-fact-force`）**只拦每条会话的第一条 Bash 调用**，与命令内容无关。
   通过方式是按它要求先说出两件事再原样重试：① 当前用户请求的一句话概括；② 这条命令验证或产出什么。
   本轮 7 个提交全部在会话内直接成功，没有任何一次被拦。不要再用 `ECC_GATEGUARD=off`、不要把命令改写绕开、
   也不要为此重开会话 —— 那些都解决不了「第一条 Bash」这个真正的触发条件。
4. **Windows 分支只能靠 CI 做编译级验证**：本机交叉 `cargo check --target x86_64-pc-windows-msvc` 会卡在 `tauri-build` 的 `embed-resource`（需要 `llvm-rc`），且在此之前不编译 deskpet 自身。CI 是唯一可靠验证途径。
5. **pi-ai 的 `streamSimple` 失败不 reject**，而是以 `stopReason: error | aborted` + `errorMessage` 正常结束流 —— 调用方必须显式检查。
6. **`guardProviderFetch` 会整体缓冲 SSE**（为满足 4MiB 响应体上限而读完才交给 pi-ai）。当前 UI 不渲染增量文本，无功能回归；**将来接流式显示时需改成 pull-based 包装**。
7. **`cli` 的 `timeoutMs` 只覆盖到响应头**（SDK 收到响应头即 `clearTimeout`），总时限必须自己用 `AbortController`。
8. **Live Test 超时后的「在飞回合」可能渗进下一个场景**，见 L10。
9. **改 Rust 命令签名要同步三处**：`commands/mod.rs` 的 `pub use`、`lib.rs` 的 `invoke_handler!`、前端 `invoke` 调用点。漏任一处 `test:types` 抓不到。
10. **`session_file_write_atomic` 只校验 home/temp 边界**，不校验目标在 `data_root/sessions` 内。
11. **删契约 `sourceFiles` 里已不存在的文件**：`scripts/live-test.mjs` 会 `readFileSync` 每个路径，缺失会在启动前报错退出。

# 阶段现状：2026-08-06

> 本文是今天对 Desk-Pet 当前代码、配置、测试和文档的阶段性审查记录。
> 它保留今天的判断和证据，不替代源码；阅读当前行为时优先看 `docs/current/` 和对应实现。

## 1. 结论摘要

Desk-Pet 当前已经从早期的“人格 + When DSL + 变量工具”实现迁移到一条更清晰的主链路：

```text
用户输入
  -> Agent Loop
  -> Card / whenText / 变量状态 / 当前会话摘要组装 Prompt
  -> Provider + 工具循环 + Safety
  -> <RUNTIME_DATA> 解析
  -> 情绪映射 + batchWriteVars + stages 持久化
  -> 会话写入 + Vue 展示
```

当前最重要的判断：

1. **核心聊天链路已经以 RUNTIME_DATA 为准**。变量写入属于 `reply/generator.ts` 和 `variable-pool.ts` 的职责，不再属于工具注册表。
2. **记忆系统已经具备会话文件、压缩摘要、长期记忆 CRUD 和整理能力，但长期记忆召回与自动提取尚未闭环**。
3. **助手模式、Plan、Safety、MCP、Skill 和 SubAgent 已有实现，但跨模块运行时覆盖不足**。
4. **Live Test 目前有 7 个 Contract、6 个 Scene；Contract 的 `sourceHash` 全部为空，源码变更过期保护实际被跳过**。
5. **当前代码在最新 GitHub tag 之后继续演进**。仓库可见的最新 tag 是 `v0.12.0`（2026-07-05），7 月 24 日的 RUNTIME_DATA 迁移和本次文档整理都不应伪装成该 tag 的内容。当前实现应称为“未发布工作区状态”。

## 2. 启动与模块总览

`src/services/init.ts` 是应用启动初始化入口，顺序为：

1. 初始化 `memory/` 和 `sessions/`。
2. 加载 Profile。
3. 扫描并注册人格 Card。
4. 注册轻量工具；按配置加载助手工具、MCP 和 Skill。
5. 扫描会话文件并恢复活跃会话。
6. 只有在当前会话没有消息时写入欢迎语。
7. 初始化 Debug 状态，并启动每小时记忆整理定时器。

前端主要入口是 `src/App.vue` 和 `src/main.ts`。业务入口按下面的边界拆分：

| 区域 | 主要实现 | 当前职责 |
|---|---|---|
| UI | `src/components/` | 角色显示、聊天、设置、确认弹窗、Profile 编辑 |
| Agent | `src/services/engine/`、`agent/runner.ts` | 预处理、主循环、Plan、会话状态、Provider |
| 人格 | `src/services/personality/` | Card 加载、人格切换、语气、情绪、变量状态、阶段文案 |
| 回复 | `src/services/reply/generator.ts` | 解析 RUNTIME_DATA、情绪映射、变量批写和回复截断 |
| 工具 | `src/services/tool/` | Local、助手工具、MCP、Skill 的注册和路由 |
| 安全 | `src/services/safety/` | SAFE/NORMAL/DANGER/NOWAY、策略和确认桥接 |
| 记忆 | `src/services/agent/memory/` | 系统文件、长期条目、会话文件、摘要和整理 |
| 平台 | `src-tauri/src/` | AppPaths、窗口、监控、文件和 MCP 子进程桥接 |

## 3. 当前 Agent Loop

`src/services/engine/agent-loop.ts` 的单轮流程如下：

```text
record user turn
  -> refreshVariablePool / interaction 更新 / reset policy
  -> getActiveCard（neutral 兜底）
  -> buildPrompt
       Card 角色、语言、输出规则
       emotionMappings
       whenText（自然语言语气指引）
       mustRules
       四类变量状态
       CANDY.md、User.md、当前会话压缩摘要
       当前模式工具声明
  -> 助手模式按复杂度可选 Plan
  -> Provider 非流式请求
  -> 工具调用循环
       Safety check -> confirm -> executeTool -> 结果回注
  -> generateReply
       移除 RUNTIME_DATA
       resolveEmotion
       batchWriteVars
       savePoolToDisk
       trim / 长度截断
  -> record assistant turn
  -> compactOnHighUsage
```

当前实现的几个边界：

- Provider 固定 `stream: false`，没有流式回复路径。
- 轻量模式只加载基础 Local 工具；助手模式动态加载写文件、完整 Bash、应用、剪贴板、删除、SubAgent 等工具。
- Plan 只有在助手模式且配置启用时参与；复杂度可由 `--plan`、关键词或一次低成本 LLM 判断触发。
- `whenText` 只作为 Prompt 文本，不在前端执行条件表达式。
- `RUNTIME_DATA` 只允许写入 Card 注册且 `updateBy=llm` 的变量；未注册、类型错误、越界或只读变量会被拒绝。

## 4. 人格与变量状态

人格 Card 位于 `src/services/personality/cards/`，加载器通过 Vite glob 扫描内置 Card，通过 frontmatter 和 Markdown section 形成 `PersonalityCard`。

四类状态的职责如下：

| scope | 来源 | 可写性 | 持久化 |
|---|---|---|---|
| `system` | 当前时间、星期、活动 Card 等运行时计算 | 系统维护 | `vars.json` 快照 |
| `card` | Card 的 `variableDefs` | 仅允许声明为 `updateBy=llm` 的变量被 RUNTIME_DATA 更新 | `stages/{cardId}.json` |
| `interaction` | 未回复数等互动状态 | 系统维护，模型只读 | Card stages 状态 |
| `session` | 当前会话信息 | 系统注入，模型只读 | 不写入 Card 状态 |

本阶段已经清理当前实现中的 `var_read`、`var_write`、`var_list`、`var_delete` 旧工具提示和阶段映射。历史文档保留这些词，是为了保留当时的实现细节，不表示当前接口仍有效。

## 5. 记忆系统现状

### 5.1 数据边界

运行时数据根目录由 Rust `AppPaths` 和前端 `BaseDirs` 共同管理：

```text
data_root/
├── memory/
│   ├── MEMORY.md       长期记忆注册表
│   ├── CANDY.md        用户手写系统指令
│   ├── User.md         高重要性用户事实视图
│   ├── Outside.md      外部知识引用
│   └── Project.md      会话归档索引
├── sessions/           会话文件与压缩摘要
├── personality/        Card 运行时状态和用户 Card
└── profiles/           用户 Profile 与素材
```

`sessions/*.md` 是会话持久化真相源，localStorage 只作为快速恢复缓存。会话文件会实时追加用户和助手轮次，并记录主题、轮数、Token 和上下文占比。

### 5.2 已接通能力

- `MemoryService.init()` 初始化目录、读取系统文件、从 sessions 重建 `Project.md`。
- `recordTurn()` 每轮截短文本到内存会话，并异步追加到 sessions 文件。
- 每累计 5 次全局 turn counter 会触发一次整理；启动时另有每小时定时器。
- 助手模式下条目足够多时可用 LLM 做合并、过期、重要性调整和新事实补充；失败回退本地去重。
- 上下文接近 `contextCompactAt` 时，压缩器保留最近消息并异步生成结构化摘要写回会话文件。
- `/clear` 会归档当前会话、清空聊天，并计入会话结束整理计数。

### 5.3 当前缺口

- `MemoryService.search()` 有 CRUD 层实现，但 `context/builder.ts` 没有调用它；长期记忆不会自动进入 Prompt。
- `forkMemorySupplement()` 有 LLM 提取实现，但没有被正常 Agent Loop 结束链路调用；它不能被描述为“每轮自动提取”。
- 会话结束计数目前由 `/clear` 路径触发，普通新建会话流程需要继续核对是否应统一调用。
- 压缩摘要和历史会话恢复有实现，但缺少稳定的跨重启自动化验证。

## 6. 工具、安全与平台

### 工具

`ToolRegistry` 统一保存 Local、MCP 和 Skill 工具。工具声明由当前模式筛选，`ToolRouter` 负责超时和结果截断。当前工具分类包括文件读取、Bash、系统信息、HTTP、文件写入、完整 Bash、应用、剪贴板、删除、SubAgent、MCP 和 Skill。

### 安全

`SafetyChecker` 使用四级风险和三种策略：

- SAFE：自动放行。
- NORMAL：轻量模式放行，助手模式首次确认后可会话信任。
- DANGER：轻量模式拒绝；助手模式按 `just_do_it` 或确认策略处理。
- NOWAY：始终硬拒绝。

确认 UI 通过 `requestConfirm()` Promise 与 ChatPanel 桥接。Bash、文件路径和危险操作还有各自的模式库与 handler 层校验。

### Windows/macOS

- Windows 通过 Win32 获取前台窗口标题，macOS 通过 AppleScript 获取标题并回退到应用名。
- 路径、窗口层级、快捷键和托盘逻辑需要继续按双平台验证。
- macOS 系统通知仍未接通，原因是未签名构建和 Tauri 沙箱限制。
- `AppPaths::validate_path()` 使用 canonicalize 校验已存在路径；写入新文件时调用方需要先校验父目录，这是当前安全边界的重要前提。

## 7. 测试现状

Live Test 位于 `src/services/__tests__/live/`：

- 7 个 Contract：emotion、memory、personality-card、planner、safety、tool-execution、variable-pool。
- 6 个 Scene：emotion、memory、safety、tool-execution、variable-pool 两个。
- `contract-checker.ts` 会检查缺少场景、深度、边界和错误路径。
- 所有当前 Contract 的 `sourceHash` 为空，检查器的 STALE 保护被显式跳过。
- Live Test 依赖真实 Provider、开发配置和外部环境；`vue-tsc`、`cargo check` 只能证明编译，不是端到端通过。

当前测试不是全仓覆盖：Plan、MCP、Skill、窗口监控、Profile、路径安全和跨平台行为仍需要补充场景。

### 本次验证记录

- `npx vue-tsc --noEmit`：通过。
- `cd src-tauri && cargo check`：通过。
- `pnpm test` 与显式 Vitest verbose 运行：测试框架能加载 Contract 并输出覆盖缺口；执行在 `initRegistry()` 为 Card 生成 stages 时等待真实 Provider，未得到场景汇总后超时结束。因此本次不能宣称 Live Test 通过。

## 8. 版本与发布纪律

今天的版本清理遵循以下规则：

1. 保留 Tauri、依赖版本、API 路径 `/v1` 和外部模型名中的真实版本信息。
2. 删除代码注释、日志和当前测试说明中的内部 `v2/v3/v4/v5`、Phase 字样。
3. 历史目录中的文档正文不改；其中的版本号是历史事实，只通过归档元数据与当前文档隔离。
4. 当前代码不写“当前版本 vX”。正式发布以 GitHub tag 为准。
5. 当前最新公开 tag 为 `v0.12.0`，但其后的迁移提交尚未形成新的发布 tag；当前状态应标记为未发布工作区状态。

当前 manifests 仍存在 `package.json`、Cargo 和 Tauri 配置之间的版本字段差异。这些字段属于发布元数据，不能在没有确定下一个 GitHub tag 的情况下随意改成 `v0.12.0`；下一次发布前应统一它们并由 tag 作为唯一发布依据。

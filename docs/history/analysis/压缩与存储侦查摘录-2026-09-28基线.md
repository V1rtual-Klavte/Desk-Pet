## 2. `deskpet-toolresult-binding.md` — 工具结果 id 体系与回读链路

**结论**：Desk-Pet 的工具结果有**稳定且唯一**的 id（`entryId == deskpetEntryId == invocationId`），存档条目全文永久保留、压缩只换视图不删条目，且已有模型侧回读入口（`read_session_event` 分页，`preserve` 防循环）；但「压缩后还能回读」有 **8 类失效条件**，其中两条对改造最关键：**id 只在结果被缩短时才出现在请求里**，以及**压缩后 id 会掉出视图**。另外 `historyCompaction: "retain"` 机制齐备却**无生产消费者**（空转的能力面）。（原始 §A3 对应关系一句话、§C10 条件表、§B7）

## 3. `cc-compact-core.md` — Claude Code 整轮 compact 全流程

**结论**：Claude Code 的整轮 compact 是「**全量摘要、保留 0 条原始消息**」——经典路径没有切点、没有 `messagesToKeep`；保留尾部只存在于 session memory compact 与 partial compact 两条旁路。边界消息是 **marker 而非 replacement**，磁盘 JSONL append-only 但 `--resume` 会剪掉最后边界前的消息；**没有专门的「撤销压缩」机制**。可借鉴面主要在摘要 prompt 结构、后处理、失败分层与压缩后清扫。（原始 §Q2、§Q4.2、§Q5、§Q8）

**证据要点**：

- **阈值公式**：`src/services/compact/autoCompact.ts:30`（`MAX_OUTPUT_TOKENS_FOR_SUMMARY = 20_000`）、`:33-49`（`getEffectiveContextWindowSize`）、`:62`（`AUTOCOMPACT_BUFFER_TOKENS = 13_000`）⇒ 阈值 = 窗口 − min(maxOutput, 20000) − 13000；200k 模型 + cap 关 ⇒ **167k（≈83.5%）**，报告自标为**按公式推算、非运行时实测**。（§Q1.1）
- **token 口径**：检查阈值用 `tokenCountWithEstimation`（`src/utils/tokens.ts:226`）= 最近一条真实 usage + 其后粗估补差；`messageTokenCountFromLastAPIResponse` 被注释标注**不得用于阈值比较**。（§Q1.2）
- **触发位置**：`src/query.ts:454`（`deps.autocompact(...)`，实现在 `autoCompact.ts:241`）——**每次 API 调用前评估一次**，不是每轮对话一次；判定 `autoCompact.ts:160-239 shouldAutoCompact`；递归护栏 `querySource === 'session_memory' | 'compact'` 直接 false（`:171-173`）；关闭开关优先级 `:147-158`。（§Q1.1、§Q1.3）

- **「不能切在工具调用中间」的真实实现**：`sessionMemoryCompact.ts:232-314 adjustIndexToPreserveAPIInvariants`（保留区 `tool_result` 的 `tool_use` 不在区内就向前扩展；streaming 分片的兄弟消息一起纳入），文件头注释给了两个真实 bug 场景（`:204-230`）。（§Q2）

## 4. `cc-microcompact.md` — Claude Code 逐条 microcompact

**结论**：**公开版 Claude Code 的 microcompact 默认是 no-op** —— 旧的「按 token 阈值清工具结果」legacy 路径已被删除（带墓碑注释），现存两条路径里缓存编辑是 ant-only 且被 DCE，时间基默认 `enabled: false` 由 GrowthBook 下发。它能借鉴的是一条与「摘要」无关的骨架：**白名单工具 → 内容替换为常量占位串 → 保留最近 N 条 → `tool_use` 原样保留 → 提示词告知模型「结果可能被清，请及时记下要点」**；且**清空后原文不可取回**（靠重跑或另存预览文件）。（原始 §1.2、§3.1、§9）

**证据要点**：

- **分层顺序（便宜 → 昂贵）**：`src/query.ts:365-468`；microcompact 在 `:412-426`（注释 `Apply microcompact before autocompact`），**microcompact 本身不看 token 数**，token 阈值属 autocompact。（§1.1）
- **墓碑注释（最重要的发现）**：`microCompact.ts:253-293` 的分派第 4 步注释 `Legacy microcompact path removed — tengu_cache_plum_violet is always true`；现存路径是「时间基清空」与「缓存编辑删除」。（§1.2）

- **压缩形态 = 常量占位串**：`microCompact.ts:36` `TIME_BASED_MC_CLEARED_MESSAGE = '[Old tool result content cleared]'`；替换 `:475-491` **只换 `tool_result.content`**，`tool_use_id`、`is_error`、块位置全部保留（block 数组被整体替换成一个字符串）。（§3.1）
- **原始内容去向**：时间基**哪都不存** —— `maybeTimeBasedMicrocompact` 是纯函数、不改输入对象、不落盘（`microCompact.ts:470-492`），清除只作用于本次请求视图（**视图不回流 REPL state 为报告标注的推断**）；toolResultBudget 则**落盘**到 `tool-results/<tool_use_id>.<ext>` 并在包装文本里给出 `filepath`，Read 对 `tool-results` 目录无条件 allow（`utils/permissions/filesystem.ts:1657-1672`）。（§4.2、§4.3）
- **取回**：没有「read the full result」专用工具；时间基清空后**无法取回**，设计上靠重跑同一工具（白名单全是可重建的快照类，此为推断）；系统提示词层面持续提醒 `prompts.ts:841`：「original tool result may be cleared later」。（§4.3、§3.3）

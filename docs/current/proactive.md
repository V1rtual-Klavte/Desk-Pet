# 主动陪伴运行时

主动陪伴由 `proactive` 单一调度器持有，路径、Card、会话和窗口监听就绪后仅在主窗口启动。窗口停留、事项时间、用户约定、角色变量、行为画像与离线日历都先形成机会，再统一筛选、去重、规划与表达；窗口监听不直接生成台词。实现验收状态及剩余证据见[执行方案](../plans/active/主动陪伴运行时执行方案.md)，测试通过与真实模型质量通过分别记录。

## 来源、事项与任务

长期事实仍只经 MemoryProvider 解引用。扫描只返回目标 id、版本、范围和时间元数据，不把 SQLite 扫描变成另一条正文注入通道。主动目的按精确目标本地选择，允许核对已过普通召回有效期的目标，仍拒绝遗忘、失效版本和不匹配 scope，不调用记忆重排模型。

事项的 `eventAt/dueAt` 保存 day 或 minute 精度与 IANA 时区；`expiresAt` 只决定普通召回有效期。`workingState` 为 open/completed/cancelled。日期精度的临期窗口在前一日09–22点，跟进从该日期结束起48小时；分钟精度在发生前24小时和发生后48小时。完成、取消、更正或遗忘会事务性关闭关联旧机会；没有用户结果证据不写现实成果。

用户可通过普通对话创建、完成、取消、改期或延后约定。`proactive_query` 返回精确目标与版本；`proactive_change` 只接受本轮已提交可信用户事件，不允许模型用历史消息或自报来源取得写入资格。改期改变事项时间，延后只改变下次提问。目标有歧义时先澄清。周期限 daily/weekly/monthly/yearly，必须有用户明确约定；没有自由 cron、脚本或后台外部工具。DST缺失时间顺延到首个合法分钟，重复时间取第一次；月末、闰日按最后合法日处理。

## 规则、预算与送达

五分钟心跳与窗口事件共用一条串行调度链。优先级为明确约定、临期、跟进、周年/仪式、回顾、普通内容。无期限未完事项仅可规划未来1–7天的一次跟进。日/周机会有稳定槽，负决定也保存；来源或合法槽变化才重评。话题使用同一内容池供主动分享和用户开聊，角色叙事明确为虚构，观测不自动变成用户偏好。

全局静默22–09点；每日成功发话最多1条、表达尝试3次、规划尝试2次，总模型额度24000 tokens。实际完整请求视图的输入估算加输出预留在Provider前原子准入；完整Card/协议放不下则拒绝，不截断或隐式调用压缩模型。失败有实际用量则结算，未知用量保留预留。任务队列100、周期约定10、每次规划新增任务最多2、一次消息目标最多2。失败最早30分钟后重试，已提交/未知提交 occurrence 不重放。

忙碌依据 Harness open operation 和 Rust claim，现有全局冷却仍由 cooldown 模块持有。未回复2次抑制非约定分享/好奇/节拍，4次抑制全部直到新用户输入。可靠连续工作30分钟降低非约定打扰；长期样本不足只用普通时间规则，不编造精确作息。

规划子运行与主动表达都无工具，分别准入、计费，受用户插话、停止、Card/会话切换、来源失效与系统状态约束。表达返回 committed/skipped/failed；committed 必须核对主动 custom trigger、原生 completed operation 的 assistant tip，再取得 SQLite 回执。message_end、模型正文和UI随机id都不是提交证明。回执成功后才投递所属会话、统计未回复、提示音与允许的Card patch；主动结果未确认时会话读模型隐藏它。

崩溃后用 session/request/attempt 身份核对JSONL与SQLite；已提交补回执，不重新生成。读取失败或无法证明的尝试保留未知状态，不当作从未发过。会话正文与SQLite不宣称跨库事务；遗忘不删除原聊天或外部备份。

## 观测、表现与控制

行为画像独立存放在 `behavior/`，不进记忆FTS、dreaming或记忆导出。四组指标与质量、存储和清除边界见[行为画像](behavior.md)。监控关闭只关闭观测来源，事项和纯时间规则仍用独立的可见性、锁屏、系统idle入口判定资格。

presence只有 idle/working/resting 和有限短动作，不移动真实窗口或执行外部动作。文案取当前Card的 `StageMap.presence`，通过titlebar所有权写入；短动作每小时最多2次、每次2秒，隐藏、锁屏、减少动态效果或销毁时停止。日历运行期离线，农历节日及节气使用[香港天文台年度历表](https://www.hko.gov.hk/tc/gts/time/conversion.htm)的2026–2035本地数据，覆盖范围外明确 calendar_uncovered，不推算法定调休。

聊天入口：`/proactive on`、`/proactive off`、`/proactive status`、`/behavior clear`。关闭取消主动尝试与表现，保留约定暂停；开启只检查仍有效窗口，不堆积补发。画像清除先撤销SQLite中的派生资格，再排空采集队列、删除文件与RAM；旧样本不能恢复，启用监控时后续新样本继续采集。没有新设置页、批准弹窗或提醒历史面板。

开发模式 `window.__proactive.events()` 只读最近200条脱敏事件。事件经现有RuntimeTrace发布，不保存标题、记忆正文、用户原话或完整Prompt；trace观察者不承担业务提交或取消资格。理想线路由用户撰写，审阅门禁与证据工具见[测试README](../../test/README.md)。

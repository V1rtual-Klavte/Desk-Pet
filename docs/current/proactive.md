# 主动陪伴运行时

主动领域持有机会、门禁、预算与送达；[统一调度核心](../../src/services/scheduler/)持有一个最近期限计时器，分别注册主动随机扫描、静默了解、dreaming 和用户任务。路径、配置、Card、会话及窗口监听就绪后统一启动，关停先拒绝新触发、取消并排空，再刷写。系统处理器没有模型工具或用户任务管理入口。当前实施与验收记录见[统一调度与子运行执行方案归档](../history/implementation/统一调度与子运行执行方案-2026-10-18归档.md)；剩余验收见[未完成总表](../plans/active/未完成工作与已知缺口.md) §11。

## 频率档位与静默时间段

三处频率统一为「关 / 低 / 中 / 高」四档，**独立启用开关全部并入档位**（档位就是唯一开关）；「关」= 不自动跑，手动入口保留（如记忆面板的手动整理按钮、静默了解页的「立即了解一次」都不受档位约束；后者不计当天自动批数，上一批未结束前不重复触发）。三处档位彼此独立：`ai.proactive.frequency`、`ai.silentAccess.frequency`、`ai.memory.dreaming.tier`（默认均 `medium`）。档位数值表（唤醒区间、每日配额、token、停留/防抖/冷却等）的唯一真相源是 [proactive/protocol.json](../../src/services/proactive/protocol.json) 的 `tiers`（生成器同步到 TS 与 Rust 两侧；[tiers.ts](../../src/services/proactive/tiers.ts) 只负责读取收拢与查表）；记忆整理档的三档只含固定钟点表与最小间隔——其每日 token 上限已于 2026-10-06 撤除（与主动链同批口径，token 只记观测账）。

| | 低 | 中 | 高 |
|---|---|---|---|
| 主动消息随机唤醒区间 | 2–5 小时 | 30–90 分钟 | 10–30 分钟 |
| 主动消息每日成功 / 表达 / 规划 / 辅助上限 | 2 / 4 / 3 / 2 | 6 / 12 / 8 / 4 | 10 / 20 / 14 / 8 |
| 主动消息开口后冷却 / 每日 token（记账阈值，非门禁） | 3–5 小时 / 8000 | 1–3 小时 / 24000 | 30–90 分钟 / 40000 |
| 静默了解固定钟点 / 批次间隔 | 12:00、20:00 / 2 小时 | 10:00、14:00、18:00、22:00 / 30 分钟 | 09:00、11:00、13:00、15:00、17:00、19:00 / 15 分钟 |
| 静默了解每日轮数（=钟点表）/ 每小时读取名额 | 2 / 4 | 4 / 8 | 6 / 12 |
| 记忆整理固定钟点 / 最小间隔 | 同静默了解表 / 4 小时 | 同静默了解表 / 60 分钟 | 同静默了解表 / 30 分钟 |

成本：主动消息低→高约 5 倍 token，设置页「高」档 help 已提示。完整字段与逐值以生成表的 `tiers` 为准。每日 token 总量自 2026-10-06 起只记账、不设闸：唯一硬边界是次数上限（见「规则、预算与送达」）。

**随机唤醒（不形成固定节拍）**：主动消息不再用固定 `tickMs` 节拍——每次唤醒后从档位区间 `[min, max)` 内随机抽下一次检查时刻（主动业务计算期限，统一调度核心安排唤醒，扫描收尾再抽下一次）。事件唤醒保留：前台身份变化、解锁、系统 idle 跨过 5 分钟阈值、变量提交、会话/Card 变化与配置刷新都会立即唤醒一次；事件唤醒覆盖该扫描作业的旧期限；用户任务的提醒专用检查只处理到期约定，不产生随机话题，也不重排随机扫描期限。`tickMs` 不再充当扫描节拍，只作 planner `set_presence` 有效期的短窗（5 分钟）。

**用户静默门（硬编码 3 分钟，不开放配置）**：非时间敏感机会要求最后一条用户消息距今 ≥3 分钟；不足 3 分钟时在扫描选择前丢弃并留痕 `proactive_skipped(user_recently_active)`。`scheduled_task` 与 `memory_checkin` 属于提醒、约定、临期，不受此门禁限制；没有用户消息的会话直接放行。

**静默时间段（设置项，出厂默认 0/0 不静默）**：仅约束**主动消息**——该时段不唤醒、不产生机会、不发送；静默了解与记忆整理不受它门禁（两链的固定钟点表本身避开 23–9，不随 quietStartHour/quietEndHour 变化）。`quietStartHour`/`quietEndHour` 是本地小时 0–23 整数（AI 设置「主动陪伴」区两个 Number），跨夜语义 `start > end`；`start == end` = 不静默（显式关闭）；白天不设窗口。晚安窗口由静默开始时刻派生：`(quietStartHour + 23) % 24` 那一小时到静默开始为止（如 start=23 时为 22:00–23:00），只保留一次晚安机会；不静默时晚安窗口一并关闭；约期前置窗口下界同样由静默值派生；变量池 `isNightTime` 与主动链共用 `isQuietHour` 同一公式。

**白天窗口删除**：原写死的 9–12 / 18–22 硬窗口（`SHARE_START_HOUR`/`SHARE_END_HOUR`/`MIDDAY_HOUR`/`EVENING_HOUR`）全部删除，rhythm（晨/晚）、retrospective（周日）、anniversary、calendar、topic_share、curiosity 改为本地整日（00:00–次日 00:00）有效，夜间边界只由静默时间段门禁负责。画像逐小时资格（可靠画像时 `observedHours[hour] > 0`）保留；小时值只统计 active 时长，idle、unknown、unobserved 不算用户活跃。它是自适应信号而不是硬窗口；画像不可靠时不限小时。

**主动开关从 SQLite 撤出**：Rust `proactive_control` 表删除 `enabled` 列（保留 `mute_until`/`revision`——运行期暂停状态，不是设置；claim 拒绝理由 `muted` 只来自暂停）。该批把 `MEMORY_SCHEMA_VERSION` 递增到 3；当前版本为 6，旧库由 Rust 迁移自动补齐，不要删除 `memory.sqlite3` 三件套（含 `-wal`/`-shm`）。

**档位投影到 Rust（终裁）**：Node 在 scanner 启动与每次 `refreshProactive()`（设置保存 / `/proactive on|off` / 配置导入的消费者刷新）把当前档位派生的 13 项 limits 经 `proactive_control` 通道下发；Rust 存为 **dispatcher 级运行期投影**（与 MonitorState 并列，不进 SQLite、不读 CONFIG、不回写），用于 claim 的间隔/配额终裁与辅助尝试天花板；缺省回落中档。校验口径：13 字段全必填且必须与 low/medium/high 任一行逐字段全等，不匹配拒绝整条请求并留痕（拒绝不改投影现值）；`off` 档不推送（Rust 保持现值/缺省）。真相源仍是 CONFIG。辅助尝试天花板按 kind 取档位最大值的静态上限（observation→静默档钟点表最高 6 轮、其他→主动档最高 8），不再按旧常量 4 截断。`dailyTokens` 自 2026-10-06 起是**观测阈值**：token 账（reserved/used/unknown）照记，不作 claim 或辅助预留的拒绝条件。

**状态**：以上为 W2 代码事实（2026-10-05 落地）；L2/L3 用例已写、**未运行**，统一留收口波；「导出配置再导入，档位与开关往返一致」待验收。

## 来源、事项与任务

长期事实仍只经 MemoryProvider 解引用。扫描只返回目标 id、版本、范围和时间元数据，不把 SQLite 扫描变成另一条正文注入通道。主动目的按精确目标本地选择，允许核对已过普通召回有效期的目标，仍拒绝遗忘、失效版本和不匹配 scope，不调用记忆重排模型。规划输入的目标记忆证据（`targets → recallMemory`）与主回合记忆投影、scanner 机会来源、观察决策同一口径，受 `ai.memory.enabled` 总闸：关闭时不召回、`evidence` 按空降级（照常产出可判输入、不报错）。规划子运行不给模型 `memory_query`——它硬需本轮已提交可信用户事件；主动规划不在用户回合内、没有事件可绑，调用必失败。模型驱动的记忆查询本批不开（2026-10-05 口径），证据仍只走运行时绑定的 targets。

事项的 `eventAt/dueAt` 保存 day 或 minute 精度与 IANA 时区；`expiresAt` 只决定普通召回有效期。`workingState` 为 open/completed/cancelled。日期精度的临期窗口在前一日09–22点，跟进从该日期结束起48小时；分钟精度在发生前24小时和发生后48小时。观察事件按真实 `occurredAt` 归属周期（23:50 的事件跨午夜仍归前一天，窗口可延伸到次日），同日两次事件各有独立 period 身份和抽样。完成、取消、更正或遗忘会事务性关闭关联旧机会；没有用户结果证据不写现实成果。

用户任务只有 `schedule_query`、`schedule_change` 两个工具，分别提供分页查询（id、状态、结果）与 propose/create/update/reschedule/snooze/complete/cancel/decline。内部 proactive、静默了解、dreaming 不在列表、上下文或可修改对象中；现有频率设置仍从设置窗或斜杠入口管理。旧模型工具名已删除。用户任务必须绑定当前会话或 Card（不接受 `scope=user`），查询同时核对冻结的 `session/Card/cardHash`；删除所属会话或 Card 时先取消在飞运行，再把对应 active 任务置为 invalidated，晚到结果不能按新 owner 交付。任务的 Card 归属只是交付与实际执行方：规划产生的跟进任务保持在规划时的 Card（有会话引用则随会话），避免跨 Card 交付；它不构成记忆范围——主动 memory 目标只来自 `user` 池与目标所属会话。

任务定义保存在 `proactive_tasks.intent`，类型为 reminder 或 agent_job；`schedule` 保存时区、日历周期、固定点／窗口／已确认作息锚／真实观测事件、固定或随机次数、最小间隔、有效期及错过策略。次数以成功送达为准；随机次数和时间点每周期只抽一次并持久化，重启、重试和延后均沿用。一次性、日、周、月、年、跨午夜、DST 与月末均由用户任务日历单点解释；观察事件缺失时不降级成固定时刻。

创建和修改必须绑定本轮已提交可信用户事件、来源版本与任务版本。信息缺失时返回具体缺项，不强制创建；关键推断需要提出具体安排，用户接受须匹配 proposalId、完整参数指纹、来源和工具描述符。只有唯一可见提议允许简短同意；多提议或多任务时，接受、拒绝和取消的原话须唯一指向目标，模型传入的 id 本身不是用户授权。完整明确指令可直接创建。改期改变事项锚；snooze 仅改变下次交付时间、不改变定义版本；送达不等于现实事项完成。

**拒绝提醒不等于取消事项**：`decline` 仅接收可见 proposalId，目标与来源从宿主冻结的提议取得，不允许模型附带替代任务、版本或事项。拒绝提议或取消关联提醒时，Rust 在同一事务写 `proactive_reminder_suppressions`（事项稳定 id、操作 id、时间）、关闭关联 active 任务并使调度产物失效，保留 working 事项正文、版本和 open 状态。抑制跨事项版本与重启保留，普通任务清理不会解除；扫描在分页前排除，claim、来源重验和结算再次拦截，避免重新派生。当前安装的抑制记录不随记忆备份恢复回退；事项本身被清除或整理删除后，记录随之修剪。只有用户明确重新创建、更新或改期且授权精确包含当前来源版本时才事务性解除，后续校验失败全部回滚。`memory_change` 的 cancel 与 correct→cancelled 拒绝仅表达「不用提醒」的证据；明确取消现实事项仍走原有事项治理。

执行型任务在独立任务 owner 下调用唯一 `runPiSubAgent`，不会启动主会话规划或占用主聊天槽。任务保存 low/medium/high 思考强度，执行时冻结实际辅助模型、能力及预算。后台只借用任务声明的已启用 MCP server，不把全部 MCP 下放；逐次复核持久授权、参数范围和描述符；MCP 的只读提示仅说明资格，仍保持 DANGER、效果互斥、不重放和 PermissionKernel 终裁。**2026-10-19 产品裁定**——`readOnlyHint` 不满足 DANGER、不绕过权限内核；有原生确认面板时，定时任务遇到持久授权不足的 `ask` 走 interactive 权限模式弹窗，用户批准后继续执行；无确认面板的宿主保持 background，`ask` 记 needs_input。必要授权或能力缺失直接记录 needs_input；只有明确的未完成/缺产物归为 needs_input，来源与能力合同失败归 failed，未知副作用归 unresolved。

工作产物通过完成条件、工具回执、链接和日期校验后保存为 ready_to_deliver，再用无工具的 Card 表达进入原有消息提交／回执链。今天新闻须有真实回执的当天日期证据；模型自报日期不算。聊天忙、当前会话/Card 不匹配或交付被门禁挡住时保留产物，窗口内再交付，不重跑工作；无法确认副作用或提交状态时先对账，不盲重放。创建结果走同一主聊天工具回合，以真实结构化结果为依据，由当前 Card 和拟人化设置表达，不另加固定成功台词。

## 规则、预算与送达

档位区间的随机唤醒与窗口事件共用一条串行调度链（机制见上文「频率档位与静默时间段」；tick 自带 busy 重入保护）。优先级为明确约定、临期、跟进、周年/仪式、回顾、普通内容。机会先按指纹去重、再按已评估与打扰档位筛选，不用前 100 条截断遮挡后面的有效事项。无期限未完事项仅可规划未来1–7天的一次跟进。日/周机会有稳定槽，负决定也保存；来源或合法槽变化才重评。话题使用同一内容池供主动分享和用户开聊，角色叙事明确为虚构，观测不自动变成用户偏好；主题权重只表示讨论参与度，选材保留否定、中立、引用与假设立场，不能改写成喜爱或认可。话题与角色变体按 30 日账本键去重：宿主 `usedTopicKeys` 在 scan 后作为第二次选材的输入，`topic:<话题>:<变体>` 与 `role:<cardHash>:<变体>` 已用项从池中剔除；角色变体只在未使用项里抽签，用尽时本轮不产出（2026-10-24 修复「先抽后重哈希」导致已用变体绕过过滤回流的问题）。

全局静默时段出厂默认不静默（设置项，见上文）；设了静默时开始前一小时只保留唯一晚安槽；每日成功/表达/规划上限随档位（低 2/4/3、中 6/12/8、高 10/20/14）。每日 token 总量随档位下发（低/中/高 8000/24000/40000）但**只记账、不设闸**（2026-10-06 用户裁决：它与次数共用同一池时只会互相踩——实机表现为规划烧满后表达 claim 被 `token_budget` 拒、主动消息一整天发不出），claim 与辅助预留的拒绝条件只有次数上限与机制门。实际完整请求视图的输入估算加输出预留在Provider前原子受理（token 账照记；超上下文窗口由 Node 侧护栏跳过）；完整Card/协议放不下则拒绝，不截断或隐式调用压缩模型。规划子运行带工具 schema 与补齐输入后同走这条准入/预留/结算口径：固定增项典型约 780 token、上限约 1080（含最多 3 件工具 schema；文本模型少一件），工具结果与多轮回灌的实际用量经子运行 usage 汇总后照常结算。规划输入冻结为：本地时间（可读时刻含星期与 IANA 时区）、presence 快照（状态/理由/判定与到期时刻）、Card 人设有界摘要（名/描述/角色设定/语言风格，≤400 token，仓库默认卡约 379 token 不截断）、变量池只读摘要（system 原始值 + card/interaction 当前值，≤300 token，不带写入指令与状态元数据）、行为画像快照（质量状态 + 就近三小时 active 毫秒 + days7/days30；只作时段信号，不能解释为心理专注）与目标记忆证据；机会与证据字段形状不变。失败有实际用量则结算，未知用量保留预留。任务队列100、周期约定10、每次规划新增任务最多2、一次消息目标最多2；普通对话的直接创建与规划结算在同一事务共享容量裁决，绕过不了上限。失败最早30分钟后重试，已提交/未知提交 occurrence 不重放。

忙碌依据 Harness open operation 和 Rust claim；AI 生成锁（回合在飞不打搅）由回合状态推导 —— harness 的受理计数加槽运行状态，没有定时器强解，长回合期间恒为真。**全局冷却的真相源是 Rust 账本**（2026-10-06 起）：起点为最近一条 committed 表达 occurrence 的账本记账时间（全表查询、跨日成立），扫描门禁只读 scan 快照 `budget.cooldownUntil`（该时间 + 档位 `cooldownMs`；无记录或已过期给 null，等价不冷却），Node 不再持有冷却状态、也不在送达后触发冷却（旧 `src/services/cooldown.ts` 整模块已删除；运行时验证待验收）。未回复2次抑制非约定分享/好奇/节拍，4次抑制全部直到新用户输入。可靠连续工作30分钟降低非约定打扰；收工机会还要求从工作转为休闲或空闲并连续观察至少10分钟，切到沟通或浏览器继续工作不算收工；长期样本不足只用普通时间规则，不编造精确作息。

**桌宠可见性不再是主动消息的门禁（2026-10-08 用户裁定）**：原 `pet_hidden`（`!activity.isPetVisible`）在扫描门禁与发送前复核**两处**都会拦下整轮。用户口径：**主动消息就是主动发消息，没有「必须当面」的要求** —— 桌宠收起时发的消息躺在会话里，展开就能看到，那是正常形态、不是需要拦掉的打扰。该关名随之从跳过原因枚举中下线（trace 里不再出现 `pet_hidden`）。静默时间段、冷却、未回复档位与每日上限全部不变。

规划子运行与主动表达分别准入、计费，受用户插话、停止、Card/会话切换、来源失效与系统状态约束。**主动规划是带只读工具的有界子运行**（2026-10-05 落地）：工具面在调用时刻从工具注册表按名装配，白名单 `screenshot` / `window_info` / `system_info`；`screenshot` 受模型能力闸——仅当辅助模型声明图像输入（`resolvePiAuxModel().input.includes("image")`，与静默了解链同款判据）才纳入，文本模型或探测失败时白名单退化为另两件（探测失败按不支持处理，不阻塞规划）；`clipboard_read` 因声明 DANGER 级排除（无用户回合时默认安全模式会落 `awaitPermission` 干等确认），全部 MCP 工具同因排除，且 stdio server 需为子运行单独借用/保活、成本不对等——两者恢复均需新裁决。装配时逐件复核 SAFE 且无参数级重定级入口，不符整件跳过并留痕；工具未注册/改名同样按跳过处理，规划降级为纯文本决策、不因工具面缺件整体失败。运行封顶为最多 3 次工具调用（`PLANNING_TOOL_ROUNDS`，其后 Provider 轮数由工具调用数决定）、90s 超时与 800 输出预留不变，实际用量照常经 settle 结算；取消纪律不变（owner 身份与调用方 signal 进 scope，来源/owner 失效随信号级联，以 `planning_cancelled` 收口）。工具执行的过程提示（`tool-executing` 事件与顶栏过程文案，仅当 owner 会话是活跃会话时）与计划步骤同一条路径，产品接受此行为（角色感由卡片阶段文案承担）。**主动表达继续 `tools=[]`**；表达准入的 `planner_tools_present` 是按回调契约保留的防御分支（当前内核把表达 reservation 的 `toolCount` 钉死为 0，生产路径不可达），一旦表达带工具面即在 claim 前整次拒回且不消耗 claim。表达返回 committed/skipped/failed；committed 必须核对主动 custom trigger、原生 completed operation 的 assistant tip，再取得 SQLite 回执。message_end、模型正文和UI随机id都不是提交证明。回执成功后才投递所属会话、统计未回复、提示音与允许的Card patch；主动结果未确认时会话读模型隐藏它。历史回执按 attempt／session／assistant entry 精确核对，切换 Card 或修改其 hash 不隐藏已确认的历史；未知提交立即进入可对账状态并保留预留，等回执或清理后再定论。

崩溃后用 session/request/attempt 身份核对JSONL与SQLite；已提交补回执，不重新生成。读取失败或无法证明的尝试保留未知状态，不当作从未发过。**「在飞」按租约计**：claim 的在飞判定只看「非终态（reserved/generating/unresolved）且租约未过期」——租约过期的 `unresolved` 是审计位（行保留、不收口、不重放），不再堵新 claim（2026-10-06 实机修复：一条 14:11 失败的规划尝试曾把全局 claim 门锁死，curiosity 机会每 tick 被 denied attempt_in_flight、重启不恢复）。会话正文与SQLite不宣称跨库事务；遗忘不删除原聊天或外部备份。

静默了解每批在两种方向里选（2026-10-21 用户口径）：`breadth` = 铺开了解整台电脑的所有方面、每批尽量换没看过的方面；`depth` = 挑一个方向往下钻，两种走法各 50%：`existing` 贴着已知了解读过的路径继续向下（宿主终裁，越界目标丢弃）、`new` 自己另找一个还没了解过的方面深入（不设路径限制）。了解层为空时**强制广度**，有已知方面后广度/深度各半；Provider 输出不设 `maxTokens`，输入侧仍保留每小时读取名额与单文件字符预算。读取数值上限已删除（2026-10-05 用户口径）：单文件 32KB、目录 40 条、单批 ≤3 目标、目录扫描预算 256 都不再设硬顶，读什么由模型裁断；路径边界全部保留并由宿主终裁（绝对路径、canonical 解析、排除数据根与凭据路径；整机只读——2026-10-06 用户裁决，不再限于用户主目录、不再排除 home 系统目录）。保留的两个数不是「读取大小上限」：每小时读取名额是防突发闸（随档位 4/8/12，`silentTierLimits(tier).maxReadsPerHour`，`MAX_READS_PER_HOUR` 常量已删），喂给整理调用的单文件字符预算（`MAX_TEXT_CHARS_PER_FILE`）是请求 token 截断。风险如实：大目录或大文件没有硬顶，靠模型裁断。

## 观测、表现与控制

行为画像独立存放在 `behavior/`，不进记忆FTS、dreaming或记忆导出。四组指标与质量、存储和清除边界见[行为画像](#行为画像)。macOS 只取前台进程自己的窗口标题（按窗口 owner PID 匹配），匹配不到就返回缺失标题，不拼其它应用的标题；窗口采样由原生事件驱动、空闲按需现采，观察时间不再是窗口机会的新鲜度判据（身份变化会取消在途窗口任务）；监控关闭只关闭观测来源，事项和纯时间规则仍用独立的可见性、锁屏、系统idle入口判定资格。锁屏（`screen_state=locked`）不再判为观察不可用：主动消息照常参与、不额外加严；静默了解在固定钟点到点即跑（2026-10-06 起不再要求 idle 达标、允许用户在用电脑），仅 `screen_state=unavailable` 跳过本轮；locked 批跳过截图类（Node 不请求、Rust 终裁拒绝），只用文件/目录与最后一次窗口快照（决策提示注明快照可能陈旧）；只有 `unavailable`（真不可知）才丢弃机会并留跳过原因。窗口类机会在锁屏期间仍会因当前窗口数据陈旧自然失效（`window_unavailable`）——这是既有新鲜度判据而非锁屏加严；非窗口类机会不受影响。观察门禁资格有常驻 L3 用例（caseId `proactive-observation-gate`，契约 pr-09，覆盖三态准入与 locked 跳过截图），测试已写、按用户要求统一留到收口波运行。

presence只有 idle/working/resting 和有限短动作，不移动真实窗口或执行外部动作。连续观察工作或开发上下文 30 分钟可进入 `working`（不依赖长期画像质量门槛）；presence 不设到期租约，由下一条观察、观察许可关闭或卡片切换释放。`resting` 来自当前观察到的 idle 或媒体上下文，不代表人格或真实休息结论。文案取当前Card的 `StageMap.presence`，通过titlebar所有权写入；短动作每小时最多2次、每次2秒，隐藏、锁屏、减少动态效果或销毁时停止。日历运行期离线，农历节日及节气使用[香港天文台年度历表](https://www.hko.gov.hk/tc/gts/time/conversion.htm)的2026–2035本地数据，覆盖范围外明确 calendar_uncovered，不推算法定调休。

聊天入口：`/proactive on`（档位恢复出厂默认「高」，不记忆上次档位，只检查仍有效窗口、不堆积补发）、`/proactive off`（档位置「关」，即时取消在飞尝试与表现、保留约定暂停）、`/proactive status`（显示当前档位 + 今日送达 + 暂停中）、`/behavior clear`。画像清除先撤销SQLite中的派生资格，再排空采集队列、删除文件与RAM；旧样本不能恢复，启用监控时后续新样本继续采集。AI设置「主动陪伴」区提供主动消息档位与静默时间段，与斜杠命令读写同一份 CONFIG（档位不再是 SQLite 控制点，命令与设置同源）。拟人表达开关控制表达节奏，静默访问档位控制观察来源，两者独立于主动消息档位。

开发证据出口：`ProactiveTrace` 的 debug 日志与 `subscribeRuntimeTrace` 只读订阅（`@/services/engine/protocol`；生产不订阅、不保留负载，测试适配器按需订阅）。事件经既有RuntimeTrace／logger发布，覆盖窗口观察与画像结算、机会、规划、claim、表达、反馈与事项治理，并给跳过原因（如静默、冷却、忙、视图过期、预算或 owner 变化）以及 tick／attempt／request 关联；不保存标题、应用身份、记忆正文、用户原话或完整Prompt，trace观察者不承担业务提交或取消资格。理想线路由用户撰写，审阅门禁与证据工具见[测试README](../../test/README.md)。

## 行为画像

行为画像是 `data_root/behavior/` 下独立的派生数据域：原始账（`segments/`、`daily/` 与内存读模型）不直接进入长期记忆、dreaming 的用户区或用户事实。画像层唯一允许沉淀进记忆的是**稳定结论**（见「稳定结论沉淀」：只在 reliable 档存在，经 dreaming 的派生区沉淀为「系统观察」，与用户事实分区存放、分区召回，并随画像清除一起失效）。静默访问档位（`ai.silentAccess.frequency`）是观察许可；档位「关」时 Rust 观察线程停止采样，前端清当前快照并结束画像分段。隐私清除先撤销主动来源对行为画像的引用，再清除画像文件与内存读模型。

### 原生观察

Rust 单一 monitor 线程发出 `window-observed`。采样由原生事件驱动：macOS 注册 NSWorkspace 的前台切换／系统睡眠唤醒／显示器睡眠唤醒／会话切换通知与锁屏、解锁分布式通知，Windows 安装前台窗口 WinEvent 钩子与会话、电源（睡眠唤醒、显示器开关）通知；不再按固定间隔轮询，`general.desktop.pollingIntervalMs` 已退役、运行期无消费者。系统或显示器睡眠、会话恢复先补发一条 `suspended` 边界再发新采样，避免把离开时长当成连续使用。每个有效采样包含 `appId/app/title`、Unix `observedAt`、本代 monotonic `sampleMonoMs`、`monitorGeneration`、单调 `sequence`、屏幕维度 `screen_state` 与正交的系统 idle、桌宠可见和前台状态。`screen_state` 三态：`observed`（前台窗口可截）／`locked`（锁屏；截图无意义但状态可知）／`unavailable`（真不可知）；idle 与它正交——锁屏也带 idle（「用户离开」与「离开多久」是两件事），idle 无效（NaN、负数或缺失）时整体判 `unavailable` 且不带 idle。事件载荷 `observation_state` 保持 5 值生命周期维度（`observed/locked/unavailable/suspended/disabled`）、字段名不变，与命令路径的 `screen_state` 不同义：正常采样由 `screen_state` 直通，监控边界样本以 `suspended`/`disabled` 直通。Windows 应用标识只取进程文件名 stem，不保存可执行文件路径；macOS 取 bundle id 与当前应用名，标题只取属于前台进程（窗口 owner PID 匹配）的窗口，否则标题缺失。锁屏和不可用状态不带应用或标题。macOS 锁键判定：`CGSSessionScreenIsLocked` 键缺失或显式 `false` = 未锁定（继续查 idle），`kCFBooleanTrue` = 锁屏，非常规取值 = `unavailable` 并一次性 `rust_warn`；键缺失打一次性 `rust_info`，不随每次采样重复。这是隐私相关的放宽：未来系统若锁屏时也不写该键会误报 `observed`，取舍是相对「键缺失即永久 `unavailable`、依赖观察的两条链从不运行」。Windows（winlogon）分支同样先查 `GetLastInputInfo` 再定状态、`locked` 也带 idle（行为变更；本机不可验证，唯一权威是 CI `windows-latest`）。独立 `get_runtime_activity` 只返回桌宠可见/前台、`screen_state` 三态、idle 和采样时间，不返回当前应用身份，空闲资格按需现采；消费包装对 `unavailable` 按同因 10 分钟限频 `log.warn` 留痕（文案含影响面「依赖观察的主动机会与静默了解会被跳过」），恢复可用后重置限频记忆。

前端唯一事件入口做形状、代际和序号校验：旧代际、重复和乱序样本丢弃；窗口工具只读这份快照。窗口观察订阅者同步收到原事件，画像写盘在自身串行队列执行，不阻塞主动规则的事件监听。

### 分段、聚合和质量

每段有效时间只落入 `active`、`idle`、`unknown`、`unobserved` 之一。相同应用身份的连续观察可以合并，但事件之间的长间隔不会整段算作 active：单段不超过 5 分钟且两端 idle 都低于 5 分钟时，才可把间隔记为 active；较长间隔用单调 idle 计数切分可证明的 active 前缀与 idle 后缀，idle 计数重置或不足以解释的部分记为 `unknown`。墙钟间隔超过 monotonic 可确认时长的部分，以及锁屏、不可用、挂起等边界前未被证明的时段，记为 `unobserved`。队列丢弃也会切断分段并记为 unobserved；时钟回退不拿负时长补账。所有时长按本地日、小时拆分。

单日聚合包含 `categoryMs`、本地小时直方图、appId 时长、工作连续段统计、切换数、`coveredMs`、`unobservedMs`、`idleMs`、`unknownMs` 和桌宠前台使用时间；`active/idle/unknown/unobserved` 互斥。`hourMs` 只累计 active，idle、unknown 与 unobserved 不进入逐小时活跃分钟。appId 每日最多记录 64 个；没有标题、正文、标题哈希或截图。滚动 JSONL 分片每片不超过 512 KiB、**保留 7 日**；daily JSON **保留 40 日**（启动只读最近 **35 日**——画像本身只用最近 30 天，余量给跨日与时钟回退）；最新四类画像只留内存读模型，可由 daily 重算。计量口径升至 `measurementVersion=2` 后，旧版本 daily 不混算为 v2；先持久化派生记忆撤销待办，再删除旧派生缓冲，避免重启重复撤销新结论。读取异常不标记装载完成，下次读取重试。首次读取或登记派生记忆前由共享 memory reconciliation 撤销旧派生行为来源，闭包成功后才清待办，失败则保留待办重试。**保留期与「画像结论长期化」联动**：稳定结论沉淀进记忆后，原始账降级为滚动工作缓冲，长期回看由结论承担；因此结论必须能在 30 天画像窗口内被重新验证或推翻，不得依赖更长的原始历史。

画像提供 `rhythm/apps/focus/activity` 四组近30个日历日画像；另有按最近7个日历日裁剪的 `weekly` activity/focus，供周回顾使用，不以“最近7个有样本的日子”代替一周。应用类别以 `appId` 身份规则判定，命中时置信度为 high；标题只用于短暂的媒体 activity hint，属于 low 置信线索，不能把未知应用推断成已知类别，原始标题不落盘。`focus` 字段是已识别 work/development 应用在 active 时间内的连续段统计，是应用类别与时间的代理指标，不代表心理专注、产出或实际工作。`quality.eligibleCollectionMs` 是覆盖时长与 `unobservedMs` 之和；应用未运行或监控关闭期间没有采样，不计入可评估时长。`unknownMs` 虽没有可靠活动分类，仍属于已收到且有时间边界的覆盖；`unobservedMs` 则是无法确认的时间。没有有效采集时间时质量为 `unavailable`；`coverageRatio = coveredMs / eligibleCollectionMs`，至少 3 个有效观察日且覆盖率≥60%才标为 `reliable`。质量不足时仍可使用当前连续观察支持的短时上下文，但不得据此宣称长期作息、精确工时、心理专注或成就。

`clearBehavior()` 先停 collector 并等待其队列完成，再删除行为目录并清空内存快照。调用端须先在 SQLite 主动控制事务里失效 behavior 来源的机会、任务、未决尝试与派生缓存，**并在同一事务里失效派生结论沉淀的记忆**（先失效引用、再写来源墓碑、删正文/索引/候选，见下节），然后调用此清理函数。停止后的迟到事件不写回。

### 稳定结论沉淀

抽取层是 [conclusions.ts](../../src/services/behavior/conclusions.ts) 的纯函数 `sedimentConclusions(snapshot)`：唯一输入是画像读模型 `BehaviorSnapshot`（近 30 日 `rhythm/apps/focus/activity` + quality），拿不到 `daily/`、`segments/` 原始账——“不沉淀原始账”是类型签名层面的边界，不是注释约定。只有 `quality.status === "reliable"`（≥3 个有效观察日 + 覆盖率 ≥60%）才产出结论，其余状态返回空数组（不登记、不沉淀）；每个画像组最多一条，共四个槽位（`rhythm/apps/focus/activity`），文本只含带段/整比/取整后的表述，并**自带判据**（依据的画像字段与窗口，如「判据：近30日画像窗口的最强 4 小时活跃带」）。**不记清单**：具体某天的工时、精确时间戳、逐次应用切换细节、窗口标题/正文/截图——这些只留在画像域。可重验/可推翻：结论由当前滚动窗口重算，新数据改写输入即改写文本；不依赖 >30 天历史（与原始账 7/40 日滚动缓冲口径一致）。

登记与整理在记忆域：`collectBehaviorMemorySources`（[sources.ts](../../src/services/agent/memory/sources.ts)）把结论登记为 `derived_behavior` 来源（合成会话 `behavior`、条目 `conclusion:<slot>:<measurementVersion>`、来源身份含 `measurementVersion` 与结论文本 hash——同版本同结论幂等，新版本进入覆盖流程）；dreaming 前置登记后按来源类别分开开作业，派生批次的 Review 是**确定性映射**（[dreaming.ts](../../src/services/agent/memory/dreaming.ts) 的 `buildDerivedCandidates`：结论文本原样成为正文，模型不参与改写或演绎观察，也不占 token 预算），同槽位新版本带 `supersedesId` 覆盖旧条目（新旧冲突的收敛 = 版本 + 覆盖，不无界堆积）。沉淀出的条目 `origin=derived_behavior`：分区存放与召回、永不进核心画像、不做 working 事项、不跨来源类别改写（Rust 在发布与治理写入两侧校验）；记忆块里标「系统观察」并注明是可由用户撤销的推断；记忆面板的库总览行与详情也对派生条目标注同一标记（用户事实不标注）。用户清画像（`/behavior clear`）时，Rust 在同一控制事务里先失效主动引用，再给全体派生来源写提取墓碑、删条目/索引/候选并推进 `forget_epoch` 与 memory revision（先失效引用再删数据）；已清的结论文本不能迟到回灌，也不会在清画像后自行复活（结论文本变化产生的新身份不受影响）。**清画像的闭包覆盖全部派生来源**：了解摘要（`understanding:` 前缀）与结论（`conclusion:` 前缀）一起被写墓碑与清理。**第二条派生通道**：静默了解的摘要经 `collectUnderstandingMemorySources` 登记为同区来源，身份绑定稳定 artifact、输入版本与摘要；同 artifact 内容更新替换旧观察，缺证据旧摘要不登记。每次最多登记最新 12 个不同 artifact 的可验证观察，满额按最旧优先 supersede；候选仍为确定性映射（文本逐字、不经模型演绎）。共享 memory reconciliation 在 recall 与 derived registration 前检查 `measurementVersion=2` 的画像待撤销标记和了解层旧证据待办；只有闭包成功才确认标记，失败保留待办重试。「清除静默了解」复用现有了解闭包，范围收在 `understanding:` 来源（`memory_apply_change` 的 `forget_understanding`，actor 固定 internal）。实现细节与失效链证据见[当前记忆](memory.md)与[数据库](database.md)。

### 了解与话题参与

静默了解的目的是了解用户本身（工作与项目、投入与关注、生活与兴趣、工具与习惯），窗口与截图只是线索。两种方向与读取边界见上文「规则、预算与送达」：`breadth` 铺开整台电脑、`depth` 各 50% 走 `existing`/`new`，了解层为空时强制广度；读取范围为整机只读，读取数值上限已删除，每小时读取名额与单文件字符预算保留。

`observation` 持有独立派生文件 `behavior/understanding.json`：观察摘要**不直接进入**长期事实，只有经 dreaming 派生区（`origin=derived_behavior`，与画像结论同区）确定性沉淀的条目才进记忆库，原始 `understanding.json` 不进 FTS、不进入记忆导出。决策输入由窗口快照（锁屏时为最后一次并注明可能陈旧）与最近 8 条已知了解，外加五块只读有界摘要组成：本地时间（含星期与 IANA 时区）、Card 人设有界摘要、画像质量与就近 6 个钟点活跃分钟（近 7 日）、话题 top-5 占比，以及长期记忆核心画像（空 query 走 core 召回、token 256、条数 ≤3、单条 ≤400 字符、显式跳过重排、身份取运行时活跃会话与激活 Card）。各块缺省或不可靠时如实降级（无激活 Card 为 null、画像不可靠原样带质量状态、话题为空数组、无活跃会话或 `ai.memory.enabled` 总闸关闭时不召回、召回失败按空），降级不使批次失败；决策输入整段计入 aux 共享 token 预留。决策解析失败、字段非法或路径非绝对时本批不读文件，只保留截图（锁屏批只保留最后一次窗口快照）。

摘要质量：纯否定结论（截图无有效内容、目录里没有项目文件、读取失败）不进入了解层——存储写入与快照两侧用同一判定挡掉，既不展示、也不计入覆盖率（`ready` 仍要求至少 3 个独立来源，但只数有信息的观察），更不会被沉淀成记忆。退化截图（高度 <120 或不足宽度 1/10 的扁带）由 Rust 判不可用，Node 回退到窗口快照与目标读取。了解批次落盘后**事件驱动**触发一次派生整理（`runDreamingSweep`，派生 Review 是确定性映射、不过模型），失败只留痕，来源仍在水位之后等下次重试。

每条了解记录同时保存 `evidenceId`（稳定 artifact 身份的 SHA-256）与 `evidenceHash`（实际输入版本的 SHA-256），不留第二份正文；前者决定独立来源数，后者只标记该 artifact 的内容版本。文件/目录以路径作为稳定身份；窗口与截图以 `appId` 作为稳定域，标题不参与身份。内容更新不增加独立来源数，新版本覆盖该 artifact 的旧观察；展示覆盖数与独立来源数分开，只有至少 3 个独立 artifact 才是 `ready`。缺少任一 hash 的旧记录可留作本地展示，但不计 ready、不进入了解 prompt，也不能登记为派生记忆来源；读取时先持久化 memory closure pending，首次 recall 或 derived registration 经共享 reconciliation 撤销旧了解沉淀，闭包成功才清 pending。

可信、已提交用户原话按参与来源入队，单次辅助调用提取标签、有限 category / sensitivity / stance 枚举与权重；正文只在 RAM 请求中使用。敏感或 unknown 标签不存入可用选材；中立、负面、引用、假设、否定与不确定立场按原枚举保留。权重表示讨论参与度，不表示喜好或稳定事实；来源与规范化主题配对后去重，同源重复模型输出不增加权重；至少两个独立用户来源才向主动选材提供占比。保留 90 日／512 条上限；清除水位与来源失效阻止旧正文回扫晋升，显式遗忘也会撤销关联标签资格。

停止、前台抢占、会话／Card或来源变化会取消旧代际；预算返回与请求前再次核对来源，原生CANCELLED终止整批；结果返回后再次核对许可与来源。`/behavior clear` 的清除顺序见上文「观测、表现与控制」。

## 数据库

主动链状态与记忆同库同文件（`数据根/memory/memory.sqlite3`）；库文件与版本策略见[数据库](database.md)。


内部固定槽与随机周期、执行产物使用 MemoryStore 的同一 SQLite 连接。静默了解只在辅助预算准入后认领槽，并关联 reservationId；dreaming 关联实际作业。两者保留独立固定钟点及十五分钟追赶窗口；失败或崩溃后没有证明的尝试留 unresolved，不重新消费同一槽。了解文件只保存观察内容，已移除调度尝试字段。

**同钟点联动（2026-10-21）**：两条链共用钟点表、同分钟并发，dreaming 常常先于同批了解出结果（实机 09:00:00 vs 09:01:14）。批次落盘后由了解链**事件驱动**触发一次派生整理，把刚落地的摘要立刻沉淀进「系统观察」区，不再等下一个整点；派生 Review 不过模型，重复触发按来源身份与水位幂等早退。

# 行为观察与画像

行为画像是 `data_root/behavior/` 下独立的派生数据域：原始账（`segments/`、`daily/` 与内存读模型）不直接进入长期记忆、dreaming 的用户区或用户事实。画像层唯一允许沉淀进记忆的是**稳定结论**（见「稳定结论沉淀」：只在 reliable 档存在，经 dreaming 的派生区沉淀为「系统观察」，与用户事实分区存放、分区召回，并随画像清除一起失效）。静默访问档位（`ai.silentAccess.frequency`）是观察许可；档位「关」时 Rust 观察线程停止采样，前端清当前快照并结束画像分段。隐私清除先撤销主动来源对行为画像的引用，再清除画像文件与内存读模型。

## 原生观察

Rust 单一 monitor 线程发出 `window-observed`。采样由原生事件驱动：macOS 注册 NSWorkspace 的前台切换／系统睡眠唤醒／显示器睡眠唤醒／会话切换通知与锁屏、解锁分布式通知，Windows 安装前台窗口 WinEvent 钩子与会话、电源（睡眠唤醒、显示器开关）通知；不再按固定间隔轮询，`general.desktop.pollingIntervalMs` 已退役、运行期无消费者。系统或显示器睡眠、会话恢复先补发一条 `suspended` 边界再发新采样，避免把离开时长当成连续使用。每个有效采样包含 `appId/app/title`、Unix `observedAt`、本代 monotonic `sampleMonoMs`、`monitorGeneration`、单调 `sequence`、屏幕维度 `screen_state` 与正交的系统 idle、桌宠可见和前台状态。`screen_state` 三态：`observed`（前台窗口可截）／`locked`（锁屏；截图无意义但状态可知）／`unavailable`（真不可知）；idle 与它正交——锁屏也带 idle（「用户离开」与「离开多久」是两件事），idle 无效（NaN、负数或缺失）时整体判 `unavailable` 且不带 idle。事件载荷 `observation_state` 保持 5 值生命周期维度（`observed/locked/unavailable/suspended/disabled`）、字段名不变，与命令路径的 `screen_state` 不同义：正常采样由 `screen_state` 直通，监控边界样本以 `suspended`/`disabled` 直通。Windows 应用标识只取进程文件名 stem，不保存可执行文件路径；macOS 取 bundle id 与当前应用名，标题只取属于前台进程（窗口 owner PID 匹配）的窗口，否则标题缺失。锁屏和不可用状态不带应用或标题。macOS 锁键判定：`CGSSessionScreenIsLocked` 键缺失或显式 `false` = 未锁定（继续查 idle），`kCFBooleanTrue` = 锁屏，非常规取值 = `unavailable` 并一次性 `rust_warn`；键缺失打一次性 `rust_info`，不随每次采样重复。这是隐私相关的放宽：未来系统若锁屏时也不写该键会误报 `observed`，取舍是相对「键缺失即永久 `unavailable`、依赖观察的两条链从不运行」。Windows（winlogon）分支同样先查 `GetLastInputInfo` 再定状态、`locked` 也带 idle（行为变更；本机不可验证，唯一权威是 CI `windows-latest`）。独立 `get_runtime_activity` 只返回桌宠可见/前台、`screen_state` 三态、idle 和采样时间，不返回当前应用身份，空闲资格按需现采；消费包装对 `unavailable` 按同因 10 分钟限频 `log.warn` 留痕（文案含影响面「依赖观察的主动机会与静默了解会被跳过」），恢复可用后重置限频记忆。

前端唯一事件入口做形状、代际和序号校验：旧代际、重复和乱序样本丢弃；窗口工具只读这份快照。窗口观察订阅者同步收到原事件，画像写盘在自身串行队列执行，不阻塞主动规则的事件监听。

## 分段、聚合和质量

相同应用的连续观察合并；变化、关闭、锁屏、不可用、暂停（`suspended` 边界）都会截断分段。事件驱动下两次观察的间隔不再代表空窗：没有事件本身就代表前台未变，整段时长回填给上一条观察；只有显式中断状态才切断分段，系统时间回退仍截断。`unobservedMs` 只来自时钟回退截断与采集队列溢出，不再由采样间隔推导。已知边界：显示器常亮、无输入、未锁屏且未进入系统睡眠的时段没有原生事件，仍按「前台未变」回填（显示器睡眠事件把这类时段的上限压到系统配置的显示器睡眠超时；配置为永不睡眠时无界）。跨本地日、小时的时长拆分。系统 idle 超过 5 分钟归入 idle，不计活跃工作。

单日聚合包含 `categoryMs`、本地小时直方图、appId 时长、工作连续段统计、切换数、`coveredMs`、`unobservedMs`、`idleMs` 和桌宠前台使用时间。appId 每日最多记录 64 个；没有标题、正文、标题哈希或截图。滚动 JSONL 分片每片不超过 512 KiB、**保留 7 日**；daily JSON **保留 40 日**（启动只读最近 **35 日**——画像本身只用最近 30 天，余量给跨日与时钟回退）；最新四类画像只留内存读模型，可由 daily 重算。**保留期与「画像结论长期化」联动（2026-10-06 用户裁决）**：稳定结论沉淀进记忆后，原始账降级为滚动工作缓冲，长期回看由结论承担；因此结论必须能在 30 天画像窗口内被重新验证或推翻，不得依赖更长的原始历史。

画像提供 `rhythm/apps/focus/activity` 四组近30个日历日画像；另有按最近7个日历日裁剪的 `weekly` activity/focus，供周回顾使用，不以“最近7个有样本的日子”代替一周。`quality.eligibleCollectionMs` 是实际收到采样、正在许可采集的时间与已知采样空窗之和；应用未运行或监控关闭期间没有采样，不计入已观测时间。事件驱动下采样间隔本身不再产生空窗，`unobservedMs` 只来自时钟回退截断与采集队列溢出。没有有效采集时间时质量为 `unavailable`；`coverageRatio = coveredMs / eligibleCollectionMs`，至少 3 个有效观察日且覆盖率≥60%才标为 `reliable`。质量不足时仍可使用当前连续观察支持的 30 分钟工作上下文，但不得据此宣称长期作息、精确工时或成就。

`clearBehavior()` 先停 collector 并等待其队列完成，再删除行为目录并清空内存快照。调用端须先在 SQLite 主动控制事务里失效 behavior 来源的机会、任务、未决尝试与派生缓存，**并在同一事务里失效派生结论沉淀的记忆**（先失效引用、再写来源墓碑、删正文/索引/候选，见下节），然后调用此清理函数。停止后的迟到事件不写回。

## 稳定结论沉淀

抽取层是 [conclusions.ts](../../src/services/behavior/conclusions.ts) 的纯函数 `sedimentConclusions(snapshot)`：唯一输入是画像读模型 `BehaviorSnapshot`（近 30 日 `rhythm/apps/focus/activity` + quality），拿不到 `daily/`、`segments/` 原始账——“不沉淀原始账”是类型签名层面的边界，不是注释约定。只有 `quality.status === "reliable"`（≥3 个有效观察日 + 覆盖率 ≥60%）才产出结论，其余状态返回空数组（不登记、不沉淀）；每个画像组最多一条，共四个槽位（`rhythm/apps/focus/activity`），文本只含带段/整比/取整后的表述，并**自带判据**（依据的画像字段与窗口，如「判据：近30日画像窗口的最强 4 小时活跃带」）。**不记清单**：具体某天的工时、精确时间戳、逐次应用切换细节、窗口标题/正文/截图——这些只留在画像域。可重验/可推翻：结论由当前滚动窗口重算，新数据改写输入即改写文本；不依赖 >30 天历史（与原始账 7/40 日滚动缓冲口径一致）。

登记与整理在记忆域：`collectBehaviorMemorySources`（[sources.ts](../../src/services/agent/memory/sources.ts)）把结论登记为 `derived_behavior` 来源（合成会话 `behavior`、条目 `conclusion:<slot>`、来源身份含结论文本 hash——同结论幂等、新结论即新版本）；dreaming 前置登记后按来源类别分开开作业，派生批次的 Review 是**确定性映射**（[dreaming.ts](../../src/services/agent/memory/dreaming.ts) 的 `buildDerivedCandidates`：结论文本原样成为正文，模型不参与改写或演绎观察，也不占 token 预算），同槽位新版本带 `supersedesId` 覆盖旧条目（新旧冲突的收敛 = 版本 + 覆盖，不无界堆积）。沉淀出的条目 `origin=derived_behavior`：分区存放与召回、永不进核心画像、不做 working 事项、不跨来源类别改写（Rust 在发布与治理写入两侧校验）；记忆块里标「系统观察」并注明是可由用户撤销的推断；记忆面板的库总览行与详情也对派生条目标注同一标记（用户事实不标注）。用户清画像（`/behavior clear`）时，Rust 在同一控制事务里先失效主动引用，再给全体派生来源写提取墓碑、删条目/索引/候选并推进 `forget_epoch` 与 memory revision（先失效引用再删数据）；已清的结论文本不能迟到回灌，也不会在清画像后自行复活（结论文本变化产生的新身份不受影响）。**清画像的闭包覆盖全部派生来源**：了解摘要（`understanding:` 前缀）与结论（`conclusion:` 前缀）一起被写墓碑与清理。**第二条派生通道（2026-10-06）**：静默了解的观察摘要经 `collectUnderstandingMemorySources` 登记为同区来源（合成会话 `behavior`、身份含文本 hash，同文本幂等）；每次只登记最新 12 条不同文本观察、在库了解条目同以 12 条为上限、满额按最旧优先 supersede；候选为确定性映射（文本逐字、不经模型演绎）。「清除静默了解」复用同一闭包、范围收在 `understanding:` 来源（`memory_apply_change` 的 `forget_understanding`，actor 固定 internal）。实现细节与失效链证据见[当前记忆](memory.md)与[数据库](database.md)。

## 有限陪伴表现

presence 只允许 `idle/working/resting`。当前实际采样连续观察到工作或开发上下文 30 分钟后可进入 `working`，不依赖长期画像质量门槛；presence 不设到期租约，由下一条观察（系统 idle、锁屏/挂起/不可用、上下文变化）或观察许可关闭、卡片切换显式释放。`working` 抑制非约定主动发话。`resting` 来自当前观察到的 idle 或媒体上下文，不代表人格或真实休息结论。

`StreamView` 只在桌宠容器执行轻微的两秒呼吸动作，每小时最多两次；减少动态效果设置、隐藏或组件销毁时停止。它不移动窗口、不切换 Profile 或视觉效果模式、不播放音频。顶栏文案通过 Card 的 presence key 读取，并由 titlebar owner/priority 服务管理；释放时只清自己的 owner 状态。

## 静默了解与话题参与

**用途是了解用户本身**——他在做的工作与项目、投入和关注的事、生活与兴趣、常用工具与习惯，积累成对用户的了解层；静默了解不是窗口监控的扩展，窗口与截图只是线索之一，决策时以「要更了解这个人，还缺什么」为准。

`observation`持有独立派生文件`behavior/understanding.json`：观察摘要**不直接进入**长期事实；只有经 dreaming 派生区（`origin=derived_behavior`，与画像结论同区）确定性沉淀的条目进记忆库（Review 不演绎、文本逐字采用，有界窗口见「稳定结论沉淀」）；原始 `understanding.json` 仍不进 FTS/记忆导出。档位非「关」时按固定钟点表（低 12/20、中 10/14/18/22、高 9/11/13/15/17/19；钟点起 15 分钟追赶窗）到点即跑，不再要求系统空闲、不再排除主回合在飞；来源新鲜与桌宠前台排除仍保留（两批至少间隔 2 小时 / 30 分钟 / 15 分钟；钟点表本身避开 23–9）；一批链路：截图（不可用或锁屏时回退最后一次窗口快照；锁屏批不请求截图）→ 决策调用（辅助模型只输出 `{targets:[{path,kind,why}]}` 候选，绝对路径、数量不设硬上限；输入在窗口快照（锁屏时为最后一次、注明可能陈旧）与最近 8 条已知了解之外补齐五块只读有界摘要，用于挑「还缺什么」：本地时间（可读时刻含星期 + IANA 时区）、Card 人设（名字/描述/角色设定按 60/160/240 字符截断、空白折叠）、画像质量与就近 6 个钟点活跃分钟（近 7 日聚合）、话题 top-5 占比（与选材同一读取口径），以及长期记忆核心画像（空 query 走召回端口 core 路径、token 256、条数 ≤3 且单条 ≤400 字符、显式跳过重排，身份取运行时活跃会话与激活 Card）；各块缺省或不可靠时如实降级——无激活 Card 为 null、画像不可靠原样带质量状态、话题为空数组、无活跃会话或 `ai.memory.enabled` 总闸关闭时不发起召回、召回失败按空——降级不使批次失败、决策照常发出；决策输入整段计入 aux 共享 token 预留，输出契约与解析/跳过规则不变）→ 宿主逐项校验读取 → 整理调用把读到的目录/文件内容与截图一并整理成「关于这位用户的了解」（只写看得到的事，不做身份/人格/情绪推断，也不写成长期事实）。可读范围是整机（2026-10-06 用户裁决）：除凭据/密钥路径与应用数据根外都可读取——不再限于用户主目录，也不再排除 home 系统目录；**读取的数值上限已删除**（2026-10-05 用户口径：单文件 32KB、目录 40 条、单批 ≤3 目标、目录扫描预算 256 均不再设）——目录全量回条目名（仍跳隐藏项与凭据类名）、文件整读，读什么、读多少由模型裁断；宿主终裁只保留路径边界（绝对路径、canonical 解析、数据根之外、凭据路径），非普通文件与非 UTF-8 目标按既有 skipped 回执。风险如实：大目录或大文件没有硬顶，靠模型裁断。决策解析失败、字段非法或路径非绝对时本批不做文件读取，只保留截图（锁屏批没有截图，只保留最后一次窗口快照）。每小时读取名额是防突发闸（随档位 4/8/12，`silentTierLimits(tier).maxReadsPerHour`，用 understanding.json 里的滚动时间戳持久记账，超限的本批跳过决策与读取）；喂给整理调用的单文件字符预算（`MAX_TEXT_CHARS_PER_FILE`）是请求上下文的 token 截断——两者都不属于已删除的「读取数值上限」，是刻意保留。截图与文件原文不落盘，辅助模型tools=[]；400输出tokens，决策与整理共用同一条模型通道与共享 token 池，一批计一次 attempt，最短批次间隔跨重启持久，每日最多 2/4/6 轮（=钟点表轮数）。了解记录带 `targets` 审计字段（本批读取的路径，有界截断），可回看 AI 读了什么；TTL7日。

可信、已提交用户原话按参与来源入队，辅助模型分批提取主题标签与权重；正文只在RAM请求中使用，持久只留标签、权重、哈希来源、时间与Card范围。单批以 `TOPIC_BATCH_TOKEN_CEILING`（24000，observation 模块自持的请求上下文资源边界）按完整可负担来源缩小批次，防长来源永久卡住队首；话题链不受三处频率档位治理。至少两个独立参与来源后才向主动选材提供主题占比；保留90日／512条上限，单次提及不当作稳定偏好。清除水位与失效来源阻止旧正文被回扫晋升；遗忘记忆的源条目与删除会话会撤销关联主题资格。

停止、前台抢占、会话／Card或来源变化会取消旧代际；预算返回与请求前再次核对来源，原生CANCELLED终止整批；结果返回后再次核对许可与来源。主窗口/e2e是唯一写入owner，设置窗口治理只发送来源ID并等待回执。`/behavior clear`先撤销主动资格、等待采集与写队列结束，再清了解与画像；已清的来源不能迟到回灌。

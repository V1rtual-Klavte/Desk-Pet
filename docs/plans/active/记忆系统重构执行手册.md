# 记忆系统重构执行手册

这是一份可以从任意新会话继续执行的工作手册。设计原则和协议细节以[记忆系统重构前置准备](./记忆系统重构前置准备.md)为准；本手册只回答“下一步改什么、怎么验证、何时算完成”。

## 0. 新会话启动方式

每次接力先执行下面的固定动作：

```bash
cd /Users/v1rtual/WEB/someworks/Desk-Pet
git status --short
cat docs/plans/active/记忆系统重构执行手册.md
cat docs/plans/active/记忆系统重构前置准备.md
```

然后读取本文件的“当前检查点”，只处理 `next_action` 指定的工作。必须先向用户说明思路、影响文件和验证方式，得到同意后才开始编码；本次创建执行手册的同意不等于后续代码修改的同意。

执行过程中遵守以下规则：

- 先读后写，先用 `rg` 找全消费者；不凭文档或旧测试结果推断当前代码已经实现。
- 不清理、覆盖或提交用户已有的未提交改动；不主动修改真实配置、`.gitignore`或运行时数据。
- 每个阶段都按“源码分析 → 最小实现 → Contract/Scene 更新 → 类型/编译检查 → Live Test → 文档检查点”推进。
- 代码或契约改变后，旧的 `sourceHash` 和旧测试结论作废；必须重新生成或重新分析受影响 Contract。
- 所有主动消息、hook、恢复消息、子代理消息都必须带来源和污染级别，不能伪装成用户输入或长期记忆来源。

## 1. 当前状态（2026-09-14）

- 前置方案仍是 `proposed`；本手册是执行入口，不代表任何待实施能力已接通。
- 当前代码仍有全局 `isAIGenerating` 忙碌锁、每轮新建 Pi `Agent`、只有 user/assistant 的会话记录、扁平 `buildPrompt()`、无持久化 Plan checkpoint、信任集合早退和非原子通用文件写入等基础限制。
- 长期记忆自动提取、Prompt 自动召回、画像安全写入和 dreaming 都不能作为已完成能力对外宣称。
- 首个目标是 P0：建立不改变用户可见行为的运行时基础协议和观测面。

## 2. 阶段总览与门禁

| 阶段 | 目标 | 主要落点 | 阶段通过条件 |
|---|---|---|---|
| P0 | 类型、事件、快照、trace 和 fake provider 基础 | `src/services/engine/`、`src/services/agent/memory/`、`src/services/__tests__/live/` | 兼容旧会话；快照可审计；fake provider 场景稳定 |
| P1 | Ingress、SessionTurnStore、来源和原子持久化 | `agent/runner.ts`、`engine/preprocessor.ts`、memory/session store、必要的 Rust 专用命令 | queued → done 可恢复；重复 request 不重复落盘 |
| P2 | AgentSlot、队列、steer/follow-up、Plan 恢复 | `engine/pi/runtime.ts`、`engine/planner.ts`、session 事件 | 忙碌时输入有回执；旧 generation 不结束新 run |
| P3 | ContextKernel、PromptSnapshot、画像投影、空 MemoryProvider | `context/builder.ts`、新 runtime/context 模块 | block 顺序、预算、来源和最终 payload 可验证 |
| P4 | tool pair 安全压缩、spill、版本化摘要 | `engine/compactor.ts`、`tool/router.ts`、session files | 不切断 tool pair；摘要失败保留原 round |
| P5 | HookBus、安全 deny-first、工具审计、网络/沙箱门禁 | `safety/`、`tool/`、Pi hooks、Rust commands | 安全拒绝先于执行；超时/取消/错误可审计 |
| P6 | MemoryKernel、长期事实、画像写入、dreaming 和评测 | `agent/memory/`、eval/contracts/scenes | 仅可信来源可 deep write；通过多轮稳定性门禁 |

## 3. P0：可直接执行的首个工作包

### P0-01 建立运行时基础类型

- 新建带 barrel 的零依赖类型模块（建议 `src/services/engine/runtime/`），定义 `MessageOrigin`、`MessageMeta`、`IngressEnvelope`、`SessionEvent`、`SessionTurnRecord`、`PromptSnapshot`、`QueueEntry`、`QueueAck`、`PlanRecord`、`PlanStepRecord`。
- 事件 kind 至少覆盖 `turn_created`、`turn_state`、`user_message`、`assistant_message`、`tool_call`、`tool_result`、`active_message`、`hook_message`、`prompt_snapshot`、`compaction`、`recovery`、`error`。
- 所有协议对象带 `schemaVersion`、稳定 ID、时间戳、`requestId`/`idempotencyKey` 和来源字段。

验收：外部模块只从 barrel 导入；类型不引入业务循环；旧 `SessionMemory` 仍可编译。

### P0-02 固化会话事件兼容协议

- 在 `src/services/agent/memory/` 内增加事件序列化/解析适配，不立即替换现有读写入口。
- 保留可读 Markdown 预览和 HTML comment 完整 JSON；缺失新字段的旧记录填充 `schemaVersion=0`、`origin=user/assistant`、`eligibleForMemory` 默认值。
- 为重复 `eventId`/`idempotencyKey` 定义幂等行为；解析失败保留原文并返回结构化错误，不静默丢消息。

验收：旧会话文件可读、新事件可 round-trip、损坏单条记录不会清空整段会话。

### P0-03 加入 PromptSnapshot 和脱敏 hash

- 新建快照构造器/序列化器，记录 system blocks、tool schema hash、agent/LLM message hash、transform 链、估算/实际 token、cache 和 redaction 列表。
- 原始 provider payload 默认不落盘；日志和测试只使用脱敏结构或 hash。
- 明确 `estimatedInputTokens` 与 Provider `usage` 的区别，禁止用估算值冒充实际 usage。

验收：同一输入产生稳定 hash；密钥、Cookie、授权头和原始 payload 不出现在 session 文件或测试报告。

### P0-04 接入只读 Pi 观测钩子

- 在 `src/services/engine/pi/runtime.ts` 接入 `subscribe`、`onPayload`、`onResponse` 或等价适配，只记录事件和快照，不改变 prompt、工具顺序和终止语义。
- 每个 listener 有超时、错误分类和脱敏边界；观测失败不得阻塞正常回复。
- active/hook/recovery 文本先保留来源元数据，禁止用 `prompt(string)` 伪装成 user message。

验收：fake provider 能观察到 request、payload、response、tool 和最终 turn 事件；普通聊天输出与改动前一致。

### P0-05 建立 Fake Provider 和最小场景

在 `src/services/__tests__/live/` 现有 Contract/Scene 结构内增加可重复 fake provider，不依赖外部 API。至少覆盖：

- `memory-prompt-snapshot`：检查 block 顺序、来源、hash 和 usage 字段。
- `memory-old-session-compat`：旧预览、旧 JSON、损坏单条记录的读取结果。
- `memory-active-origin`：主动搭话不产生 `origin=active` 的 `role=user` 事实事件。
- `memory-tool-pair-baseline`：工具调用和结果成对观测，为 P4 建立基线。

每个场景使用稳定 `caseId`，并在对应 Contract 的 `scenarios` 中登记；更新受影响 Contract 的 `sourceHash`。

### P0-06 P0 验证和检查点

```bash
pnpm run test:types
pnpm test -- --module memory --strict
pnpm test -- --module agent-runtime --strict
```

如果只新增静态类型而没有对应 Live 场景，P0 不算通过。运行结果需要记录到本文件的“当前检查点”，包括命令、时间、trial 数、失败分类和报告路径。

P0 完成后再单独提交代码；没有用户明确要求时不要替用户提交 Git commit。

## 4. P1–P6 执行清单

### P1：Ingress 与 SessionTurnStore

- 将 `preprocessor` 的模块级 `lastUserText/lastUserTime` 降为请求级字段；输入保留 raw/normalized text、querySource、priority、taint。
- 先持久化 `queued`，再更新 UI 和调用 Pi；实现单会话写锁、事件幂等、版本/CAS、临时文件 + rename 原子提交。
- 启动时扫描 `dispatching/running/waiting_tool`，转为 `interrupted` 或 `unknown_side_effect` 并写 recovery event。
- active 入口显式写 `origin=active`、`querySource=active_monitor`、`eligibleForMemory=false`。

门禁：重启后 queued turn 可恢复；重复 request 只有一份事实事件；通用 `file_write` 语义不被悄悄改变，如需原子写则新增专用 session 命令并注册到 `lib.rs`。

### P2：AgentSlot、队列与 Plan

- 按 `sessionId` 管理驻留 Agent，移除全局忙碌锁作为事实来源。
- 实现 `persisted → reserved → dispatched → accepted` 回执和 `now > next > later` 优先级；steer/follow-up 必须先落盘再调用 Pi。
- 每个异步 drain 带 generation；旧 generation 不能结束新 run。
- Plan/step、子 agent、工具开始/结束写 checkpoint；外部副作用无完成凭证时标记 `unknown_side_effect`，不自动重试。

门禁：忙碌时输入不丢失且有 queued/steered/followup/deferred/failed 回执；恢复后不重复执行未知副作用。

### P3：ContextKernel 与 PromptSnapshot

- 将 `buildPrompt()` 内部改为固定层级 block：`static → dynamic → profile → memory → transcript → ephemeral`，保留兼容入口。
- User.md/画像只作为 projection；长期记忆先接空 `MemoryProvider`，不宣称已自动召回。
- 在 `transformContext` 后及最终 Provider payload 处各捕获一次快照，最终 payload 以 `onPayload` 为准。
- prompt rewrite 只产生派生字段，保存 input/output hash、reason、derivedFrom，不覆盖用户原文。

门禁：预算不足有明确裁剪原因；active/hook/recovery 只进入 ephemeral 或 UI-only；快照可按 request/turn/run 完整追踪。

### P4：压缩与工具输出 spill

- L0 清理 UI-only/重复块并将超长 tool output spill 到受限文件；L1 按完整 API round 摘要；L2 只删除最旧完整 round。
- tool call/result 必须成组；摘要失败保留原 round，不伪造孤立 `role=tool` 摘要。
- compaction event 带 coveredEventIds、input/output hash、generation 和版本；旧任务不能覆盖新 snapshot。

门禁：压缩前后 tool pair、最近用户/助手、Plan checkpoint 和安全上下文完整；spill 文件路径经过 Rust 校验且不泄露敏感内容。

### P5：Hook、安全、工具和错误

- 建立 Desk-Pet HookBus，区分 blocking 与 bounded async；每个 hook 有 hookId、deadline、错误分类、重入保护和 taint 继承。
- 安全顺序固定为 deny-first：来源/作用域 → 静态规则 → 动态策略 → 用户确认 → 工具执行；不能先命中 session trust 就放行。
- ToolRouter 记录 opId、schema/policy hash、超时、AbortSignal、结果截断和 spill；网络工具统一走 allowlist、DNS/IP 防护、请求超时和响应上限。
- 取消、窗口关闭、安全拒绝、超时和 shutdown 都写结构化 turn/tool 状态；持久化错误文本使用脱敏摘要。

门禁：禁止调用在执行前可观察；任何 hook/工具异常都有稳定 error code；Rust 命令返回 `AppResult<T>` 并完成 `invoke_handler!` 注册。

### P6：MemoryKernel、画像和 dreaming

- 召回与提取分离；提取只读取 `eligibleForMemory=true` 且 `taint=trusted_user` 的 user 事件。
- 以 `MemoryCandidate`/`ProfileMemoryCandidate` 表示候选，保存来源事件、策略 hash、置信度、状态和冲突关系；模型不能直接覆盖 User.md/MEMORY.md。
- dreaming 分 Light/REM/Deep，具备 lease、dreamId、输入/输出版本、幂等键、preimage 和失败重试。
- deep write 前必须通过敏感字段、冲突、过期、来源和用户可追溯性门禁；active、hook、recovery、system、subagent 默认不得写入长期事实。

门禁：长期事实写入可回滚、可解释、可按来源删除；多轮真实 trial 的 `pass@k`/`pass^k` 达到发布要求，未通过时保持候选态。

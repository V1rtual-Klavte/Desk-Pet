# 记忆系统运行时契约：P6 目标

运行时前置已实现，当前事实见[当前运行时契约](../../current/runtime-contract.md)。本文保留尚未实施的长期记忆目标；候选写入、存储和评测要求不代表当前能力。原论证保存在[历史总方案](../../history/design/轻量陪伴运行时与统一内核建设方案-2026-09-17基线.md#9-memorykernel本地结构化记忆)和[历史协议](../../history/implementation/记忆系统运行时契约-2026-09-17基线.md)。

## 已有前提与端口

会话事件、来源/taint、压缩 checkpoint、权限和 PromptSnapshot 已提供运行时边界。[MemoryProvider](../../../src/services/agent/memory/provider.ts) 是现有只读端口，默认空实现，具有召回时限和预算；写入、纠正、遗忘不塞进这个端口。

Recall 继续输出现有 MemoryProjection 的 sourceId、memoryVersion、provenance、taint、text、tokenBudget。旧草案的 sourceIds/blocks 形态不是当前接口；若确需更改，先统一协议与全部消费者，不另建第二份同名类型。User.md 当前仍是只读 profile projection。

## 存储、检索与迁移

- **事实存储**：Rust 管理本地 SQLite MemoryStore。memory_item 保存内容、kind/scope/status、重要性/置信度、观测/有效/过期时间、替代关系与 version；memory_source 保存 session/event、origin/taint 与 hash。schema、迁移、路径和备份统一管理。
- **派生索引**：全文索引可重建；中文需确定分词或 n-gram 策略、持久化规则版本并测试短查询。FTS5 本身不保证中文召回质量，关系图和向量在评测证明需要后增加。
- **读取顺序**：先过滤用户/Profile/Card/session scope、状态与来源，再检索排序、去重和 token 裁剪。检索失败/超时退化为空，不阻断普通回复；回合取消停止相关工作。候选未接受前不进入 Prompt。
- **迁移顺序**：只读盘点 → 用户可检查的预览 → 备份 → staging DB 导入 → 数量/来源/hash 校验 → 单一 reader 切换；失败回旧 reader，不设隐式双写同步。
- **Markdown 边界**：人工指令、Card 和会话继续保留；迁移后的 MEMORY/User 是导出或只读投影，人工修改通过显式导入。本文不授权迁移真实数据。

## 候选与写入资格

原草案中的字段按职责保留为实施要求，具体 TS/SQL 类型在实现时与现有运行时协议对齐：

| 对象 | 必须表达的数据 |
|---|---|
| MemoryCandidate | candidateId、sourceEventIds、fact/preference/goal/profile_change 类型、confidence、provenance、taint、candidate/accepted/rejected/superseded 状态 |
| ProfileMemoryCandidate | candidateId、sourceEventIds、target、patch、confidence、policyHash、状态；target 表示画像/注册表视图，迁移后提交到 MemoryStore |
| 事实提交记录 | 版本、来源、前镜像/替代关系、门禁结果与可撤销信息 |

提取与 recall 分离。默认只有 eligibleForMemory=true 且 taint=trusted_user 的 user event 能产生候选；active、hook、recovery、system、subagent、工具结果和已召回 memory 排除。摘要只能帮助定位来源，不能洗掉 taint、凭空生成用户事实或授权。

写链路为：用户/助手回合持久化完成 → 过滤 eligible source → eventId 幂等的有界候选队列 → 规则去重/来源/敏感/冲突检查 → 必要时低预算模型提取 → 事务提交或待确认 → 索引失效/重建。模型不能直接覆写 User.md、MEMORY.md 或 Card。

轻量模式先完成明确的“记住/纠正/忘记”，再评测普通聊天自动提取。明确陈述与模型推测分开，推测不自动成为事实；不是每句闲聊都需要永久保存。

## 纠正、遗忘与陪伴语义

更正用 supersedes/有效区间解除矛盾 active 条目。遗忘覆盖事实、索引、缓存及自动回灌来源，避免下一轮从旧会话重新提取；同时解释会话原文和备份的独立删除范围。为可撤销操作保留的历史与彻底删除请求需分别定义，不能以审计为由无限保留待忘内容。

优先支持称呼、表达偏好、持续话题、明确期待和共同经历，区分稳定偏好、短期情绪与时效事项。Card 关系进展默认隔离，用户基础偏好是否共享由 scope 决定。用户能查看记住了什么、来源和更正时间，并能编辑或忘记。

## Dreaming 与验收

后台整理有界、可恢复、低优先级，不抢占首答：Light 整理候选和来源；REM 检查冲突/过期/敏感字段并产出报告；Deep 只原子提交通过 gate 的候选，保存来源、版本与结果。不得作为每轮隐式副作用重新接回主回复。

最小验收集合：

- 候选接受/拒绝、幂等重复写、冲突更正、过期、遗忘防回灌；来源、状态和版本可追溯。
- 中文短查询、无相关记忆、scope 隔离、预算与污染隔离；确定性 fake 场景和真实模型质量评测分开。
- active-origin、profile rewrite、PromptSnapshot hash、压缩恢复与 deep-write gate；改写保留 input/output hash、原因及 derivedFrom，不改变用户原意。
- crash_before_flush、crash_after_tool、timeout、compaction_error 等故障注入，以及迁移失败回退。
- 冷启动、空闲内存/CPU、首答延迟、每轮 token、检索/整理耗时的基线对比；没有测量不承诺固定 MB/ms。

P6 不重建已有 Context/权限/队列内核。具体实施顺序与已有验证证据见[未完成工作与已知缺口](未完成工作与已知缺口.md)。

## 0. 交付目标与现状

**目标：JSONL 保留完整会话证据；Rust SQLite 保存经过来源与版本治理的记忆；小画像、事实偏好、经历与短期事项分层；本地无向量检索，按需 LLM 重排；dreaming 增量生成带证据的 staging 提案，复核后自动事务提交。**

“一次性弄完”指同一轮实施交付完整 B，包括存储、运行时、用户入口、整理发布、测试和文档。工作包只是依赖顺序，不是先上线 A、把 B 留给以后；过程中不保留 Markdown/SQLite 双主路径，不以空接口或只通过编译结束。

## 1. 关键决定

| 问题 | 本方案选择 |
|---|---|
| 权威 | JSONL 是会话正文权威；SQLite 是已接受记忆与治理决定权威；FTS/Markdown 是可重建投影 |
| 所有权 | Rust 管库、事务、版本、作业租约与路径；TS 复用 SessionRepo、模型网关与 Runtime |
| 发布 | 单库候选隔离，作业完成后复核并单事务自动提交；日常整理不替换整个 DB 文件 |
| 在线成本 | 本地检索可独立工作；adaptive 仅在多个相关候选需要取舍时重排 |
| 写入 | 可信用户来源的显式操作与 dreaming 产物直接提交；来源、版本、墓碑和幂等是治理边界 |
| 调度 | 出厂 manual，可显式开启 idle；两种触发方式都在作业完成时自动提交 |
| 画像 | 少量用户确认并置顶的事实；importance 高不自动升级为画像 |
| 指令 | 记忆是 derived 数据，不升级为系统指令；V1RTUAL/Card/权限独立 |
| Markdown | 在 memory/exports 显式导出；运行时不把旧 MEMORY/User 当记忆来源 |
| 遗忘 | 与会话原文/外部备份删除分开，不承诺模型已完全不知道当前对话中的内容 |

参考机制：[Engram](https://github.com/Gentleman-Programming/engram/blob/main/docs/ARCHITECTURE.md)的渐进取全文和主题键；[OpenClaw](https://docs.openclaw.ai/concepts/dreaming)的来源门控、操作提案和宿主校验；Hermes 的有界画像与后台 review；Claude Code 的增量游标与整理锁；[Letta MemFS](https://github.com/letta-ai/letta-docs-md/blob/main/concepts/memfs/index.md)的常驻/按需分层。不移植完整 Agent、直接改记忆文件或 agent 来源提升规则。

## 2. 语义分层与 scope

| 层 | 内容 | 默认读取 | 生命周期 |
|---|---|---|---|
| 核心画像 | 称呼、表达偏好、用户选定的重要事实 | 每个普通用户回合优先选，小预算 | 来源有效且未撤销；不因年龄自动降低真实性 |
| 事实/偏好 | 用户自述的稳定事实、兴趣、长期目标 | 主题、别名、关键词 | 可纠正、替代 |
| 经历 | 用户讲述的经历、持续话题及原文锚点 | 相关时召回，保留时间 | 不从一次经历推导永久性格 |
| 短期事项 | 有期限的安排、短期状态 | 相关且有效时召回 | 到期退出默认召回；不自动变成提醒任务 |
| 原始会话 | 完整 JSONL 事件 | 原文追溯或明确历史查询 | 会话模块管理，不整库进入 FTS |

`kind = fact | preference | episode | working`；核心画像是已接受条目的 `pinned` 属性，不复制画像事实表。`subject = user | third_party | unknown`；自动提取默认只产生 user 主体自述的候选，第三方、引用、假设或主体不明作为拒绝/待澄清报告项。

scope 为 `user | card | session`：当前单用户以数据根为 owner 边界；基础偏好默认 user，特定 Card 经历可选 card，当前会话临时信息可选 session。**外观 Profile 切换不改变记忆归属**，Card 变量不复制进记忆库。

准入前将当次冻结 Card 身份随现有输入来源协议落盘，不能事后从当前 UI 推测。已有事件缺 Card 身份时只可作 user 范围待审证据；缺 eligible/taint 不自动提取。查询先过滤 scope；跨 scope 不隐式 supersede，有冲突的确定事实不同时注入，需明确解决或标注待澄清。

## 3. 存储与数据协议

### 3.1 落盘与进程模型

数据库固定为 `AppPaths.memory` 下的 `memory.sqlite3`，命令不接受任意数据库路径。采用 `rusqlite` + bundled；W0 用 Context7/安装源码核对版本和 FTS5 支持，精确锁入根 Cargo.lock，不依赖系统 sqlite3 CLI。

Rust 单一写入所有者；阻塞 SQL 在有界工作线程运行，不持锁等待模型、用户确认或网络。设置窗口只有查询和操作客户端，不维护独立业务 Store。启用 foreign_keys、WAL、有限 busy timeout 与可靠提交配置，并在双平台实测。启动只初始化/校验 schema，不全量扫描历史、不发 memory LLM 请求。

导出在 `memory/exports/`，带 revision/时间/只读说明。V1RTUAL.md 保持人工指令职责。旧 MEMORY/User/Outside/Project 文件不自动导入、覆盖、删除，也不作为 fallback。

### 3.2 表与约束

| 表 | 必须表达的字段/用途 | 约束 |
|---|---|---|
| memory_meta | schema_version、store_revision、forget_epoch、index_version | 版本单调；不支持的库格式明确报错，不静默建空库 |
| memory_item | row_id、id/version、content/summary、kind/subject、scope_kind/scope_id、topic_key/aliases、pinned、importance/confidence、status、observed_at、valid_from/valid_to、expires_at、supersedes_id/version | row_id 为索引地址；id/version 唯一，一个 id 一个当前版本；区间合法、替代不跨 scope/不成环 |
| memory_source | source_id、session_id、entry_id、event_id、seq、origin/taint/eligible、content_hash、证据片段位置、观察时间与冻结范围 | 同事件幂等，来源资格不能由 LLM 参数赋值；不保存整份会话副本 |
| memory_item_source | item_id/version ↔ source_id；可选 governing_operation_id | 唯一外键关系；合并事实保留全部来源，人工更正通过治理决定解释 |
| memory_candidate | id/run_id、source_ids、proposal、base_revision、payload_hash、状态、风险/冲突、作业决定 | `prepared` 不进召回/FTS；来源+规范化提案指纹幂等；提交前复核失败即不进 active |
| memory_change | operation_id、actor/action、目标版本、候选/决定引用、前后 hash、revision、at | 操作幂等；人工编辑也记录；遗忘可清除涉及的正文，不借审计永久保留 |
| memory_suppression | 稳定 session_id+event_id/entry_id、source_hash、scope/可选 topic、截止 seq、effect、目标 item/version、reason、forget_epoch、at | 不依赖可重建的 source_id；effect 区分 block_extraction / revoke_items / reject_proposal，按阶段检查 |
| memory_job | id、phase/status、owner/lease、输入 manifest、base_revision/forget_epoch、policy/prompt/model 标识、进度、usage、错误 | 固定输入、单 owner；过期回包拒绝；部分产出和进度事务推进 |
| memory_watermark | session_id、已扫描 seq、规则版本、最近成功扫描状态 | 按会话推进；mtime/物理行号不能作为处理证据 |
| memory_fts | 当前可召回版本的 content、summary、aliases 文本 | 来源 JSON、工具输出、候选与报告不索引 |

纯关联字段可规范化成关联表，但不能省略约束。`status = active | superseded | expired`，候选状态另为 `prepared | accepted | rejected | stale`。遗忘删除正文及派生副本，只保留最小抑制/操作元数据，不能保留全文并改成 forgotten 来冒充删除。

summary/aliases 是派生检索信息，不是新事实；confidence 不是校准后的真实性；importance/召回频率不能绕过来源、时间和 scope。

人工更正必须保留“原始会话来源 + human_governance 决定”：新版本仍关联原始 source，另关联 memory_change.operation_id；原话只证明更正前的出处，新内容的依据是用户编辑决定，UI 分别展示，不能把原话当作新内容的直接支持。本轮 UI 新增记忆必须从一条可信用户消息选择，不提供无来源的自由文本新增；编辑已有条目不要求伪造一条聊天消息。原来源已被删除/遗忘的条目不能靠编辑复活，需新的可信输入。

### 3.3 事务与一致性

- 发布事务一起写 item/version、source 关联、change、candidate 状态、FTS 和 revision；失败全回滚。
- operation_id 由宿主生成。提交结果未知时先查该 ID，不盲重放。
- 模型和评审期间不持锁；提交检查 base_revision、目标版本、payload_hash、forget_epoch，不一致返回 conflict/stale，重算并复审。
- 仅 JSONL 不能重建人工编辑、自动提交和遗忘；备份必须包含 SQLite 治理记录。
- JSONL/SQLite 不伪装成一个事务：已提交事件幂等收集，崩溃通过水位补齐；主回复不等待提取模型。
- 导出在提交后生成，失败只报告导出失败，不回滚已接受记忆；导出不得反向覆盖 DB。
- 所有 change/publish/restore 由 Rust writer 串行化；job 使用执行租约，交互写使用绑定窗口/会话/代际的 operation 状态。进入写事务前最后检查取消与 owner，标记 committing 后以事务结果为准，不再返回“已取消且未修改”。若 UI 取消与提交交错，按 operation_id 查询 committed/failed；事务回滚前不释放操作所有权。

## 4. 来源收集与水位

由 `agent/memory/sources.ts` 经 session 公开 barrel 读取已提交 Entry，复用句柄与 Pi 解析。覆盖普通发送、实际消费的 steer/followUp、恢复后的真实用户输入；未消费/已撤回 inbox 不提取。

自动候选同时要求 user 消息、有 deskpetEventId、origin=user、eligibleForMemory=true、taint=trusted_user、未被抑制。assistant/tool/compaction/active/hook/recovery/subagent/已召回记忆全部排除。资格通过后仍检查主体、引用、假设、否定和时间；“我朋友喜欢咖啡”“翻译：我叫小明”不能进入画像。

宿主先从 SessionRepo 注册有界来源 manifest，再把不透明 source_id 给模型。模型输出引用与证据位置；宿主核对位置/内容。Rust 核对已登记来源、hash、scope、运行 owner 和遗忘状态，拒绝未登记来源。提交前宿主重新读源核对 hash，消失/变化则拒绝。

**Rust 不另写 Pi parser，也不声称独立验证了 JSONL；受信边界是应用宿主，模型不能调用来源登记 IPC 或自行声明 trusted。** UI 对已有记忆的编辑是明确的人工作用，记录 human actor 和治理决定，不能伪装为旧会话原话；这不放宽自动候选资格。

Light 为每个会话冻结最高已提交 seq，固定 entryId/eventId/hash manifest；后续追加留给下一批。来源登记与扫描水位同事务；Review 进度另记在 job，模型失败不把未成功产出候选的批次标为完成。只保存有界证据片段和引用，不复制整个会话。

重启只读未完成作业状态、标记 interrupted；manual 等用户继续，idle 重新满足条件才续跑，不因启动马上发模型请求。

**必要前置提案：** 当前 SessionRepo 经 file_read 受 5 MiB 整文件上限影响，不能把超限会话一律跳过后宣称完整 B。本方案将解除“宿主会话读取借用通用工具 5 MiB 门”纳入 W1：新增只读、仅限 sessions 域的宿主命令 `session_read_text`（域内相对路径、可选 maxLines），由 SessionRepo 专用 FileSystem 适配调用；maxLines 由 Rust 按行有界读取，open 所需完整正文继续交给 Pi 原有 parser。通用模型 file_read 的 5 MiB 限制不变；不改 JSONL 格式，也不声称 Pi 已变成流式/增量重放。

至少用超过 5 MiB 的真实 JSONL 验证列表、打开和来源提取；一次仅处理一个历史会话并及时释放，单独测峰值内存。权限、损坏或资源不足仍可造成特定会话失败：必须列出范围且不推进水位，不报全量完成。W0 需确认这项前置进入实施范围；若不接受，应修改交付范围后重新评审，不能实施中静默省略。

## 5. 分层召回与 Prompt

### 5.1 唯一端口

Runtime 的核心画像和动态记忆都通过 MemoryProvider.recall 获取，不再另读 User.md。管理 UI 可查管理接口，但结果不能旁路塞入 Prompt；模型主动查记忆也走同一 MemoryProvider 查询链。

在现有 MemoryRecallRequest 中补冻结 scope、runGeneration 和外部 AbortSignal，保留 requestId/sessionId/query/tokenBudget；外层组合回合取消与 1.5 秒时限。MemoryProjection 保留 sourceId/memoryVersion/provenance/taint/text/tokenBudget，新增 `tier: core | recall`，一次更新全部消费者/测试/快照，不保留两套类型。

sourceId 指向 item/version，memoryVersion 带读取 revision，provenance 可回查；taint=derived，不能因原始来源 trusted_user 就提升为 system。

### 5.2 查询顺序

1. 同一 DB revision 下先过滤 scope、active、有效时间、来源与遗忘；核心画像按 pinned 读取。
2. 本地有界规范化 query，合并 FTS、topic/alias 精确或前缀、短中文 LIKE；去重后最多 50 条。
3. 无命中时不无条件填充高 importance 事实。无词汇锚点的语义改写依靠已有主题/别名补充，漏召回边界通过质量集量化。
4. 相关性优先，importance/时间作次级调整，同分按稳定 ID；持久偏好不因年龄被判假。历史查询必须显式选择，superseded 不进普通 recall。
5. 先完成本地候选/排序作为 fallback。adaptive 在相关候选超过最终上限（初值 6 条）时重排；核心画像、零命中、小集合不发额外请求，不新增 LLM 来判断是否重排。
6. 最多给模型 12 项，按总 token 再缩减；只含 id、主体/类型、scope、保留否定和时间的一行摘要以及当前 query。不发送完整长正文、原始会话或来源 JSON。
7. 模型只返回有序 ID 子集，允许空。校验 JSON、ID 白名单、去重与条数；无效则本地回退，不补造 ID、不让重排改正文。
8. 按 ID 取全文时检查 revision；变化则重做本地资格过滤，不再追加一次重排。按预算取完整条目，优先丢低优先条目，不把否定/条件裁没。

FTS5 trigram 的 MATCH 不匹配少于三个 Unicode 字符；首版在已过滤 scope 的记忆表上增加转义、参数化的短词 LIKE 补救，实测其规模代价。候选检索失败不能靠重排救回。FTS 版本化、可重建；更换分词器必须重建 index_version。[SQLite 官方说明](https://www.sqlite.org/fts5.html#the_trigram_tokenizer)

期限在每次查询时过滤，不能依赖 dreaming 已经把 status 改成 expired；随后本地维护可清理过期 FTS 行。SQLite BM25 分值不直接与 importance/时间原值相加：各候选通道先形成稳定排序，再作归一化合并，权重在领域策略单点定义并用独立标注验证。

### 5.3 时限和预算初值

| 项 | 提案值 | 所有者 |
|---|---|---|
| 总 recall | memoryConfig.recallTimeoutMs，生产模板4000 ms | provider wrapper |
| 重排截止 | 剩余时间减 200 ms，单次最多 900 ms；不足 300 ms 跳过 | recall 编排 |
| 画像/动态预算 | 320 / 800 tokens，动态默认最多 6 条 | config getter / 领域策略 |
| 本地/模型候选上限 | 50 / 12 | 领域常量 |
| 重排摘要/输出预算 | 1200 / 128 tokens | 领域常量与模型网关 |
| 查询缓存 | 首版不缓存查询结果，只冻结当前小投影 | 避免第二条失效链 |

这些是待验证初值，不是实测承诺。completePiText(purpose=memory) 复用冻结模型、认证、取消，不叠加重试；另记 rerank/extract 子项，归 memory 总账，不污染主回复统计。缺 usage 记未知/估算，不记成零成本。

320/800 是主请求注入上限；1200/128 是重排请求输入摘要/输出上限，属两个账本，报告不得相互抵扣。估算、scope 或投影校验失败时放弃该记忆块并留诊断，不按0 tokens放行。总窗口硬上限优先，空间不足时 core 也可整条淘汰，不保证每次能注入满320 tokens。

聊天重排审计绑定原 session/request/run；跨会话 dreaming 绑定 memory_job，不随便落入当前聊天。扩展网关审计目标为 session 或 memory_job 两种，复用同一 hash/usage 采集，job 侧保存非正文快照；不新建模型调用器、不把后台提示写进用户 transcript。

DB 失败降级空记忆并审计；重排失败保留本地结果。外层总超时只是最后兜底，内部必须提前回退。迟到响应不更新投影、不继续模型调用。

### 5.4 注入、预算与同回合变更

“核心画像常驻”表示每回合优先携带，不表示系统指令。本方案 core/recall 都作为带来源的尾随瞬时记忆数据块，system prompt 只保留稳定使用规则。

createRequestViewHook 顺序：先准备现有视图及工具投影 → 计量不含记忆的真实用量 → 计算 `max(0, normalInputTarget - usedWithoutMemory)` → 按 core/recall 各自上限逐条追加 → 同口径核对硬上限和采集快照。空间不足只丢可选记忆并记录 budgetDrops，不能为记忆额外压缩/丢弃未覆盖正文。

记忆块不写会话正文、不进压缩素材/下一轮候选；PromptSnapshot 只留 hash、item/version 与来源审计信息。同步 payload/usage 快照、token 分类和统计消费者，不能只改拼接。

同回合写工具成功递增 revision，下一 Provider 请求前刷新核心/本地召回，不重复重排。UI 在运行中忘记时让旧投影失效，并取消涉及旧投影的在飞运行、等待收口后报告应用完成；已发出的网络输入无法收回，不宣称远端已撤销。提交后不因回合取消回滚。

## 6. 记住、纠正、遗忘

### 6.1 入口与确认

聊天消息提供“记住这条”，绑定可信用户 entryId。自然语言操作由主模型提出工具调用，不新增每轮意图分类请求。

模型工具只增加 `memory_query`（只读且走 MemoryProvider）和 `memory_change`（remember/correct/forget）；不给模型发布 dreaming 批次、执行 SQL、写 Markdown 的能力。

memory_change 通过 defineTool → PermissionKernel，使用 local_mutation/exclusive_effect/replay:never，继续由统一裁决链检查。工具只接受本轮已提交可信用户事件，并在写事务前绑定 session/generation/operationId/参数 hash/policy/revision；不建立另起的人工发布确认 UI，也不凭模型自报来源放行。

UI 接受/编辑/忘记和工具共用同一 Rust 提交函数；UI 直接动作记录 human actor。真正的成功是 Rust 已提交 revision，不以模型说“记住了”为准。提交结果未知先查 operation_id。歧义忘记只列候选让用户选，不以字符串相似批删。

### 6.2 纠正与变化

correct 指定目标 id/version、新事实、新来源或人工治理决定。correction 表示旧事实本来就错了；change 表示以前有效、现在变化，要关闭旧 valid_to。事务同时处理替代关系、来源、治理记录和 FTS。旧版本在管理历史可查，普通召回不返回；没有明确更正关系的矛盾进入待审，不凭时间较新就覆盖另一 scope。

### 6.3 遗忘闭包

对目标及其替代/派生版本求闭包，同一事务写 suppression、清正文/FTS/候选及作业相关载荷、递增 forget_epoch/revision。治理审计只留必要非正文元数据；刷新全部窗口投影。

首版对被忘事实的全部已知 source event 设置自动提取抑制，防模型换标题/改措辞回灌。已接受且独立的同消息其他事实不随之删除；代价是该旧事件不能再自动挖掘新事实，用户需通过新的可信输入重新表达。对未来新输入的主题级禁止必须由用户明确选择，不能无限扩大一条遗忘。

抑制以稳定 session_id+event_id（并留 entry_id/source_hash）匹配，不以重建时可能变化的 source_id 匹配；source 重新登记、旧水位补扫、备份恢复和候选发布都先检查这组身份。抑制记录不随来源行删除。已接受的独立兄弟事实允许保留，但对来源的定向遗忘和全会话遗忘按各自批准范围裁定，不把“禁止再次提取”和“所有既有事实失效”混成一个条件。

具体执行：忘掉单个事实写目标闭包的 revoke_items，以及其来源事件的 block_extraction；召回/FTS重建排除前者，提取/新候选发布排除后者，已有独立兄弟条目仍可召回。全会话遗忘则明确撤销该范围全部关联条目。reject_proposal只拒绝原提案，不可提升成事实删除。跨备份恢复保留这三种效力，不能只按“存在一行suppression”一刀切。

`/memory clean` 变为全部记忆/候选遗忘预览和确认：记录**所有既有会话**的截止 seq，不只记录已扫描水位，阻止未扫描旧聊天重新填满库；来源范围列不全时不报告全量完成。清空后的新输入可产生候选；显式“重新记住”才解除对应抑制。保留现有 busyPolicy 的明确拒绝。

UI 分别说明：

1. 忘记记忆清应用管理的正文、派生和回灌资格，保留原始聊天。
2. 删除聊天原文是会话管理独立操作；源删除时同步撤销相关记忆或要求处理，不留下假来源链接。
3. 应用管理的导出可清理；用户另存文件/外部备份不自动删除。SQLite 逻辑删除不宣称磁盘取证级擦除。

当前聊天或既有摘要仍可能含被忘内容，不能宣称模型完全不知道。长期遗忘质量在新会话验收，当前会话另验删除范围说明与取消行为。

## 7. Dreaming

### 7.1 阶段和状态

`queued → collecting → reviewing → prepared → publishing → completed`；异常为 paused/cancelled/failed/stale。Light=collecting，REM 在本产品称 Review，Deep=publishing；不意味着三次模型调用。

| 阶段 | 工作 | 可写范围 | 完成证据 |
|---|---|---|---|
| Light | 读取固定水位、筛来源、去重、分批 | source/job/watermark | 各来源有处理结果，不改 active |
| Review | 有界提取主体/事实/时间/aliases，比较相关旧条目，产 add/merge/correct/expire/reject 提案 | candidate/报告/usage | 原话引用、理由、风险和基准版本齐全 |
| 提交前复核 | 重新检查差异、来源、范围、时间、冲突与 payload/hash | candidate payload/hash、作业版本 | 复核绑定本批来源和 baseRevision |
| Publish | 重新核对来源/版本/抑制后自动事务写入 | item/source/change/FTS/revision/job | 整批提交或零提交、返回原因 |

Review 可生成有证据的规范化事实，但不能改来源。Publish 只执行已审 payload，不再让模型改写。每次只发有界事件和相关旧条目，不发送全库/完整工具对话。

### 7.2 调度与资源

- 回合结算后登记待处理范围，失败由增量扫描补齐；主回合 finally 不等待提取 LLM。
- manual 在面板触发；idle 用户开启后，无主回合/计划/工具效果任务、连续空闲120秒、距上次自动 Review ≥60分钟且有新增来源才启动。忙碌判断复用现有运行所有者，不建第二份 AI 锁。
- Rust 应用级租约对应一个主窗口 TS 执行者；设置窗口只请求启动/取消。WebView 挂起/退出/租约失效标 paused/interrupted，不承诺退出后继续。
- 前台新输入暂停后续批并取消在飞后台 completion；保留已提交候选。继续前重查 owner/generation/revision/forget_epoch。
- 每批最多20个用户事件或6000输入 tokens，先到为限；单条过大标 oversized 并让用户选片段，不静默截事实。提取输出1200 tokens，单次30秒，无自动重试。
- 每次自动作业最多3批，每日自动预算12000 tokens；调用前预留估算输入+输出上限，结束按已知 usage 结算，未知保留预留。手动作业显示估计并有批数上限。
- staging 候选最多1000条，满时停止提取并保留作业终态，不丢旧候选/伪推进水位；已接受事实不按旧 maxEntries 自动删除。
- 失败/取消部分产出可查看清理。超过30天的终态诊断可自动清理，staging 候选、抑制、已接受事实不受此清理；遗忘可立即清相关文本。

### 7.3 竞争与恢复

Review 期间可继续聊天。目标被纠正/遗忘/scope改变使 prepared 候选失效，必须重新生成差异；两个窗口同时提交只允许一个事务成功。提交前进程退出 active 不变；提交后退出按 change/job 记录恢复结果。重试只处理未完成输入，不复制候选。

拒绝候选记录 source+proposal+policy 指纹，防同一提案反复出现；拒绝不是永久禁止用户以后重新表达。

## 8. UI、配置与 IPC

### 8.1 记忆管理

现有 SettingsPanel 新增记忆 Tab，不新建 Tauri 窗口。AITab 保留 V1RTUAL/会话压缩信息，移除旧 memMax/注册表统计。

接线同时修改 SettingsPanel 的 tabs、activeTab union、MemoryTab ref、template 挂载和 doSave 配置映射；MemoryTab.defineExpose 仅暴露待保存策略，数据操作独立提交。删除 AITab.memMax、对应 expose、SettingsPanel 的 ai.memory.maxEntries 映射与 config getter，并全仓检查零生产消费者；V1RTUAL 的既有编辑/保存链仍保留。

MemoryTab 包含已记住（类型/范围、置顶、来源、纠正历史、编辑/忘记）、整理任务（范围/阶段/费用、取消、继续、失败报告）、策略与导出；不提供候选选择或发布按钮。

数据操作单独提交，不能混入“保存 CONFIG”；设置取消不撤销已提交记忆，界面明确说明。事件只广播 revision 让其他窗口重读，不广播事实正文。错误保留编辑输入并可重试，空库、读取失败、stale 作业有不同状态。

角色过程文案走 StageMap/CommandReplies/FallbackReplies → stages-prompt → validateStages/缓存失效 → 消费者；技术错误/差异/删除范围保持中性。新增 key 必须让旧缓存过期。memoryCleared 只在提交成功后使用，不为每次后台回退弹角色台词。

### 8.2 配置提案

```yaml
ai:
  memory:
    enabled: true
    coreTokenBudget: 320
    recallTokenBudget: 800
    rerank: adaptive       # off | adaptive
    dreaming:
      mode: manual         # manual | idle
      idleSeconds: 120
      minIntervalMinutes: 60
      maxDailyTokens: 12000
    maxSessions: 20         # 现有会话标签管理语义不变
```

删除 maxEntries/超额自动删除语义。enabled=false 停生产召回、收集、自动整理，不删库；管理/导出/遗忘仍可用。预算允许0；idleSeconds范围30–3600、minIntervalMinutes范围1–1440、maxDailyTokens范围0–100000、coreTokenBudget范围0–2000、recallTokenBudget范围0–4000，均为整数；0日预算禁止自动模型整理。由同一校验函数供设置和运行读取使用，非法值明确报告，不能 `|| default` 吞掉0。

召回/重排截止由既有 memoryConfig 类型化配置读取（生产模板4000/2500ms）；候选上限、批大小、保留期放领域常量，不重复建立默认值；路径/schema 不是设置。同步链为 CONFIG.yaml → CONFIG-DEV.yaml.example → Config/getter → MemoryTab/ref/defineExpose → SettingsPanel保存 → flush/reload → 文档。缺新字段由 config 模块取生产模板默认，不映射旧 maxEntries、不复制业务默认值。

策略在下一 run 冻结；关闭/降低后台预算即时阻止新批并取消自动作业。真实 CONFIG-DEV.yaml/运行时 CONFIG 仍需单独授权；交付说明未同步项，模板和代码不能漏改。

### 8.3 命令分组

以下为目标命名，W0 一次冻结 Rust serde/TS 类型，不接受任意 SQL/数据库路径。

| 组 | 命令 | 关键校验 |
|---|---|---|
| 初始化/管理 | memory_init/status/list/detail | revision、分页、范围；不可用不假装空 |
| 来源/召回 | memory_register_sources/query/get_items | register仅宿主；scope先过滤；取全文重查revision |
| 显式写 | memory_apply_change | operationId、版本、可信用户来源/人工决定，单事务 |
| 作业 | memory_job_start/checkpoint/cancel/resume/list | 租约、phase、固定输入、幂等/取消 |
| 自动提交 | memory_candidates_add/memory_dreaming_commit | prepared 候选的 payload hash、来源与 baseRevision，整批复核后单事务提交 |
| 导出/维护 | memory_export/backup/rebuild_index/restore_preview/restore_apply | 显式用户操作，完整性、治理抑制和恢复范围 |

Rust 返回 AppResult<T>，新增 MemoryUnavailable/Conflict/Stale/SourceRejected/Cancelled 等 code；SQL 细节进脱敏日志，不日志化完整用户事实。同步 commands/mod.rs、lib.rs 注册、invoke、capabilities（适用时）、错误映射与测试宿主。

DB/WAL/SHM/内部作业材料为受保护路径，通用模型文件写入不能绕过治理 API。Rust 规则覆盖 rename两端、符号链接和平台大小写；V1RTUAL 保持人工指令入口。Bash 保留硬基线与可判定路径拦截，但同用户任意脚本不是通用沙箱，不宣称 OS 级不可绕过隔离；dreaming 用无工具 completion，不开放 Bash/文件写工具。

## 9. 备份、旧数据与失败

首次只建空库，不导入/删除旧用户文件，代码替换不等于授权清理磁盘。提供 Markdown事实视图导出和包含治理记录的 SQLite 一致性备份；WAL 下用 SQLite备份接口/一致性机制，不直接复制写入中的主文件。

恢复是明确维护操作：暂停记忆写入→预览版本/数量/来源→校验完整性→合并保留当前suppression→重新校验候选→提交恢复结果。旧备份不能覆盖当前遗忘；治理记录已丢失时停自动提取并说明无法证明的遗忘范围。恢复不自动切回旧Markdown reader。

退出不建守护进程；SQLite已提交保留、未提交回滚；下次作业显示interrupted，不假定托盘退出会await前端LLM。库损坏/磁盘满/权限或schema错误显示不可用，聊天可继续，但禁止静默重建空库。

### 12.3 真实模型对照

Live Test已接独立capability数据集，临时数据根、真实Provider、sendMessage入口。五组使用同一冻结记忆库和相同问题：无记忆、纯本地、每次重排、adaptive、gold evidence；always只用于评测，不增加生产策略分支。

已起草80个中文合成标注用例（AI草案，双人gold审计未完成不得判质量通过）：称呼/稳定偏好、经历/时效、纠正、遗忘各20，交叉含中文短词/同义表达/无关查询/跨Card/第三方/假设/歧义。标注允许source/item、禁止旧事实、有效区间；问题不进入提取材料。提取质量用同一标注对话集单独测误记/漏记，避免归因混淆。

一次调用使用隔离临时数据根；每个cell从同一fixture重新构造独立数据库实例和会话，由debug+E2E守卫的Rust命令关闭并重建唯一Store连接，记录generation与规范化fixture指纹，配对策略指纹必须一致；关闭自动收集/dreaming；全部质量cell统一撤下模型工具，防止搜索/文件读取绕过无记忆对照，fixture治理仍用真实Rust IPC；清空旧投影与Provider会话。纠正/遗忘题只允许该题规定的显式操作，每题后重置。五组交错/随机顺序并记录seed，不能复用上一组的库或暖会话；提取集、记忆库、问题与答案标注分别保存。报告记录fixture指纹、datasetVersion与provider/model/memoryConfig明文，远端缓存作为测量变量单列。

每组至少3次trial，额外token与首文本延迟按相同case/trial相对本地策略配对；收益按题目聚合后bootstrap95%区间，adaptive默认开启还须区间下界为正。报告每scope候选Recall@50与合并池Recall、选择Precision/Recall、五项回答正确率、误记、旧事实泄漏、拒答、fallback率、额外token、缓存、首答P50/P95。gold须双人独立审计；回答/提取须经校准的独立judge盲审，可用人工或不同于被测模型的AI，审阅哈希绑定全部采集产物，不以被测模型自评作为通过依据。命令、staging状态与证据目录见[测试 README](../../../test/README.md#trace记忆质量与性能门禁)。

初始门槛，评审后冻结，不能失败后现场放宽：

- 来源越权、跨scope泄漏、未经复核提交、遗忘复活：确定性零失败；真实样例有失败单独分析，不用均值抵消。
- 明确标注的称呼/偏好/经历时效/纠正/遗忘各≥90%；自动提取候选precision≥95%、recall≥80%；照实报告样本和统计限制。
- adaptive相对本地回答正确率不降低，须有可重复的选择/回答收益；无收益或几乎总超时，则交付默认off并记录依据，保留可关闭的已验证重排能力，不能宣称重排有效。
- recall_total_latency 从调用端口至返回投影，受当前memoryConfig.recallTimeoutMs总截止控制，报告记录实际配置并单列调度误差。rerank_latency与成功/fallback比例分别报告，不能靠全部fallback证明收益。
- first_answer_delta 用上述独立配对trial计算，另报P50/P95及网络/Provider耗时；它包含后续请求长度和缓存变化，不能直接等同于召回截止。adaptive 的首答P95若明显退化且没有质量收益，不采用默认开启。

### 12.4 资源

性能脚本已接入release原生存储与debug WebView IPC两种测量域；debug不充当release IPC基线。以当前release存储构建为基线，在1k/10k已接受记忆测冷/热检索、短词扫描、DB打开/FTS重建、发布、前后台并发。端到端召回包含IPC与取全文，不只给SQL时间。

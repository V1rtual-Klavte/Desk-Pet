**已决策、不再实施**（论证见 [Pi 方案基线](../../history/implementation/Pi运行时与工具协议建设方案-2026-09-20基线.md) §4.3 与[收尾清单基线](../../history/analysis/收尾清单-2026-09-20基线.md)）：

- 写类工具（`write` / `edit`）**保持** `policy.permission: passthrough`，不改为 `ask`——工具侧 `ask` 会压过 base `allow`，等于用静态声明静默改掉 `safety.mode = just_do_it` 的语义；要收紧应改安全模式或 checker。
- L3 依赖闭包门禁**不加**：闭包差 89/92 是 barrel 噪声，收益不抵 hash 维护成本。

- **item 1 类（handler 不结算导致额度泄漏）不属上一条结论**——它曾是可阻塞的真实入口（`file_read` 读 FIFO 会让 open 一直等对端，额度永不归还），已由 TOOL-06a 从源头消除：文件命令只接受常规文件，FIFO/设备/套接字在调用前被拒。
- `before_run` / `before_run_end` hook **不补**：回合冻结已由宿主 preflight 等价完成，基线标注 `before_run_end` 可选（FIX-11/12）。
- `toProviderMessages` / `entryProjectors` / `resources.skills` **保持上游默认**：默认 `convertToLlm` 把 `custom` 投影为 user 且 `deskpetEventId` 不泄漏，不注册 projector 是有意边界（FIX-13）。
- 七阶段投递证据链**保持 4 阶段**：`request_started` 与 `settled` 分别由 `request_prepared`、`responded` 覆盖（FIX-14）。
- Harness 的 `totals` **不消费**：逐请求 usage 已满足需求（FIX-15）。
- 工具恢复的 memo 持久位**不实现**：`replay: "never"` 已保证不重放（FIX-16）。

## 4. 验证缺口

以下均已实现，缺的是验证手段；完成前不得宣称已发布就绪：

- **Windows 运行时行为**：本机 macOS 只能证明 cfg 隔离与类型正确，不证明运行时行为；P8、托盘与窗口生命周期均无 Windows 实机记录。
- **跨进程重启的人工冒烟**：`app_restart` 的进程级重启链路未在真实应用里点过。
- **UI 未经人工查看**：ChatPanel 排队面板与投递意图选择、聊天区「停止」按钮与「正在停止/已停止」文案、暂停项操作条（继续处理 / 全部丢弃）、中断运行的继续/丢弃决策条、设置页新增控件（对话投递 / 只读并行 / 工具策略声明区）、`DebugBar` 的 Σ 用量面板、`effectMode` 门控后的光标跟随；Live Test 宿主不渲染 UI，上述入口目前只有协议级场景证据。设置页「修改 → 保存 → 文件回读 → 关闭重开」的往返未执行。前舞台批次新增的 UI 入口（PlanConfirm 面板与逐步门、计划待处置条（继续/丢弃）、ChatPanel 工具过程文案、设置页复杂度判定控件）同样只有协议级场景证据：Live Test 宿主不渲染 UI。
- **main 窗口关闭路径**：改为隐藏到托盘后，macOS ⌘W / 红点与 Windows Alt+F4 的实际行为未实机复核（Live Test 宿主不建 main 窗口）。
- **音效留痕未运行验证**：三个音效的节点构建失败走 `reportEffectFailure` / `reportSuspendedOnce` 统一留痕，只有类型与静态核对，未实际触发过一次；需人工在设置页点一次音效试听确认出声与无异常留痕。
- **`persistFailed` 路径**：触发条件是 lane 写入真失败，Live Test 无法构造，只有类型与静态核对；「界面显示过的正文可能没进会话文件」这一后果未经过运行验证。
- **恢复时 MCP 借用失败的显式提示（FIX-61）**：需要「恢复运行引用的 MCP 服务器本次借不到」这一前提，Live Test 宿主无法构造，只有静态核对与类型检查。
- **长期记忆质量评测**：P6 未实施，不适用。

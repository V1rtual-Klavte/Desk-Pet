### 3.2 尚未完成的验收口径

- **权威质量对照（主口径）**：LongMemEval oracle（常规回归层，官方判分移植）、MemoryBank cn（中文对照）、LoCoMo（对外可比，词面 F1、免 judge）按 [memory-bench README](../../../test/memory-bench/README.md) §8 的分层节奏在本机运行；报告与 hypotheses 是质量证据。门禁保持现状：CI／`test:release` 不跑评测集（最多冒烟级自检）；允许子集与偏差的口径、许可与官方判分差异按该 README 执行，不用自建 80 题替代权威对照结论。
- **兜底冒烟与治理语义回归（自建 80 题）**：80 个中文标注用例（称呼／稳定偏好、经历／时效、纠正、遗忘各 20）；无记忆／纯本地／always／adaptive／gold 五策略各至少 3 trial，always 仅供评测。每 cell 独立 SQLite 与 store generation、相同规范化 fixture 指纹、关闭模型工具及自动收集／dreaming、配对随机顺序并记录 seed；禁止复用上一组库或暖会话。
- **判定门槛**：来源越权、跨 scope、未经复核提交、遗忘复活确定性零失败；五项回答正确率分别 ≥90%，自动提取 precision ≥95%、recall ≥80%。gold 需两人独立完整审计；回答／提取由经人工校准且不同于被测模型的 judge 盲审（或人工盲审），评分绑定 dataset 与完整采集产物 hash；不得失败后临时放宽。
- **重排收益与成本**：每 scope 候选 Recall@50、合并池 Recall、选择 Precision/Recall、旧事实泄漏、拒答、fallback、额外 token 与缓存分别报告。按题目聚合 3 trial 后 bootstrap 95% 区间；adaptive 默认开启须回答质量不退化、可重复收益且区间下界为正；无收益或几乎总超时维持默认 off。召回总延迟按实际配置截止，重排延迟／fallback、首答配对 P50/P95 与 Provider／网络耗时分列；usage 缺失为未知，不算零成本。
- **资源与治理整链**：1k／10k 冷热、短词、打开／重建／提交／备份／争用、真实 IPC 与正文取回；10k 热路径 P95≤500ms。release 存储、debug IPC 与 release UI/IPC 分域；产品 RSS/CPU、二进制增量、DB/WAL/SHM/候选/报告/备份总磁盘及 LLM 账分别保留基线。还需 >5 MiB 真实 JSONL 的列表／打开／来源收集与失败不推进水位、遗忘后重建来源／索引／旧批次／旧备份不复活、任务抢占／取消／重启／租约竞争与持久预算故障矩阵。
- **UI 与全平台**：使用 §3 隔离设施记录真实 settings 往返与跨窗口 revision；Windows 原生 check/Rust/L2/L3 须对应当前提交且先转绿（修复已入工作树、待 CI 复跑）。修复后重做受影响快层与完整严格 L4，更新 Contract 真实覆盖与哈希；发布时执行现有 `test:release` 门禁。
